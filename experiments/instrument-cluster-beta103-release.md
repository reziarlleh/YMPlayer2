# YMPlayer 2.5.5beta-build103 — проверка приборной панели

Это отдельная экспериментальная бета для проверки отображения музыки на приборной панели TENET T8 (Android 10). Проверьте её **на том же ГУ, где возникла проблема**, и сравните с плеером, который на нём уже показывает данные. На реальном TENET результат беты пока не подтверждён.

**Media Monitor устанавливать не нужно.** Если обычный экран разрешений ГУ пишет, что выдавать нечего, не ищите там разрешение для этой проверки: данные собираются с компьютера через ADB.

## 1. Что скачать

На компьютер с Windows скачайте:

1. [YMPlayer-2.5.5beta-build103.apk](https://github.com/reziarlleh/YMPlayer2/releases/download/v2.5.5beta-build103/YMPlayer-2.5.5beta-build103.apk) — экспериментальный плеер.
2. [ClusterMedia-ADB.zip](https://github.com/reziarlleh/YMPlayer2/releases/download/v2.5.5beta-build103/ClusterMedia-ADB.zip) — PowerShell-скрипт для сбора диагностики.
3. [Android SDK Platform Tools для Windows](https://developer.android.com/tools/releases/platform-tools) — официальный пакет Google с `adb.exe`, если ADB ещё нет.

Распакуйте Platform Tools. Из `ClusterMedia-ADB.zip` извлеките `Collect-ClusterMedia.ps1` и положите его в папку `platform-tools` **рядом с `adb.exe`**. Скопируйте туда же скачанный APK, если будете устанавливать его командой ниже. Штатные файлы и DLL из Platform Tools оставьте в этой папке.

## 2. Подключить ГУ и установить бету

Подключите **то самое ГУ** к компьютеру с включённой отладкой и разрешите запрос на отладку на экране ГУ. Если ADB уже настроен для этого ГУ, используйте существующее подключение. Откройте папку `platform-tools` в Проводнике, введите `powershell` в адресной строке и нажмите Enter. В открывшемся окне выполните:

```powershell
.\adb.exe devices
```

Рядом с серийным номером ГУ должно быть `device`. При `unauthorized` подтвердите запрос на ГУ и повторите команду; при `offline` восстановите ADB-подключение. Продолжайте, когда видите своё ГУ в состоянии `device`.

Если бета ещё не установлена, из этой же папки выполните:

```powershell
.\adb.exe install -r .\YMPlayer-2.5.5beta-build103.apk
```

Дождитесь `Success`. APK подписан тем же сертификатом, что и YMPlayer 2.x, и обновляет стабильную сборку 2.5.4-build102 без удаления данных. **Не удаляйте установленный плеер перед обновлением.** При нескольких подключённых Android-устройствах оставьте подключённым только нужное ГУ либо укажите его серийный номер через `-s` для команды установки и `-Serial` для скрипта ниже.

## 3. Снять показания во время воспроизведения

В том же окне PowerShell выполните:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Collect-ClusterMedia.ps1
```

Если `adb.exe` находится в другом месте, запустите скрипт из папки, куда распакован `ClusterMedia-ADB.zip`, с параметром `-Adb`:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Collect-ClusterMedia.ps1 -Adb "C:\путь\к\platform-tools\adb.exe"
```

Если ADB видит несколько устройств, добавьте в конец команды `-Serial СЕРИЙНЫЙ_НОМЕР` из вывода `adb devices`. Параметр `-ExecutionPolicy Bypass` действует только для этого запуска PowerShell.

Скрипт проверит ГУ и установленные YMPlayer, FMPLAY и Яндекс Музыку. Для каждого найденного плеера он предложит четыре шага:

1. Вручную включите трек с известными названием, исполнителем и обложкой; дождитесь обновления приборки и нажмите Enter.
2. Вручную смените трек или станцию; дождитесь обновления и нажмите Enter.
3. Вручную поставьте паузу и нажмите Enter.
4. Вручную продолжите воспроизведение и нажмите Enter.

После каждого снимка **коротко напишите, что видно на приборке**: название, исполнитель, обложка, пустая карточка или отсутствие карточки. Если шаг невозможен, введите `S`; установленный плеер можно пропустить целиком. Перед следующим плеером вручную остановите предыдущий. Плеер, которого нет на ГУ, скрипт пропустит сам. Особенно полезно сравнение YMPlayer с FMPLAY, который уже работает на этой приборке.

## 4. Что отправить автору

После завершения скрипт напечатает путь к файлу вида `platform-tools\reports\ClusterMedia-...zip`. **Отправьте автору именно этот ZIP.** Если все снимки показывают ноль сессий и уведомлений, всё равно отправьте ZIP и сообщите об этом. Если скрипт остановился до создания ZIP, пришлите точный текст ошибки и вывод `.\adb.exe devices`.

В архиве будут модель и версия Android, версии найденных плееров, выбранные блоки их медиасессий и уведомлений, а также ваши наблюдения приборки. Названия прослушанных треков и данные ГУ могут быть видны — перед отправкой архив можно открыть и проверить. Полный `logcat`, общие `dumpsys` и содержимое уведомлений других приложений туда не включаются. Скрипт не устанавливает приложения, не выдаёт разрешений, не меняет настройки ГУ и не требует root; для работы ему нужно уже разрешённое ADB-подключение.

## Что изменено в beta103

У медиауведомления убран `media3_group_key`, а в `subText` передаётся альбом или радиостанция. Legacy MediaSession сообщает `flags=3` вместо `7`. На эмуляторах Android API28 и Android TV API29 проверены системное уведомление, метаданные и обложка, кнопки и Pause/Play, фоновое воспроизведение и MediaBrowser; release lint прошёл без ошибок. Это проверка Android-стороны, а не подтверждение работы приборки TENET.

Бета выпущена как **ручной prerelease**. GitHub Latest и стабильные каналы обновления остаются на 2.5.4-build102. У beta103 номер сборки выше, поэтому установить stable102 поверх неё обычным обновлением нельзя; возврат без удаления данных потребует будущую стабильную сборку с более высоким номером.

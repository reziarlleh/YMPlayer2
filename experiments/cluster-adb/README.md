# Сбор данных приборной панели через ADB

Этот способ нужен, если Media Monitor на ГУ не получает доступ к уведомлениям.
Скрипт выполняется **на компьютере Windows** и читает стандартные сведения
Android о медиасессиях и уведомлениях YMPlayer, FMPLAY и официальной Яндекс
Музыки. Устанавливать или запускать Media Monitor на ГУ не нужно.

## Перед началом

1. Скачайте архив `ClusterMedia-ADB.zip` из [экспериментального выпуска
   YMPlayer](https://github.com/reziarlleh/YMPlayer2/releases/tag/v2.5.5beta-build103)
   и распакуйте в отдельную папку.
2. Подключите **то самое ГУ** к компьютеру с разрешённым ADB. Нужен `adb.exe`
   из [официальных Android Platform Tools](https://developer.android.com/tools/releases/platform-tools).
   Можно положить скрипт в распакованную папку `platform-tools` рядом с
   `adb.exe` и его штатными DLL либо передать путь к существующему `adb.exe`
   через `-Adb`. Проверьте `.\adb.exe devices` в этой папке: статус ГУ должен
   быть `device`, не `unauthorized` и не `offline`. При `unauthorized`
   подтвердите запрос отладки на самом ГУ.
3. На ГУ установите проверяемую beta103 YMPlayer и те плееры, с которыми
   хотите сравнить её показ на приборке. Не удаляйте данные приложений.

## Запуск

Откройте PowerShell **в папке со скриптом** и выполните:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Collect-ClusterMedia.ps1
```

Если `adb.exe` не найден автоматически:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Collect-ClusterMedia.ps1 -Adb "C:\путь\к\platform-tools\adb.exe"
```

При нескольких подключённых устройствах добавьте `-Serial СЕРИЙНЫЙ_НОМЕР`
из вывода `adb devices`. Ключ `-ExecutionPolicy Bypass` действует только для
этого запуска PowerShell; системные настройки скрипт не меняет.

Скрипт по очереди попросит вручную запустить YMPlayer, FMPLAY и Яндекс Музыку.
Для каждого установленного плеера он предложит снять четыре состояния:
воспроизведение, смена трека/станции, пауза, продолжение. После каждого шага
впишите коротко, что в этот момент показывает приборка, либо оставьте ответ
пустым. `S` пропускает недоступный шаг или целый плеер. Перед следующим
плеером остановите предыдущий **вручную**. Скрипт сам не нажимает Play/Pause.

В конце появится путь к ZIP в папке `reports`. **Отправьте этот ZIP** автору
YMPlayer. В нём `summary.json` и папки снимков с `media-sessions.txt`,
`media-notifications.txt`, `capture.json`. Перед отправкой можно открыть их
обычным текстовым редактором: названия прослушанных треков и сведения ГУ
сохраняются. Содержимое чужих уведомлений, полный `dumpsys` и `logcat` в ZIP
не включаются.

Скрипт ничего не устанавливает, не выдаёт разрешений, не меняет настройки ГУ
и не требует root. Он читает данные через уже разрешённое ADB-подключение.
Если прошивка запрещает `dumpsys`, ошибка останется в соответствующем снимке;
отправьте получившийся ZIP, чтобы было видно ограничение. Снимок Android не
раскрывает внутреннюю связь с MCU/CAN, но позволит сравнить публикацию трека
и уведомления работающего и неработающего плееров на одном ГУ.

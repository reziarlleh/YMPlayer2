## Подтверждённые механизмы восстановления Play

На собственномAPI28 прежняя логика сохранения воспроизводимо провалила3 из7
целевых native тестов с настоящим ExoPlayer:

1. `command()` записывал `playing=false` до выполнения любой команды. Play,
   ожидающий чтения метаданных, оставался сохранённой паузой при завершении процесса.
2. `userCommanded` переживал отсоединение движка. Повторное metadata-only
   восстановление сервиса принимало начальное тихое состояние нового движка
   за намерение паузы и затирало ранее сохранённый Play.
3. `checkpoint()` приравнивал ошибку потока к паузе, хотя пользователь запрашивал
   Play. Ошибка источника не доказывает внешнюю/ручную команду Pause.

Исправление передаёт явный Play/Pause/Stop до очереди команд, остальные команды
сохраняют намерение. Промежуточная загрузка не сохраняется как завершённая команда;
при ошибке сохраняется последнее намерение, отдельная ручная Pause/Stop его
сбрасывает. Повторное тихое подключение сервиса не является пользовательским Play.
Точные последовательности выключения физическихГУ этим не воспроизведены.

Дополнительно native тест подтвердил: при переходе из радио в музыку остановка
уходящего радио перезаписывала новый сохранённый источник какRADIO. Музыка играла,
но следующий запуск восстанавливал остановленное радио. Запись нового владельца
теперь выполняется после остановки старого, до постановки медленной команды.
Этот тест сначала упал с `expected MUSIC, actual RADIO`, после правки прошёл наTV.

Это согласуется с разделением `onPlayWhenReadyChanged`/причины изменения и
`onPlayerError`/перехода вIDLE в документации
[Android Media3](https://developer.android.com/media/media3/exoplayer/listening-to-player-events).
Для фокуса сохранён адресный перенос только когда исчезает доступность уже
сфокусированной кнопки; обновление метаданных не запрашивает новый фокус.
[Рекомендации Compose](https://developer.android.com/develop/ui/compose/touch-input/focus/request-focus).

## Очередь и временный кэш волны

Логическое окно ограничено10 записями: на старте current+9, после продвижения
previous+current+8. Предыдущий и его аудиофайл сохраняются по уточнению владельца;
удаляется более старая история. Сначала готовятся текущий и следующий, затем
остальные аудиофайлы. Готовым считается полный проверенный файл с атомарным
переименованием, а не ID/URL. Новые лайки/офлайн-коллекция этим не создаются.
Обычные списки, включая более10 треков, не входят в эту схему полной загрузки.

До выпуска тесты нашли оставшийся старый срез восстановления из трёх записей:
остальные подготовленные кандидаты выпадали из очереди, оставаясь в фильтре
уже предложенных. Сохраняется/восстанавливается всё окно до10; новая native
проверка сопоставляет IDs всех десяти до/после restart и повторно проверяет
полные аудиофайлы без запроса новых рекомендаций вместо потерянных.

Профиль/аккаунт/источник и поколение защищают от поздних ответов. Неполные файлы
удаляются, ошибки записи различаются с сетевыми. D-006 — ограниченный исходный
отзыв без версии/диагностики; совпадение с персональным случаем не объявляется
доказанным только по увеличению очереди.

## Интерфейс и качество

- В широкой компоновке управление слева, обложка/метаданные справа.
- Три пиктограммы: Моя волна/Офлайн/пользовательский список, пока локальное
  избранное. Третий слот имеет отдельный UI-контракт, новая настройка его выбора
  ещё не реализована. Название текущего источника/списка показывается отдельно.
- Настройки волны доступны только настоящей Моей волне.
- Auto иMaximum сейчас выбирают самый высокий доступный битрейт; адаптации
  к скорости сети нет. Уточнены8 переводов и обе инструкции, ключи настроек сохранены.
- Новая необязательная рольOFFLINE наследует встроенную иконку в прежних скинах.

## Проверки и остаток

Целевые тесты, финальные результаты и артефакты ещё проверяются. Исходные red
результаты хранятся локально в `.local-build/maintenance264/resume-before.txt`.
Первый UI прогон выявил неполную фикстуру: страница возвращала один трек, и
Next был правильно недоступен. В фикстуре UI проверок загружается вторая страница;
это не дефект продукта. Первый незавершённый compile тестов из-за параллельной
правки debug-фикстуры исправлен повторной сборкой замороженного snapshot.
Сборки продукта/Build для этих внутренних проверок не выделялись.

Клипы, эксперимент приборки,1.x, Kivi и иные физические устройства не менялись.
Публикация, feeds и шапка4PDA не выполняются автоматически.

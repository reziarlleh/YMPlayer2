# Android 8/6 — повторная оценка 13 ноября2026

База — текущие исходники2.6.6 с локальным подписанным133, stable132.
Это проверка возможности по вопросу владельца, а не выполненная адаптация:
minSdk во всех11 Android-модулях остаётся28, target36/compile37 не менялись.
Новый APK или номер версии для снижения SDK не выделялся.
[Предыдущая оценка9 октября](API_23_26_FEASIBILITY.md) — историческая.

## Вывод

Принципиального препятствия для **Android8.0/API26** или **Android6.0/API23**
по проверенным исходникам и зависимостям не найдено. Для8 нужны локальные
совместимые ветки; для6 их больше, включая запуск приложения и подпись APK.
Переписывать интерфейс или заменять Media3/Compose не требуется по выявленным
контрактам. Готовая совместимость не доказана:23/26/27 не запускались.

Из текущего manifest-merger report подписанной133 перечитаны74 манифеста:
10 внутренних библиотек с объявленным min28 и **64 сторонних**. Максимум
у сторонних —23, выше23 нет, отсутствующих исходных манифестов нет.
Не смешивать наши min28 с ограничением сторонних зависимостей.
[Результат с координатами всех библиотек](qa/api23-api26-feasibility-2026-11-13/dependencies.json).

Google [подтверждает API23 для основных аудио/видеосценариев Media3](https://developer.android.com/media/media3/exoplayer/supported-devices).
При этом [текущий общий default AndroidX уже24](https://developer.android.com/jetpack/androidx/versions#minimum_sdk_version):
это не поднимает минимум закреплённых в нашем проекте версий автоматически,
но будущие обновления зависимостей для поддержки6 придётся проверять по minSDK.

## Что потребуется адаптировать

| Область | Android8/API26–27 | Дополнительно Android6/API23 |
| --- | --- | --- |
| Проверка обновлений и подписи APK | UpdateClient и UpdateCoordinator безусловно используют longVersionCode/signingInfo/GET_SIGNING_CERTIFICATES из28. Нужны прежние versionCode/signatures с прежней проверкой ключа | canRequestPackageInstalls/экран разрешения источника из26 заменить соответствующим системным сценарием; contentLengthLong из24 разобрать совместимо |
| Обложки постоянного кэша | LikedFileStore проверяет ImageDecoder из28; нужен декодер для старой ОС с ограничением памяти и проверкой повреждения | Тот же путь, проверка памяти на старых устройствах |
| Определение интернета | Используемый registerDefaultNetworkCallback с одним аргументом доступен с24 | AndroidInternetConnection вызывает его в init: нужен старый callback с сохранением проверки активного маршрута, иначе возможен отказ уже при старте |
| Локализация | LocaleList/configuration.locales доступны с24 | Совместимая работа с одиночной Locale в AppLanguages/UiStrings, настройках волны и диагностике |
| Кэш, его перенос, USB и экспорт | java.nio.file доступен с26 | StorageNode, CacheDirectories, MountedFolderPicker: совместимые файловые операции/desugaring, сохранение атомарной публикации и проверки границ каталога; не терять аудио/checksum при сбое |
| Службы и уведомления | Каналы и startForegroundService доступны с26 | OfflineSyncService/FileTransferService/MainActivity/PlayerApplication: прежние варианты запуска/уведомлений/stopForeground; воспроизведение и экспорт должны продолжать работать в фоне |
| Java API | java.time.Instant доступен с26 | Включить подходящий library desugaring либо совместимую реализацию времени/файлов. Сейчас library desugaring не настроен |
| Подпись продукта | Текущая v2 поддерживается начиная с Android7 | Подписать также v1 тем же ключом; нынешний APK133 имеет v1=false/v2=true и на6 в таком виде не установится |

Основные вызовы сверены в актуальных файлах, а не перенесены из старого отчёта.
Дополнительные по сравнению с9 октября области — сетевой observer,
FileTransferService, StorageNode/CacheDirectories/MountedFolderPicker и v1.
Хранилище аккаунтов использует AndroidKeyStore/KeyGenParameterSpec изAPI23;
переход на6 не требует замены его на открытый текст или другой продуктовый ключ.
SideBar остаётся только для K4811: понижение SDK общего плеера не расширяет
его аппаратную поддержку и не запускает overlay на всех старых устройствах.

Основания: [ImageDecoder/API28](https://developer.android.com/reference/android/graphics/ImageDecoder),
[сетевая подписка/API24](https://developer.android.com/reference/android/net/ConnectivityManager#registerDefaultNetworkCallback(android.net.ConnectivityManager.NetworkCallback)),
[доступные Java API/desugaring](https://developer.android.com/studio/write/java8-support#library-desugaring),
[v1 для Android6 и v2 начиная с7](https://source.android.com/docs/security/features/apksigning/v2).

## Границы и последовательность

Таблица — адресная оценка, не полный отчёт lint с пониженным минимумом.
Сборка с min23/26 и AVD этих версий не выполнялись. Риски проверки: запуск,
язык, реальный OAuth/сеть, system MediaSession/BT, локальные файлы/SAF/USB,
целостность кэша и его перенос, экспорт, автообновление, аппаратные декодеры
и ресурсы конкретного старого устройства. Возраст ОС сам по себе не объявляется
доказанным отказом авторизации или сервиса Яндекса.

При реализации разумно целиться в23 одним приложением —8 также попадает
в диапазон. Сначала проверить зависимости/manifest и полный NewApi lint на23,
адаптировать обращения без удаления функций/проверок подписи, затем проверить
23/26/27 и прежние28/35/36, подпись v1+v2 и обновление поверх прежнего APK.
BaseVersion и критерии выпуска нужно зафиксировать перед этим циклом по
VERSIONING; следующая версия не назначается одной этой оценкой.

README и инструкции продолжают правильно указывать Android9+ для доступного
продукта. [Текущий статус](PROJECT_STATUS.md) · [План](ROADMAP.md).

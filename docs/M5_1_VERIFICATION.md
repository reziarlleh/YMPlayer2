# M5.1: исправление переноса аудиопротокола 1.x

2026-09-12. Владелец подтвердил поиск и «Мне нравится» в build9, но запуск
«Титаника» завершался сообщением «Не удалось прочитать ответ Яндекса».

## Причина и сверка с 1.x

В `YandexMusicClient` 1.x (commit `7d118b4`) `buildDirectLink` читает `ts` как
строку и без преобразования включает её в URL. В build9 была добавлена проверка
`[0-9]+`, которой в рабочем алгоритме нет. Настоящий XML Яндекса содержит,
например, `ts=1a093e33038`. Build9 отклоняет его до первого запроса аудио.
Это ошибка переноса; прежняя фикстура с `ts=123` её скрывала.

Проверено без пользовательского токена: поиск «Титаника», `download-info` и XML
вернули HTTP 200. Формула 1.x для того же XML дала HTTP 206 и 1024 байта публичного
аудиопревью. До исправления новый Android-тест воспроизвёл `MusicException: RESPONSE`
в `buildDirectLink`. [Ответ и воспроизведение ошибки](qa/m5-1).

| Звено 1.x | Реализация 2.x и результат сверки |
| --- | --- |
| `getDirectUrl` | `YandexMusicApi.stream`: тот же `/tracks/{key}/download-info`, OAuth только API |
| `chooseDownloadInfo` + `AudioQuality.AUTO` | Восстановлен выбор полного варианта по bitrate с бонусом 2 для MP3; дополнительный фильтр «только MP3» удалён |
| `request(..., false)` для XML | `HttpsMusicTransport`: без OAuth, заголовки 1.x, connect/read 15/20 секунд |
| `buildDirectLink`, `tag`, `md5` | Строковые `host`, `path`, `ts`, `s`; UTF-8, прежняя соль MD5, удаление одного начального `/`; `ts` сохраняет буквы, регистр и ведущие нули |
| Передача URL аудиодвижку | `ResolvingDataSource` получает ссылку перед чтением настоящего Media3 |

Проверки HTTPS, допустимого сервера, DTD/entities, размера ответа и отсутствия
OAuth на серверах аудио сохранены. `ts` проверяется как один безопасный сегмент
URL, без требования десятичного числа. Разделение provider/core/playback сохраняется.

## Проверка исправления

Добавлены регрессии для реального формата `ts`, ведущих нулей/регистра, выбора
варианта AUTO 1.x и отклонения символов, меняющих структуру URL.

`OnlineNetworkTest` запускается явно с `-e yandexLiveProbe true`: получает
настоящий публичный XML Яндекса, передаёт его production-построителю ссылки и
через production `onlineDataSourceFactory` воспроизводит аудиопревью в Media3.
Провайдер не подставляет WAV или фикстурную ссылку; пользовательский токен
не читается. Без флага сетевой тест пропускается, обычные тесты остаются автономными.

Команда для подготовленного эмулятора:

```text
adb -s emulator-5580 shell am instrument -w -r -e class dev.petrov.ymplayer2.OnlineAdapterTest,dev.petrov.ymplayer2.OnlinePlaybackTest,dev.petrov.ymplayer2.OnlineNetworkTest -e yandexLiveProbe true dev.petrov.ymplayer2.dev.test/androidx.test.runner.AndroidJUnitRunner
```

Итог: **17/17** проверок на Android 35 и **17/17** на Android TV 29.
Это 11 сценариев адаптера, 5 интеграций очереди и 1 живое сетевое воспроизведение.
Позиция настоящего аудио достигла 2625 мс на телефоне и 2524 мс на TV.
Debug, тестовый APK и lint собраны успешно: 0 ошибок, 19 предупреждений.
Задача `:core:test` проверена через актуальный Gradle-кэш (43 прежних JVM-теста;
core в этом исправлении не менялся).

Тест перехода назад на TV дополнен ожиданием возврата панели после асинхронного
закрытия клавиатуры. Production-навигация не менялась; повторные 17 тестов прошли.

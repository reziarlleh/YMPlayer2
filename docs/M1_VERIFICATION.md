Общие сценарии: первый Play/мини-плеер, навигация и recreation; поиск/фильтры
без изменения playback; разделение профилей и позиций; категории/детали/очередь
и недоступный USB; error/retry и восстановление светлой темы. TV-сценарий:
начальный фокус Play, DPAD_CENTER запускает демосостояние, RIGHT + CENTER
выбирает следующий трек. В подписанном APK отдельно повторены эти TV-команды.

Восемь JVM тестов проверяют профильную изоляцию, смену источника с остановкой,
seek/stop, unavailable/foreign IDs, конец очереди, независимость каталога,
пустой источник и восстановление checkpoint с проверкой принадлежности треков.

11 предупреждений lint: 8 уведомлений о более новых инструментах/зависимостях,
targetSdk 36 вместо последнего, размер векторного TV banner и предложение указать
fullBackupContent для API <31. Для старых API явно задан allowBackup=false,
для API 31+ — исключения cloud/device transfer. Предупреждения не скрыты.

## Смерть процесса

На TV проверен именно подписанный APK: позиция установлена на 1:22, приложение
убрано в фон и завершено `am kill`. PID изменился с 7213 на 7369. После возврата
через существующую Activity позиция осталась 1:22, плеер восстановился на паузе.
[Машинный результат](qa/lifecycle.json). Force-stop и reboot — другие сценарии;
M1 не обещает сохранять всю сессию на диск.

## Исправления по результатам проверки

- Корневой Surface задаёт правильный цвет текста для обеих тем.
- В короткой области или с крупным шрифтом транспорт стоит перед artwork;
  шапка не вытесняет контент многострочным служебным статусом.
- Поиск имеет IME Search; автоматические проверки корректно прокручивают lazy
  content. Layout-runner использует реальные границы списка, а не область мини-плеера.
- SavedStateHandle восстанавливает активную очередь после смерти процесса на паузе.

## Что ещё не подтверждено

RepoWise 0.49.0 использован для навигации. Структурный индекс после реализации
M1 успешно обновлён (exit 0), актуальные контракты получены через CLI context.
Повторный refresh после заключительной правки пути Git-каталога и документации
ожидал глобальный lock; эту повторную попытку остановили. Чужие lock/processes
не удалялись. [Последний успешный refresh](qa/repowise-refresh.json) и
[контекст](qa/repowise-context.json) сохранены; заключительные правки проверены
по исходникам и PowerShell parser. Сборка и APK-проверки от индекса не зависят.

M1 — UI и демосостояние **без звука и хода времени**. Нет настоящих аккаунтов,
файлового/USB индекса, Яндекс API, скачивания/кэша, MediaSession/CWG, видео,
SideBar, updater и постоянного многопрофильного хранилища. Клипы и авторизация
обозначены как следующие этапы. Beta не снимается.

Физический K4811 не подключался. Расширенные boundary tests, полноценный TalkBack,
возврат TV-фокуса на прежнюю строку каталога, paged lists и runtime Android 36/37
не заявлены проверенными. Первый запуск AVD сопровождался системными ошибками
SystemUI/TV recommendations; падений процесса YMPlayer при итоговых сценариях
не обнаружено. Эти результаты не заменяют приёмку настоящего плеера на устройстве.

Дальше — ограниченный сценарий реального локального воспроизведения и каталога,
с отдельными контрактами и критериями. M1 не запускает автоматически всю roadmap.

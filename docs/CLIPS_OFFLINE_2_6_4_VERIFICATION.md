## B-040: настоящий touch и переход к пульту

Кнопки ClipControlsView — native TextView. Их isFocusableInTouchMode=true
заставлял Android тратить первый ACTION_UP на получение фокуса вместо click.
Обычные кнопки должны сразу выполнять onClick; это соответствует
[Touch Mode Android](https://developer.android.com/develop/ui/views/touch-and-input/input-events#TouchMode).
На старом APK настоящий DOWN/UP не запустил декодер: [red](qa/clip-offline264/touch-before.txt).

Кнопки остаются focusable для DPAD, но не получают фокус от касания. Для явного
входа с пульта используется requestFocusFromTouch. Дополнительный combined-тест
выявил: Android иногда потребляет первый navigation DOWN при выходе из touch mode
и оставляет фокус на TextureView. Обработчик принимает также оставшийся UP для
показа/фокусировки управления, не активируя кнопку этим же отпусканием.
Одной смены focusableInTouchMode было недостаточно; промежуточный вариант
не публиковался. Decoder/API/ClipActivity не менялись.

## B-041: готовое офлайн-аудио

При каждом audio() повторялись root/backup обходы и полный SHA256 под общим
mutex. Дополнительно knownTracks/decorate превращали разрешение соседей в
квадратичный обход всей коллекции. Теперь офлайн использует account-scoped
индекс, без ожидания онлайн-метаданных, а полное чтение выбранного/проверяемого
файла не удерживает общий lock для остальных треков.

Проверенный неизменный файл получает ограниченный in-memory proof (до256):
URI, размер, положительный mtime и checksum. Изменение/удаление/перенос и
неизвестный mtime не позволяют слепо использовать proof; права/существование и
контрольная сумма сохраняются. После смены места проверяется его актуальность.
Первая проверка нового/изменённого файла остаётся полной. Первое перечисление
метаданных большого SAF-каталога остаётся O(N), мгновенность тысяч query не обещана.

Расширенная регрессия нашла пропуск повреждения того же размера при грубом
mtime хранилища: 37/38 прошли, damagedAudioAndCoverAreRepairedIndependently упал.
Исправлено разделение путей: playback может переиспользовать proof, но явные
load-аудит и sync всегда заново вычисляют checksum. Они не удерживают общий
lock на время полного чтения. Тест не ослаблен; повторные проверки идут ниже.

Native slow-SAF выдаёт первые8 секунд настоящего WAV сразу, EOF закрыт gate.
На старом APK готовый трек остаётся buffering=true, position0 при offline
requests0: [red](qa/clip-offline264/cache-latency-before.txt). Условие проверяет
реальный ExoPlayer.isPlaying на main, отсутствие buffering и продвижение позиции.
Прежнее промежуточное условие state.playing давало ложный green, потому что
этот флаг обозначает Play intent; оно исправлено, результат не выдан за доказательство.

## B-042: независимый офлайн-сеанс

Ранее playOffline открывал tracks.first@0, а волна сбрасывала общие режимы.
Теперь профиль+аккаунт имеют отдельные current/position/repeat/shuffle и полный
логический порядок. Порядок сериализуется только при изменении order/revision,
текущие значения — малыми записями. Явный Offline играет с сохранённой точки,
metadata/process restore уважает Pause. Исчезнувший трек заменяется доступным,
аккаунты/профили изолированы; взаимное исключение режимов сохранено.
На старом APK возврат ожидал2-й трек, но получил1-й:
[red](qa/clip-offline264/offline-before.txt).

Первый нормальный CDN-адрес source-tag вернул403 с сообщением о лимите50 MB,
хотя APK занимает7 020 941 байт. Полное дерево source-tag —520 409 293 байт:

`81085e6419c7031b1cf6e6e47efceba240decb3e`: только четыре файла выпуска и provenance README,
всего 7023278 байт. Это пакет доставки, отдельной ветки разработки
нет; source-tag/main/история не переписаны. APK взят тем же Git blob и имеет прежний
SHA256; подпись и Build не менялись. Text-assets используют нормализацию строк Git.
[Receipt](qa/clip-offline264/distribution-tag.json).
Create-DistributionTag.py проверяет источник/хэш/размер и не перезаписывает тег;
Prepare-UpdateManifest.ps1 проверяет полный размер дерева и хэш APK из тега.

Refresh-UpdateMirrors сверяет также URL/notes, чтобы одинаковые Build/hash не
маскировали устаревшие метаданные того же выпуска.

Маленький artifact-tag решает ограничение скачивания APK. Старые клиентские
динамические `@main/update` остаются под наблюдением D-001; новая упаковка APK
не доказывает очистку их edge-кэшей или поддержку большого main на каждом узле.

# Ручной масштаб интерфейса — 2.5.5-build104

Задача11–12 октября2026: по отзыву о мелких элементах на автомобильных экранах
добавить ручной масштаб, применяемый сразу. Уточнение владельца: **50–200%,
шаг10%**. Основа — main/d15f6cd, stable2.5.4-build102. Изменения отдельного
эксперимента приборной панели не переносились; его номер103 не переиспользуется.

## Поведение и границы

- Настройки → Масштаб интерфейса: ползунок, −/+, процент и сброс100.
  Предпросмотр обновляется при движении. Влево/вправо с пульта меняют значение;
  вверх/вниз покидают ползунок. Оболочка редактора остаётся базового размера,
  поэтому ни ползунок, ни кнопки возврата не сдвигаются при настройке.
- При выходе из редактора выбранная плотность применяется к тексту, кнопкам,
  отступам остальных Compose-разделов без пересоздания Activity/аудиодекодера.
  Выбор общий для устройства; хранится в appearance/interface_scale_percent
  независимо от theme_mode, языка, профиля и пакета скина.
- Density и Configuration масштабируются совместно. Системные fontScale,
  разрешение экрана, настройки Android и состояние playback не изменяются.
- Главный плеер остаётся без прокрутки. На тесном окне PlayerViewportFit
  ограничивает увеличение по доступной ширине/высоте, чтобы основные кнопки
  не уходили за экран. Поэтому200% не обещает буквально двойной размер каждой
  кнопки на любом маленьком экране. Остальные страницы допускают прокрутку.
- ClipControlsView получает отдельный scaled Context при открытии. TextureView,
  поверхность и пропорции видео остаются в исходной плотности. Боковая панель
  K4811 — отдельная системная панель, её размеры не меняются этой настройкой.
- Нет новых permissions, библиотек, endpoint или изменений в Playback/core/API.
  Новые подписи переведены на все8 языков. Каталог сохранил прежний порядок
  сообщений; генератор проверяет678 записей и полноту пакетов.

## Начальные отказы и исправления

1. Первое увеличение скрывало кнопки на маленьких окнах: из6 начальных
   layout-прогонов прошли2. Введён ограничитель конечного плеера и rail,
   затем матрица API28 прошла6/6, после окончательной правки API35 —6/6.
   [Начальная матрица](qa/interface-scale/emulator-5560/matrix-initial.json).
2. На TV изменение rail при drag сужало редактор1696→1616 физических пикселей.
   Редактор вместе с оболочкой теперь использует базовую плотность, выбранный
   размер показывает отдельный предпросмотр; проверка ширины прошла на всех3 API.
   [Первый TV-прогон](qa/interface-scale/scale-tv-recovery-final-initial.txt).
3. Audio-тест первоначально ожидал, что импорт автоматически запустит очередь;
   исправлено явным playQueue. Следующий отказ был ошибкой теста: ExoPlayer
   читался с instrumentation thread. Сравнение экземпляра декодера выполняется
   на main thread. Это не исправление производственного playback.
   [Первый API35-прогон](qa/interface-scale/scale-api35-final-initial.txt),
   [ошибка потока теста](qa/interface-scale/scale-api35-playback-repeat-initial.txt).
4. TV-эмулятор перестал отвечать даже на getprop/pm до запуска тестов.
   Выполнена холодная загрузка того же AVD без очистки userdata. После этого
   установка debug и native-сценарии завершились. Это отказ лабораторной среды,
   не доказанный дефект приложения.
5. В добавленном предпросмотре ошибочно указан пакет SkinIcon; ошибка компиляции
   устранена, последующая сборка/lint/JVM успешны. Каталог не сортируется заново
   ради3 новых сообщений: сохранён прежний порядок и небольшой diff.

Начальные отказы не суммируются с успешными повторами как дополнительные
успешные тесты. Полные прогоны11/11 относятся к исправленному UI; последующая
перегенерация только восстановила прежний порядок ресурсов, тексты и поведение
не менялись.

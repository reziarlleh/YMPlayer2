# ADR-040 — настройки «Моей волны» из API

Историческое решение первого этапа beta81. Следующее уточнение 2026-10-06
разрешило остальные источники и режимы: [ADR-041](ADR_041_WAVE_SOURCES_AND_LIST_MODES.md).

2026-10-06. На момент первого этапа прямое указание владельца: только
«Настроить волну». Волны по треку/исполнителю/плейлисту, продолжение списка
волной и бесконечный рандом остаются отдельными задачами с уточнениями.

## Контракт

- Основной источник — `/rotor/wave/settings?seeds=user:onyourwave` с OAuth
  текущего профиля. `blocks[type=contexts].items` дают занятия, жанровые и
  mood-контексты; `settingRestrictions` — характер, настроение и язык.
  Это ближе к интерфейсу на фотографии, чем все 680 станций `/stations/list`.
- В session/new передаются выбранный контекст и `serializedSeed` вариантов.
  Настройки отдельной сессии не меняют сохранённые настройки веб-плеера Яндекса.
  Запросы settings2 POST не нужны. API отвечает за музыкальную выдачу.
- Случайный/региональный `defaultStation.stationId` из ответа не заменяет
  `user:onyourwave`. Список региональных языков и их wire-значения не выдумываются.
- Выбор хранится отдельно по паре профиль/UID. После смены аккаунта старый
  ответ отвергается; после перечитывания списка недоступные значения удаляются.
  Закрытие окна сохраняет выбор для следующего запуска, «Слушать волну» явно
  запускает новую сессию. Просмотр и изменение настроек не останавливают музыку.
- Request входит в batch и checkpoint: восстановление/ошибка session сохраняют
  контекст и настройки. Feedback идёт в выбранную станцию. Настроенная сессия
  при ошибке не подменяется ненастроенной общей волной; recovery остаётся ограниченным.
- «…» находится справа внутри общего фона кнопки волны, имеет собственный
  доступный фокус и 48dp hit-area. Главное окно не получает прокрутку;
  прокручивается только диалог. Все статические сообщения переведены на восемь языков.

## Русский язык независимо от региона

Условное пожелание владельца принято: добавлять русский, если API позволяет
отдельно выбрать его. В [публичном HTTP-срезе](qa/2-4-wave-settings/language-probe.json)
новый endpoint подписывает `settingLanguage:russian` как «Казахский»; при
нескольких пробных query параметрах список не меняется. Старый station/info
подписывает тот же ключ «Русский». Это расхождение ответов, а не доказательство
того, какой язык реально будет иметь персональная выдача.

Регион пользовательского аккаунта и эффект запроса без OAuth не установлены.
Независимый русский/казахский selector пока не подтверждён: вымышленные
`settingLanguage:ru`, `kazakh` или дублирование одного ключа двумя названиями
не внедряются. Сохранить эту часть пожелания как исследование, не объявлять
невозможной и не выдавать неподтверждённую кнопку за работающий фильтр.

## Источники и границы

- [Первичный клиент Wave](https://github.com/MarshalX/yandex-music-api/blob/main/yandex_music/_client_async/wave.py)
  и [модель настроек](https://github.com/MarshalX/yandex-music-api/blob/main/yandex_music/wave/wave_settings.py)
  описывают endpoint и seeds.
- [Модель блока](https://github.com/MarshalX/yandex-music-api/blob/main/yandex_music/wave/wave_settings_block.py)
  описывает contexts. Это неофициальный API-клиент, не гарантия сервера.
- Sanitized fixture `app/src/androidTest/assets/wave24-settings-public.json`
  взята из фактического ответа 2026-10-06. Содержит только структуру UI/протокола;
  server invocation/UID удалены. Native fixtures не подтверждают персональную
  музыкальную выдачу владельца; её приёмка учитывается отдельно.

# Яндекс Радио — оценка интеграции

Исследование2026-10-06, база **2.4.1-build84**. Запрос владельца: возможность
добавления, авторизация и возможности API. Затем владелец разрешил проверочный
прототип существующего Music OAuth для личного FM-избранного:
[текущий прогресс и точка продолжения](YANDEX_RADIO_AUTH_PROBE.md).
Владелец затем назначил **2.5.0beta**; собрана внутренняя проверка токена на
смартфоне в beta85. Полное FM-воспроизведение не реализовано, stable feeds/latest84
не меняются. [Актуальный план](PLAN_2_5.md).

## Два разных сервиса под названием «радио»

Современное [Яндекс Радио](https://radio.yandex.ru/) — прямые эфиры станций,
включая региональные версии, новости и ведущих. [Официальное описание](https://yandex.ru/support/radio/ru/radiostations).
Методы `rotor_*`, называемые Radio в библиотеках Яндекс Музыки, описывают
персональные/жанровые волны, а не каталог этих FM-эфиров.
[Исходная документация библиотеки](https://ym.marshal.dev/radio/).
Их наличие не доказывает поддержку нового FM-сервиса.

## Авторизация

- Для тематических/персональных волн подходит существующий OAuth текущего
  профиля: `YandexWaveApi` уже использует `music.account(profileId)` и
  `/rotor/session/new`, `/rotor/session/{id}/tracks`, feedback/settings
  через `api.music.yandex.net`. Дополнительный вход/отдельное хранилище не нужны.
- Эфирное Радио позиционируется как бесплатное. По официальной справке вход
  нужен для лайков/сохранения станций и треков. Каталог и метаданные станции
  реально получены без Authorization, cookies, логина или Plus:
  [срез исследования](qa/radio-research-2026-10-06/public-probe.json).
- Наличие Яндекс ID у обоих сервисов не доказывает взаимозаменяемость токенов.
  В публичном web-клиенте есть cookie/session-авторизация; общий HTTP-resource
  умеет формировать OAuth-заголовок, но его наличие не является проверкой
  приёма нашего Music-токена FM-endpoint. Персональное FM-избранное/реакции
  нашим токеном не проверены. Отдельную авторизацию заранее вводить не следует:
  сначала проверить прямой запрос с существующим токеном в ограниченном прототипе.
- Радио-треки с `yaMusicUrl` можно сопоставлять с ID Яндекс Музыки и использовать
  существующие операции «Мне нравится» для музыкального аккаунта. Это проектное
  предложение, не выполненная интеграция. Radio `trackId` нельзя передавать
  как Music ID: в публичном ответе это разные идентификаторы.

## Что доступно у эфирного сервиса

[Справка станций](https://yandex.ru/support/radio/ru/radiostations) и
[коллекции](https://yandex.ru/support/radio/ru/collection) описывают:

- Каталог/поиск станций, подбор по жанрам, выбор города/регионального эфира.
- Описание, логотип, контакты/сайт станции, включение случайной станции.
- Информацию о текущем треке, историю «Играло сегодня» и сведения о передачах.
- Любимые станции и треки после входа; трек из каталога Музыки может попадать
  в «Мне нравится». Сведения/функции могут отсутствовать у отдельной станции.

Эфирные emoji-реакции — отдельные события: их нельзя автоматически считать
лайком/запретом музыкального трека или любимой станцией.

Публичная страница дала первую подборку50 станций; у «Европы Плюс»47 вариантов
эфира. Без входа получены жанры, история, `yaMusicUrl` для части треков,
`availableFeatures` (`recently-played`, `show`, `show-host`, `widgets`). Это
результат чтения серверного JSON в HTML, не вызов официального публичного REST API.

Web-клиент использует отдельный `stationsResource`: каталог `getAll`,
`getStationsByGenre`, `getStationBySlug`, `getStreamBySlug`,
`getStreamUrlBySlug`, историю/реакции/телеметрию. URL аудио запрашивается отдельно
от метаданных. Обнаружено по публичным JS, версия frontend `radio/v1.280.0`:
[плеер](https://yastatic.net/s3/music-frontend-static/radio/v1.280.0/_next/static/chunks/077p6moz21ca1.js),
[HTTP/авторизация](https://yastatic.net/s3/music-frontend-static/radio/v1.280.0/_next/static/chunks/2h9k4qxl4xbc0.js).
Документированный публичный FM API с устойчивым контрактом для сторонних клиентов
не найден. Получение URL/формат потока, срок жизни URL, повторное подключение,
личные FM операции и воспроизведение в Media3 пока не проверены.
Web-доступ из одного сетевого окружения вернул ограничение по региону;
локальная проба вернула `serviceAvailable=true`, `userSessionRegionIso=kz`
и `geoRegionIso=kz` без входа в аккаунт.
Это не обещание доступности всех станций во всех странах.

## Возможности Music/rotor отдельно

Библиотека описывает каталог тематических станций (`stations/list`),
рекомендованные станции (`stations/dashboard`), информацию/настройки станции,
сессии выдачи следующих треков, feedback о старте/окончании/пропуске/реакциях.
Также описаны генеративные непрерывные станции; это отдельный вид потока,
не FM-эфир. [Методы rotor](https://ym.marshal.dev/yandex_music._client.radio/).
Текущие My Wave/волны по объектам2.4 уже реализуют значительную часть механизма;
каталог всех тематических станций/генеративные станции в YMPlayer2 не добавлены.
Библиотека сторонняя и документирует исследованный внутренний API; её документация
не является официальной гарантией Яндекса для сторонних приложений.

## Текущий следующий шаг и последующее предложение

Первым по уточнению владельца выполняется проверка **существующего токена** и
личного FM-избранного. HTTP-прототип и анонимные/неверные-token контроли готовы;
владелец сообщил, что токен только на смартфоне, поэтому подготовлен ручной probe
внутри beta85. Основной прогон ждёт его обезличенного результата. Это не проверка rotor и не
повторный вход с выдачей другого токена. [Отчёт](YANDEX_RADIO_AUTH_PROBE.md).

Для эфирного Радио — ограниченный прототип одного эфира: получить актуальный
URL, проверить доступ без входа, формат/Media3, остановку и reconnect; затем
каталог/поиск/города и локальное избранное. Персональную синхронизацию добавлять
после отдельной проверки существующего OAuth. Не создавать новую систему
авторизации или обширные заранее предполагаемые модули.

Live-поток не следует помещать в конечную трековую очередь волны. Для него
нужен явный режим прямого эфира: без повтора трека/списка и перемотки как файла,
с отдельными метаданными станции/играющего трека и без офлайн-синхронизации
эфира. В текущем FM web-плеере repeat/shuffle/переход по трекам отключены.
Текущая линия —2.5beta, полная интеграция ещё не выполнена; B-006 сохраняется в ROADMAP.

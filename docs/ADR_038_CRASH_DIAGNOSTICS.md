# ADR-038 — локальная диагностика необработанных исключений

2026-10-04. Причина — B-007/первый отчёт4PDA: существующий журнал событий
не объясняет вылет при касании поля поиска на Galaxy A14/API35.
[Первичный разбор](FORUM_REPORT_2026_10_04.md), текущие результаты и выпуск:
[patch2.3.3](PATCH_2_3_3_VERIFICATION.md).

## Решение

Добавить CrashDiagnostics в Android app, без нового сервиса или внешнего SDK.
При старте Application установить обёртку над исходным uncaught handler.
Она синхронно сохраняет один ограниченный отчёт в AtomicFile и всегда
передаёт исходные Throwable/Thread штатному обработчику Android. При сбое
самой записи Android всё равно получает исходное исключение. Успешная
запись не превращает падение в продолжение работы с повреждённым состоянием.

Сохраняются типы исключений, причины/ограниченное число suppressed, имена
классов/методов и номера строк. Сообщения исключений, имена потоков и файлов
не сохраняются: они могут содержать токены, пути, запросы и данные музыки.
Структура ограничена восемью исключениями, 32 кадрами каждого и 32KiB текста;
чтение повреждённого файла ограничено48KiB. Циклы Throwable распознаются.
Для retrace используются фиксированное имя SourceFile и номера строк;
R8 mapping выпуска архивируется Build-Release локально вместе с APK:
`releases/<version>/mapping.txt`, исключён из Git. Соответствующую карту
нужно сохранять для разбора отчётов прошлых опубликованных Build.

Окружение: версия приложения, API/release/buildID, manufacturer/model,
плотность, масштаб шрифта, ориентация, системные языки и компонент IME.
Контекст оболочки ограничен известным именем раздела, размерами окна и
видимостью IME. Текст поля, профиль/аккаунт, названия треков и URI не передаются.
Необходимые данные окружения вычисляются вне fatal handler.

На API30+ ручной просмотр/экспорт добавляет до пяти последних системных
причин завершения своего пакета: timestamp, числовые reason/status/importance,
PSS/RSS. Это отличает Java/native crash, ANR и завершение из-за памяти.
Description, сырые ANR/native traces и process-state summary не экспортируются.
API29 продолжает работать без вызова отсутствующего API.
[Контракт Android](https://developer.android.com/reference/android/app/ApplicationExitInfo):
системный trace обычно относится к ANR, а не гарантированному Java crash stack;
поэтому он не заменяет собственного сохранения исключения.

События, сведения о падении и окружение объединяются в существующем
**Настройки → Диагностика → Экспорт в Downloads**. Очистка удаляет crash file
и журнал, а watermark скрывает старые системные записи, которые приложение
не может удалить из Android. Отправка остаётся ручной; фоновой передачи нет.

## Проверка и границы

Pure JVM: исключение/causes/suppressed без сообщений и путей, огромный стек,
циклы, downstream при ошибке диска и повторном fatal callback, fallback.
Native: сохранение/повторное чтение/очистка; настоящий сбой отдельного
debug-only процесса, системная регистрация падения и ручной MediaStore export.
Пробная Activity отсутствует в release и не экспортирована даже в debug.

B-008 относится к диагностике и может быть закрыт после проверок выпуска.
B-007 остаётся открытым до стека и подтверждённого исправления Samsung.
Наличие нового журнала само по себе не исправляет неизвестное падение.

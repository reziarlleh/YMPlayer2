# ADR-039 — геометрия фокуса без повторного поиска

2026-10-04. Исправление B-007 в текущей линии 2.3.x.
Уточняет геометрию строк из [ADR-033](DECISIONS/ADR-033-tv-focus-navigation.md).

## Причина

В свежей диагностике build78 сохранён `StackOverflowError`. Совпадающая
R8 mapping восстанавливает цикл `AndroidComposeView.getFocusedRect` →
`ChoiceRow.focusProperties` → поиск фокуса → `getFocusedRect`.
Когда Android удерживает фокус окна, а Compose не имеет активного дочернего
элемента, запрос прямоугольника сам запускает поиск. Нельзя вызывать его
из свойств фокуса, которые вычисляются внутри этого же поиска.

Вызов добавлен в build66 (b1c16ea) для исправления пропуска выбранных пунктов
на TV. В build64 его нет, что соответствует сообщению test037. Это ошибка
приложения, а не доказанный дефект прошивки или клавиатуры. В новом отчёте
указан Gboard; прежнее предположение о Samsung Keyboard снимается.

## Решение

`PrismTheme` хранит только координаты реально сфокусированного элемента,
обновляемые событиями `prismFocus` и размещения. `ChoiceRow.focusProperties`
читает эти координаты напрямую через публичный `LayoutCoordinates.boundsInRoot`.
Android View и повторный поиск фокуса в этом вычислении не используются.

При отсутствии активного элемента используется обычная геометрия группы.
Отсоединённые координаты игнорируются, потеря фокуса и disposal очищают
свою запись, не затрагивая новый фокус. Данные принадлежат конкретному
экземпляру темы; глобальной ссылки на Activity/View нет.

При вертикальном входе сохраняется проекция на колонку текущего элемента
и переход к выбранному пункту. Стрелки не меняют выбор. Прокрутка строки,
горизонтальная навигация и выход вверх/вниз из прогрессбара сохраняются.
Provider, очередь, воспроизведение и проект 1.x не изменены.

## Доказательство и границы

Новый native-тест удерживает фокус Android-host при отсутствии активного
Compose-child и вызывает публичный `View.getFocusedRect`. На исходном коде
build78 получен тот же `StackOverflowError` и цикл. Внутренний FocusOwner
используется только в тесте для создания кратковременного состояния:
обычный Android автоматически восстанавливает фокус слишком рано.
Production не обращается к внутренним API.

Целевые тесты также проверяют выбранные строки с обеих сторон, края широкой
строки, настоящий InputConnection, поиск при аудиовоспроизведении и Slider.
Результаты: [проверка patch](PATCH_2_3_4_VERIFICATION.md).
Проверка на эмуляторах отделяется от повторной приёмки автора на SM-A145F.

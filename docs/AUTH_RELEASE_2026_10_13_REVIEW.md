# Свежий вход в Яндекс и сообщение об отказе клипов

Проверено 13 октября 2026. Последний опубликованный стабильный выпуск —
**2.6.0-build106**. Этот отчёт дополняет [проверки2.6](FILE_TRANSFERS_2_6_VERIFICATION.md).

## Авторизация

Жалоба на4PDA относится к2.5.5-build104: свежий вход недоступен, установка102,
вход и последующее обновление обходят проблему. Сравнение подписанных APK:

| APK | OAuth-конфигурация | Проверка |
|---|---|---|
| 2.5.4-build102 | Есть | Совпадает с действующей конфигурацией клиента |
| 2.5.5-build104 | Отсутствует | В DEX нет действующих значений; декомпилированный token request содержит пустой client_id |
| 2.6.0-build106 | Есть | Совпадает с102; подписанный APK на API28 получил настоящий код Яндекса |

Причина104 — выпуск из checkout без локальной игнорируемой
`.provider/yandex.properties`. Gradle допускал пустой clientId; приложение
показывало UNCONFIGURED. Это дефект комплектации APK, а не отсутствие разрешения
INTERNET. Уже сохранённая сессия выбирается раньше UNCONFIGURED, поэтому вход
через102 с последующим обновлением мог работать. Установка104→106 сама по себе
не проверяла свежую авторизацию; это ограничение прежнего выпускного прогона.

В106 проверен реальный запрос кода из production-приложения, без подмены API,
до открытия браузера. Полное подтверждение владельцем в браузере и получение
его токена этим прогоном пока не доказаны. Код/секрет/токен в отчёты не включены.
[Результат signed106](qa/auth-release-2026-10-13/latest-signed-auth.json).

Защита следующих выпусков: Build-Release проверяет наличие и формат клиента
**до резервирования Build**, после сборки сверяет конфигурацию в DEX APK.
Gradle assembleRelease/bundleRelease также отказывает при пустом clientId.
Проверены missing/empty/invalid/valid и APK102/104/106;104 отвергнут.
Gradle release dry-run прошёл;17 AccountAuth JVM-тестов без ошибок.

## Клипы

Владелец сообщил: «Не удалось воспроизвести клип. Попробуйте следующий»,
и следующий тоже не запускается. Сообщение соответствует onPlayerError:
ссылка уже передана Media3, но ошибка HTTP/сети/декодера этим текстом не различается.
Причина пока не установлена.6 native-тестов API28 запуска/предзагрузки/MP4/HLS/DASH
прошли, но работают с контролируемыми видео и не доказывают доступность реальных
потоков Яндекса. Движок/транспорт/выбор потока между104 и106 не изменялись.

Яндекс [официально сообщил](https://yandex.ru/company/news/09-10-2026-01)
о повреждении инфраструктуры Сасово/Калуги и остановке площадки во Владимире
(обновление11 октября). Это подтверждает внешний инцидент, но не устанавливает
причину конкретного отказа клипов и не доказывает уничтожение всех трёх площадок.

Следующая проверка — подтверждённый вход владельца и реальные ответы video API,
загрузка манифеста/сегментов и код ошибки Media3 при отказе. Для live-проверки
запрошено подтверждение device code; оно не завершено, код истёк
(token API invalid_grant). Токен не запрашивается у пользователя.
Дополнительно9 native AccountScreen/ClipProtocol прошли.
До получения этих данных B-030 открыт; исправление клипов не объявляется.
Новый APK только ради защиты выпускного скрипта не создаётся.

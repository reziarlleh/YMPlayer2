# M6.5 — короткая активная очередь «Моей волны»

Дата: 2026-09-29. Изменение исходников после опубликованного build49; нового
подписанного APK и приёмки на телефоне владельца пока нет.

Ответ Яндекса по-прежнему определяет ровно одного следующего кандидата.
`WaveAudioBuffer` начинает готовить его аудио во время текущего трека;
временный буфер по-прежнему хранит только текущий и следующий файлы.
После продвижения по волне `AndroidPlayback` оставляет в активном списке
Media3 предыдущий, текущий и готовый следующий трек. Это сохраняет один
шаг назад, но не накапливает длинную очередь воспроизведения. Сессия,
cursor и восстановление после сетевых сбоев не менялись. При чтении
checkpoint прежней версии плеер копирует только соседние записи; длинный
сохранённый список не остаётся активной очередью.

Проверка на Android 15: 19 сценариев `MyWavePlaybackTest`,
`WaveQueueModeTest` и `AudioQualityPlaybackTest`, 0 ошибок и пропусков
([XML](qa/m6-5/wave-android15.xml)). Длинный сценарий проходит
через седьмой трек и после каждого продолжения проверяет границу в три
элемента. Он также проверяет восстановление обычного короткого checkpoint,
паузу во время загрузки, ошибку следующего аудио, feedback, качество потока
и фильтрацию запретов. `core:test` и `app:lintDebug` завершились без ошибок.
После отдельного исправления копирования короткого окна при восстановлении
повторно прошли 2 сценария восстановления, 0 ошибок
([XML](qa/m6-5/restore-android15.xml)); `core:test` и `app:lintDebug` также прошли.

Это не завершает M11: при локальном последовательном воспроизведении
переход ещё обращается к полному снимку каталога, shuffle/repeat ALL
передают весь каталог Media3. История исключения повторов волны — до 4000
записей с метаданными — также ещё не упрощена до ID. Миграция специально
составленного старого длинного checkpoint отдельно не тестировалась.
Работа на устройстве владельца этим тестом не подтверждается.

# Ошибочные решения и правила повторного использования

### 2026-10-28 — намерение Play не равно состоянию нового или ошибочного движка

Безусловная запись `playing=false` в начале любой команды превращала ожидающий
метаданных Play в паузу. Сохранявшийся после detach флаг пользовательской команды
давал metadata-only сервису перезаписать Play тихим состоянием нового движка.
Отдельно ошибка потока ошибочно считалась паузой. На прежней логике3 из7 native
проверок воспроизвели эти случаи; явные Pause/Stop обязаны оставаться приоритетными.
Фиксировать намерение до отложенной команды, не писать промежуточную загрузку как
результат, отделять тихое восстановление метаданных от запуска воспроизведения.
[Доказательства и границы2.6.4](MAINTENANCE_2_6_4_VERIFICATION.md).

При смене владельца аудиовыхода сначала остановить уходящее радио, затем
сохранить нового владельцаMUSIC: обратный порядок давал играющую музыку с
сохранённымRADIO. При увеличении очереди также обновлять восстановление:
оставшийся старый срез из3 записей терял7 подготовленных кандидатов, которые
уже входили в фильтр повторов. Оба случая пойманы до публикации2.6.4.

Для очереди волны нельзя прекращать загрузку текущего файла лишь потому, что
быстрый Next сделал его предыдущим: файл нужен для возврата. Сохранять полное
ограниченное окно, а отменять ушедшие за его пределы/сменившие владельца данные.

### 2026-10-28 — форумные обещания и результаты приёмки должны попадать в план

Пять пунктов из чата22 октября не охватывали последующие обещания№90 о смене
online/offline-источника и подготовке волны; отдельный сброс фокуса№80 тоже не
имел записи. При сверке читать весь диалог, включая ответы владельца, новые
уточнения и подтверждения исправлений. Не считать цитаты независимыми жалобами,
ответ «подумаю» — утверждённым UI, отсутствие build — доказанной регрессией.
Пользовательскую приёмку USB/поиска учитывать отдельно от собственных тестов.
[Сверка93 сообщений и обновлённые планы](FORUM_PLAN_AUDIT_2026_10_28.md).

### 2026-10-27 — форум: разделять формы и проверять сохранённый результат

Объединение postingform с attachment POST перенесло `act=post/CODE=9` в запрос
загрузки: форум пересохранил неизменённую шапку. Для attach отправлять только
поля uploader, индекс первого экземпляра брать из JavaScript (`Array.push` →1),
не предполагать0. Предпросмотр и HTTP200 не доказывают публикацию: перечитать
редактор и публичный permalink. Старый анонимный Cloudflare HIT одного URL не
опровергает новый серверный текст другого — фиксировать каждый ответ отдельно.

Для APK скачивать реальные байты после страницы-посредника и строго сравнивать
SHA256. Форум может переупаковать PNG: отдельно сравнивать размеры и декодированные
RGB-пиксели. Иконка может рендериться статическим linked-image без attachment ID;
не объявлять её утраченной по одному поиску числового ID в публичном HTML.
[Последовательность и доказательства](FORUM_HEADER_REFRESH_2026_10_27.md).

### 2026-10-19 — fallback должен восстанавливаться в обе стороны

В2.x перенесён modern→legacy, но не обратный путь из рабочих getMoreMyWave/
getMyWaveFastStart1.x. Временный сбой делал fallback постоянным; повторная выдача
правильно отбрасывалась историей, но не оставляла нового трека. Кроме того,
recovery использовал cursor до drain. Одного успешного modern→station теста
недостаточно: проверять временный modern503, несколько legacy треков, повторы,
последний пригодный cursor, возврат modern, пустой ответ, fatal/cancel и настройки.
Не очищать историю/дизлайки и не расширять очередь для маскировки NO_PROGRESS.
Для accepted=0 нужны отдельные числовые причины, без токенов и ответовAPI.
[Red/green и реализация](WAVE_RECOVERY_2026_10_19.md).

### 2026-10-13 — TV extender: конструктор чтения не включает доступность

TvExtender(notification) читает flags существующего extension. Если Media3
notification ещё не имел extension, flags остаются0; одни content/delete intents
не включают доступность на TV. Для новой публикации использовать TvExtender()
с default FLAG_AVAILABLE_ON_TV, затем переносить optional channel/suppress
и действия. Проверять isAvailableOnTv в первой и поздней публикации обложки.
Ошибка найдена до публикации кандидата108, финальный номер109. Источник:
[AndroidX TvExtender](https://github.com/androidx/androidx/blob/androidx-main/core/core/src/main/java/androidx/core/app/NotificationCompat.java).

### 2026-10-13 — две разные карточки Android TV

У Android TV Home системная карточка фонового аудио4321 принадлежит
tvrecommendations и использует framework Pause. App notification1001 и его
TvExtender/deleteIntent — другой путь. Требование исчезновения1001 после
системной Pause давало ложный отказ: звук уже остановлен, но обычное paused
уведомление допустимо. Проверять реальную кнопку, звук/позицию, persisted intent
и именно системную карточку; отдельно — app notification dismissal.
Не называть Android TV Home платформой Google TV из-за имени пакета Google.
[Доказательства/первичные отказы](TV_NOTIFICATION_2_6_2_VERIFICATION.md).

### 2026-10-13 — pending actions и естественный конец списка

Server verifiedRevision не меняется при queued offline unlike. Кэш должен
учитывать desired membership; snapshot сервера до отправки intent не вправе
возвращать такой файл. Проверка fullSyncCannotResurrect... сначала выявила
дефект, затем прошла. Rollback одного failed persist не должен возвращать
целый старый pending list и удалять intent другого kind.

Событие EOF может быть стёрто последующим source refresh до polling tick.
Сохранять intent отдельно; metadata window не равен целому списку.
Native reproducer использует raw ExoPlayer на main: MediaSession wrapper
перенаправляет setMediaItem в очередь команд и не моделирует source refresh.
[Доказательства/границы](PATCH_2_6_1_VERIFICATION.md).
### 2026-10-13 — релиз без настроек OAuth

Игнорируемые .provider/.signing файлы не переносятся в новый worktree сами.
В104 Gradle подставил пустой clientId, а signed upgrade проверил сохранение
данных и не заметил отсутствие свежего входа. Нужно проверять OAuth до выдачи
номера, сверять его в итоговом APK и отдельно получать настоящий device code
из production APK. Сохранённая сессия и mock configured=true не заменяют этот
тест. [Подтверждение и защита](AUTH_RELEASE_2026_10_13_REVIEW.md).

### 2026-10-13 — шаблоны имён и файловые проверки

Android ICU и JVM Pattern различаются: обе фигурные скобки в шаблонной regex
нужно экранировать. JVM-тесты не заменяют native проверку. Test DocumentsProvider
должен делегировать стандартные call в super, иначе mkdir/rename/delete не
проверяют производственный код. Не запускать два Gradle процесса одного
checkout: lint может прочитать JAR в момент его перезаписи. На16GB host
одновременные3 AVD и компиляторы вызывают swapping. [Отказы](FILE_TRANSFERS_2_6_VERIFICATION.md).

SAF создание зависит от MIME/расширения: неверный тип JSON может изменить
запрошенное имя. Проверять документированное поведение системного провайдера
и моделировать его в fixture. Не удерживать файловый read-lock на сетевом
download: переносу нужен отдельный location lease, а cached playback должен
читать готовые файлы независимо от зависшего resolve. Native тест специально
блокирует resolver и пытается прочитать второй готовый файл.

### 2026-10-12 — ручной масштаб и неподвижный редактор

Менять только Density недостаточно: ветвление экранов по Configuration тогда
видит прежнюю ширину. Масштабировать их совместно. Бесконечное увеличение
конечного экрана скрывало кнопки на800×480; ограничение по доступной области
сохраняет плеер без прокрутки. Масштабирование rail при drag меняло ширину
редактора1696→1616 на TV: оболочку редактора оставить базового размера,
масштабировать отдельный предпросмотр. onValueChangeFinished читает последнее
значение из prefs, не устаревшую захваченную переменную. Для native клипов
менять только Context контролов, оставляя видео/TextureView в исходной плотности.
Начальные отказы и исправления: [отчёт](INTERFACE_SCALE_2_5_5_VERIFICATION.md).

### 2026-10-12 — проверять ошибку Git до следующего действия

PowerShell продолжает последовательность после ненулевого git exit code,
если явно его не проверить. После отказа staging из-за старого index.lock
локальный tag создался на прежнем HEAD. До push он удалён/создан заново
после успешного commit; публичный tag не переписывался. На зависимых командах
останавливаться при каждой ошибке. Lock снимать только после проверки возраста,
содержимого и отсутствия writer именно для этого worktree.
[Запись](INTERFACE_SCALE_2_5_5_VERIFICATION.md).

### 2026-10-09 — непрозрачный track ID и отрицательные AAC timestamps

Числовая проверка аккаунта/альбома не переносится на track ID: пользовательские
загрузки имеют строковые ID. Проверять сквозной путь списка, download-info,
лайков и дискового кэша, а не только редактор. Сохранять URI-сегмент безопасным.
TextureView не наследует screen-on политику PlayerView; Play/buffering должен
явно держать экран, pause/background отпускать его.
Отрицательный MediaExtractor.sampleTime у AAC priming не означает EOS;
использовать sampleTrackIndex и отдельный счётчик первого пакета. API35 дал
реальный PTS=-23219µs и обнаружил B-026. Не обходить такой отказ заменой файла
на более удобную фикстуру. [Доказательства и проверки](PATCH_2_5_4_VERIFICATION.md).

### 2026-10-09 — Bundle не заменяет настройки, SAF не универсален

rememberSaveable сохраняет состояние экрана, а не выбор пользователя после
любого завершения приложения. Режим оформления должен сохраняться сразу
при выборе независимо от жизненного цикла Activity. Наличие DocumentsUI
или доступа у другого приложения не доказывает доступ YMPlayer к USB.
Нужен доступ этого приложения; альтернативный обход должен проверяться
на публичной памяти с READ, а не только на приватной тестовой папке.
Попытка теста создать общий файл без WRITE закономерно отказала: исправлена
подготовка фикстуры, permission записи в продукт не добавлялся.
Дедупликация волны должна сохраняться отдельно от короткой очереди, а старый
курсор сам по себе не доказывает зацикливание сессии.
[Причины и свидетельства](PATCH_2_5_3_VERIFICATION.md).

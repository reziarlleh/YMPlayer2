# Ошибочные решения и правила повторного использования

## Восстановление сеанса: intent, источник и профиль должны согласовываться

6 октября прежняя политика паузы после старта была заменена требованием
продолжать последний активный источник. Нельзя сохранять только isPlaying:
буферизация и автоматическая пауза видео в фоне не равны пользовательской Pause.
Нельзя автоматически проигрывать Music при создании AudioService: сервис может
быть создан для метаданных, а последним выходом могло быть Radio/Clip.
При смене профиля записывать MUSIC/paused для входящего профиля до restore;
иначе его старый RADIO/play может включиться при следующем cold start, хотя
фактически после переключения показывался остановленный музыкальный плеер.
Клип должен ставить музыку на паузу через gate даже если она ещё восстанавливается.
[Проверки и свидетельства](SESSION_RECOVERY_2_5_VERIFICATION.md).

Кандидаты88–91 резервировались до окончания всех lifecycle-проверок и не
публиковались. Выпускной номер резервировать после финализации кода; старые
локальные APK не переименовывать/переиспользовать. Последний опубликованный
до задачи build87 сохранялся до финального92.

Постоянная навигация меняет подготовку старых тестов: Local/Radio должны явно
выбирать начальный экран. Remote-событие разрешено посылать только после
получения фокуса своим окном. Эти ошибки фикстур сначала воспроизведены,
потом адресно исправлены/проверены; не подгонять продукт под прежний default.

RepoWise: после большого изменения обычный cascade50 оставил часть страниц
stale, doctor исправил рассинхронизацию SQL/FTS/vector. Повтор с --since базы
задачи и cascade500 перестроил311 страниц без модельной генерации. `--full`
в этой версии требует provider даже с --index-only; не запускать LLM ради
структурного индекса. Symbol search всё ещё может не вернуть новый класс,
который присутствует в SQL: отсутствие выдачи не доказывает неиспользование.
[Свидетельство и ограничения индекса](qa/session-recovery-2026-10-07/repowise.json).

## FM OAuth prototype, кандидат85 →86

В первой beta85 отчёт правильно различал отсутствие FM UID и несовпадение UID,
но UI сводил оба случая к тексту «Радио не вернуло UID». Проверка только boolean
не подтверждает корректность сообщения пользователю. До публикации добавлена
отдельная ветвь сообщения и native assertions для mismatch/missing UID;
кандидат85 не опубликован, новый APK получает86. [Доказательство и прогоны](YANDEX_RADIO_AUTH_PROBE.md).

## Раздел Радио / beta87

- stream shortSlug обозначает город/вариант потока и не уникален между станциями.
  Для пагинации/карточек использовать station slug вместе со stream slug;
  проверять реальные формы stations/streams, а не только синтетический happy path.
- Порог горизонтальной компоновки считать после вычета навигационного rail.
  Проверить снимок на телефоне в обеих ориентациях, не только полный размер экрана.
- Фикстура AccountStore должна действительно сохранять save(null), а PlayQueue
  уже начинает воспроизведение. Дополнительный toggle меняет его на паузу и
  создаёт ложную регрессию. Проверять контракт команды перед исправлением плеера.
- TV requestFocus нельзя автоматически переносить на телефон в touch mode.
  TV-сценарий scoped по устройству, остальные радио-проверки проходят на API28.

Ошибки, исправления и исходные логи: [проверки87](RADIO_2_5_VERIFICATION.md).

При проверке CWG сначала включить доступ к уведомлениям и выбрать внешний
YMPlayer2 вместо встроенного CWG Player. Пустой внутренний плейлист не
доказывает отсутствие метаданных внешнего приложения. Обложка асинхронна:
появление текста раньше логотипа после Play само по себе не означает потерю
ARTWORK_URI. [Фактическая проверка CWG3.6.3-R2](RADIO_CWG_VERIFICATION.md).

## Каталоги Радио / beta93

- Не помещать suspend-ответ прямо в `state.value.copy(...)`: Kotlin сначала
  вычисляет receiver; параллельный ответ возвращает устаревшую копию. Сначала
  await, затем copy текущего state. Проверять обе очередности реальных задержек.
- Guard повторного cursor относится к продолжению списка. Первая страница
  после смены вкладки/refresh не должна сравниваться с cursor прежнего списка.
  Happy-path следующей страницы недостаточно: нужен Collection→All и refresh.
- При вложенных horizontal/vertical scroll `performScrollTo` дочерней кнопки
  может прокручивать только ближайший LazyRow. Проверять видимость и прокрутить
  внешний список перед касанием. Сбой автоматизации нельзя исправлять в аудио.
- Возврат из Dialog асинхронен. Для аппаратного фокуса использовать реальный
  DPAD, а не ожидать keyboard focus в touch mode телефона.

Падение прежнего порядка await, повторяемый cursor и исправленные прогоны:
[отчёт](RADIO_CATALOG_2_5_VERIFICATION.md).

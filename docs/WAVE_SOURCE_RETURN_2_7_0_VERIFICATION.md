## Причина в исходниках136

В AndroidPlayback.playMyWave выбор источника безусловно вызывал startWave.
restoreOfflineQueue и другие смены списка вызывали cancelWave с default
discardAudio=true. Они удаляли полный временный аудиокэш, session/cursor и
waveItems. Единственный queue:profile затем заменялся checkpoint офлайна.
Отдельная закладка offlineState уже была, симметричной закладки волны не было.

Сохранённая история исключала ещё не услышанный хвост, что правильно для
настоящего нового запуска. В ошибочном новом сеансе уже услышанный текущий
трек отфильтровывался, а бывший следующий мог оказаться первым. Конкретная
выдача сервера не гарантирована; совпадение первого трека не означает
сохранение очереди.

Native red на API35, исходный продукт136 с новым тестом: после переключения
в офлайн исчезли все10 подготовленных файлов, IDs2…11; тест упал на точной
проверке набора файлов (expected10, actual empty). Исходный отказ сохранён,
не объявляется успешным результатом.

## Исправление

- Полный существующий JSON-checkpoint Моей волны дополнительно сохраняется
  как myWaveState:profile:account в одном SharedPreferences editor с queue.
  Включает порядок, current/position, request/settings, session/cursor,
  batch каждого трека и историю; ни токены, ни временные signed URL не пишутся.
- Обычная смена источника сохраняет checkpoint перед заменой движка и
  отменяет незаконченные фоновые задачи, оставляя готовые файлы. Возврат
  использует тот же bounded restore, что восстановление процесса.
- Возврат сверяет аккаунт, source, current в IDs и station/settings.
  Офлайн-позиция/режимы и его Stop не становятся состоянием волны.
- Явный Stop/очистка активной волны удаляют её закладку. Повторный выбор
  уже активной волны и применение настроек сохраняют прежний свежий запуск.
  Другие настройки либо аккаунт не восстанавливают неподходящее окно.
  Возврат сверяет профиль и текущий аккаунт, не только ID трека.
- Подготовка аудио и пополнение10 идут по прежнему алгоритму; постоянный
  офлайн-кэш и его синхронизация не расширяются.

## Неудачные подходы и исправление

1. Браузерная загрузка требовала доступа расширения к file URLs. Native-окно
   Chrome остановлено защитой определения URL. Разрешения расширения и настройки
   безопасности не менялись. Это промежуточная остановка, затем устранённая
   переходом к прямо разрешённому владельцем HTTP-клиенту.
2. После перерыва прежняя HTTP-сессия не сохранилась. Выполнен новый обычный вход
   в4PDA в рамках подтверждённого владельцем входа/CAPTCHA. Cookies оставались
   только в памяти процесса; пароли и приватные HTML не включены в Git.
3. Ошибочно объединённая postingform с attachment POST направила запрос в
   обработчик редактирования и пересохранила старую шапку без изменений.
   Повторный редактор подтвердил точное равенство прежнего текста и сохранение
   вложений. Исправлено разделением полей формы публикации и формы загрузки.
4. Для первого uploader индекс равен1: JavaScript получает его из результата
   Array.push. Индекс0 давал404. Фактический upload использует FILE_UPLOAD[],
   code=check/upload, relId=145319180; существующие MD5 не загружаются повторно.
5. Первая ссылка APK отдаёт страницу загрузки. Проверять нужно файл по реальной
   ссылке этой страницы, а не хэш HTML. Временные download-session URL не
   опубликованы и в QA не сохранены.

Порядок, который сработал: свежая форма → отдельная загрузка → предпросмотр →
скачивание/проверка файлов → сохранение → повторный редактор и публичный GET →
скриншот → обновление журналов. [Уроки](LESSONS_LEARNED.md).

Остаток по этому заданию: замечания владельца к уже опубликованной шапке.
Разработка пяти будущих функций, клипы и эксперимент приборной панели этим
поручением не запускались.

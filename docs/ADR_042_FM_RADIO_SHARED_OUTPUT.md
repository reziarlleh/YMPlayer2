# ADR-042 — эфирное Радио и общий аудиовыход

6 октября2026. Решение для утверждённого раздела2.5; исходная компоновка —
[вариант1](RADIO_UI_DESIGN.md). Это эфирные FM-станции, а не rotor «Моя волна».

## Контракты и ответственность

- `core/Radio.kt`: станции, города/жанры, страницы каталога, коллекция и
  наблюдаемое состояние. Поиск глобальный и с задержкой350мс. Поколения запросов
  не позволяют поздним ответам сменить фильтр или коллекцию другого профиля.
- `provider:yandex/YandexRadioApi`: публичный FM API, POST добавления/удаления
  станций и существующий `AccountAuth.withSession` для личных операций.
  Собственной авторизации, токена или браузерного Cookie у Радио нет.
- `playback:android/AndroidRadio`: использует тот же ExoPlayer в AudioService.
  Другого аудиосервиса или постоянного кэша эфира нет. Добавлена HLS-поддержка:
  реальный API возвращает `.m3u8`, включая поток на домене радиостанции.
- `feature:shell/RadioScreen`: четыре вкладки, поиск, две карусели в коллекции,
  закреплённый плеер снизу/слева. На узком горизонтальном экране уменьшены
  отступы/текст плеера; каталог прокручивается отдельно. Цвета/иконки берутся
  из существующего скина; новый RADIO icon имеет стандартный fallback.

## Арбитраж и восстановление

Перед передачей движка Радио музыка сохраняет свой checkpoint. События FM
не записываются как позиция/история музыкального трека. Команда музыкального
плеера прекращает FM и восстанавливает музыкальный источник; запуск клипа
освобождает FM-аудио. Radio MediaSession разрешает play/pause/stop и скрывает
seek, next/previous, repeat/shuffle. Pause эфира означает остановку подключения;
Play получает актуальный URL и начинает прямой эфир заново.

Сеть/конец потока допускают пять повторов2/4/8/16/30с с новым запросом URL.
Stop, смена станции/профиля, передача аудио музыке/клипу и потеря постоянного
аудиофокуса отменяют работу. Последняя станция сохраняется отдельно для каждого
профиля без URL. В beta87 после перезапуска она оставалась остановленной;
новое требование владельца от6 октября заменяет это восстановлением прежнего
play/stop при явном запуске приложения. Создание сервиса само по себе не включает
эфир. [Контракт сеанса](SESSION_RECOVERY_2_5_VERIFICATION.md). Каталог загружается
только при входе в раздел. Метаданные обновляются по `pollAfterMs`, ограниченному
5–60с; отсутствие музыкального виджета допустимо и не останавливает эфир.

## Реальные особенности API

- `userRegion` обязателен у каталога/поиска/станции: отсутствие дало400,
  явно пустое значение дало200 и использует default сервера. Выбранный город
  задаёт поток; поиск остаётся глобальным.
- Stream endpoint принимает полное и короткое имя потока. В городских списках
  `shortSlug` одинаков у разных станций: ключ списка — `(stationSlug, streamSlug)`.
- Добавление: POST `/collection/stations`, `stations:[{slug,timestamp}]`;
  Unix timestamp в секундах. Удаление: POST `/collection/stations/bulk-delete`,
  `slugs:[slug]`. Форматы сверены с актуальным официальным frontend.
- Сердце относится только к станции. Подписки на шоу, коллекция радиотреков
  и emoji-реакции эфира не включены; музыкальные лайки/дизлайки не меняются.

OAuth отправляется только фиксированному HTTPS API Яндекса, без redirect.
Публичный URL эфира передаётся движку без заголовка авторизации; допускается
HTTPS без userinfo/нестандартного порта. URL/ключи не сохраняются в состоянии
UI, checkpoint или диагностике. В журнале только коды RADIO_*.

Существующий личный OAuth подтверждён экспортом владельца из86. Новые native
проверки POST используют явный тестовый транспорт и не доказывают приём реальной
записи Яндексом. Итоговые проверки/границы: [отчёт](RADIO_2_5_VERIFICATION.md).

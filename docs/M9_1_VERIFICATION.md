# M9.1 — протокол волны клипов

Дата: 2026-09-25. Это первый законченный технический шаг M9, **не готовый
экран клипов** и не новый beta-релиз.

`YandexClipApi` переносит поведение `ClipWaveClient` 1.x в границы аккаунта
2.x: создание combined session с `supportedTypes=[clip]`, продолжение с
очередью клипов, события start/finish/skip и поиск видеопотока по `playerId`.
Выбор предпочитает незащищённый HLS, затем DASH и другие потоки; при
отсутствии подходящего потока допускается preview. Ответы других типов
исключаются из очереди. Запросы исполняются через `AccountAuth.withSession`,
поэтому старый профиль/выход не должны завершить новый запрос как свой.

Отдельный `HttpsClipTransport` отправляет OAuth только на точные хосты
`api.music.yandex.net` и `frontend.vh.yandex.ru`, запрещает редиректы,
ограничивает ответ и не переносит токен в URL медиапотока. URL потока и
обложки проверяются как HTTPS-хосты Яндекса. Тексты ответов и исключений
не записываются в журнал.

Проверки: offline-сборки `:provider:yandex:compileDebugKotlin`,
`:app:assembleDebug`, `:app:assembleDebugAndroidTest` прошли. На Android TV
API 29 пройдены 3 адресных instrument-теста: форма сессии/очереди/feedback,
приоритет потока/DRM/preview и граница отправки токена. Фикстуры проверяют
наш контракт с 1.x; они **не доказывают**, что текущий личный аккаунт и
ответы живого API предоставляют клипы. Такая проверка, а также видеоплеер,
предзагрузка, аппаратное управление и аудио/видео-взаимоисключение остаются
следующей частью M9.

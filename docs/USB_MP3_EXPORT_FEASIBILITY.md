# Экспорт аудио на USB в MP3 — оценка возможности

12 октября2026, текущий2.5.5-build104. Владелец спросил о выгрузке нашего
офлайн-кэша либо плейлистов Яндекса для простого плеера. Это исследование,
не утверждение нового этапа реализации. Код приложения не менялся,
прототип экспорта и новая версия не создавались.

## Фактическое состояние

- LikedFileStore сохраняет байты DefaultDataSource в обычный файл `.audio`.
  Дополнительного шифрования аудио в модуле нет. SHA256 используется для имён
  файлов и проверки целостности, а не для шифрования. JSON-метаданные и обложка
  хранятся отдельно. Файлы лежат в private filesDir, доступ к USB надо предоставить
  отдельной командой экспорта; простое подключение телефона не открывает этот каталог.
- `.audio` — служебное расширение, не кодек. Настройка качества выбирает
  download-info вариант по bitrate, с небольшим бонусом MP3; единый формат
  всего кэша не закреплён. Полученный файл проверяется обычным MediaExtractor.
- В YandexMusicApi.stream уже учитывается поле codec=`mp3`. Это показывает,
  что адаптер рассчитан на такие ответы, но не доказывает наличие полноценного
  MP3 у каждого трека текущего аккаунта: live download-info в этой задаче не запрашивался.
- Официальное приложение Яндекс Музыки сообщает о зашифрованных загрузках,
  доступных только в нём на устройстве скачивания. Этот факт нельзя переносить
  на самостоятельно реализованное хранилище YMPlayer2.

Источники: [LikedFileStore](../library/offline/src/main/kotlin/dev/petrov/ymplayer2/offline/LikedFileStore.kt),
[YandexMusicApi](../provider/yandex/src/main/kotlin/dev/petrov/ymplayer2/yandex/YandexMusicApi.kt),
[официальная справка Яндекса](https://yandex.ru/support/music/ru/listening/listening-offline).

## Варианты реализации

1. Для кэша определить контейнер и кодек. Готовый обычный MP3 копировать,
   присвоив читаемое имя и при необходимости записав теги. Другой контейнер
   с MP3-звуком потребует извлечения потока; AAC и другие кодеки — перекодирования
   либо повторного получения исходного MP3, если сервер его предлагает.
   Одно переименование `.audio` в `.mp3` формат не меняет.
2. Для Яндекс-плейлиста получить состав через существующий аккаунт, затем аудио
   доступных треков. Сам плейлист содержит ссылки/метаданные, не музыку.
   Предпочтительно запрашивать готовый полноценный MP3: нет лишней потери качества
   и затрат CPU на перекодирование. Превью не экспортировать вместо полного трека.
3. Если нужен гарантированный MP3 из любого поддерживаемого исходника, потребуется
   отдельный MP3-encoder. В стандартной таблице Android MP3 указан как decoder,
   encoder не гарантирован. Зависимость, размер APK и нагрузку надо оценить
   перед реализацией, не добавлять библиотеку заранее.
4. Выбор USB-папки, обработка извлечения носителя/нехватки места, прогресс/отмена,
   безопасные имена файлов и теги — отдельная операция. Экспорт плейлиста
   не расширяет постоянную офлайн-синхронизацию: она по-прежнему только «Мне нравится».

Обычный незашифрованный MP3 не требует YMPlayer2, Яндекс-токена или интернета
для дальнейшего воспроизведения. Конкретный плеер должен поддерживать выбранные
параметры MP3, файловую систему, объём и структуру каталогов флешки.
Такого плеера/флешки в этой задаче не проверяли.

[Поддерживаемые Android кодеки и наличие encoder](https://developer.android.com/media/platform/supported-formats).

## Итог и следующий шаг при выборе этого этапа

Технически экспорт реализуем; дополнительное шифрование нашего кэша не препятствует
копированию. До реализации проверить реальные форматы имеющегося кэша и доступность
готового MP3 у разных треков/плейлистов. Не обещать готовый MP3 всем трекам только
по наличию проверки codec в коде. Встроенной команды экспорта сейчас нет.

# M11.9 — режимы без полной очереди локального каталога

Дата: 2026-09-30. Изменение после build51; выпуск и итоговые проверки указаны ниже.

Автоматическое воспроизведение локальной/USB-медиатеки больше не загружает
в Media3 полный каталог при включении shuffle или repeat ALL. Повтор списка
возвращает первый доступный ID после последнего; повтор одного трека остаётся
штатным режимом Media3. Shuffle хранит только перемешанный порядок доступных ID,
а метаданные получает для предыдущего, текущего и следующего трека. Обычный
режим сохраняет ограниченный список до 29 соседних элементов. Экранный порядок
каталога от shuffle не меняется.

MediaSession сообщает выбранные режимы внешним контроллерам и направляет
Next/Previous через порядок плеера. Движок не зацикливает своё короткое окно
вместо всей медиатеки. При смене профиля восстанавливаются режимы, текущий ID
и позиция; старт остаётся на паузе. Волна сохраняет отдельное продолжение Яндекса
и запрет shuffle/repeat.

## Соответствие 1.x

В `YmpPlaybackService.playNextInternal` 1.x обычный список идёт по порядку,
повтор возвращает начало, а волна получает продолжение сервиса. Эти границы
сохранены. Shuffle 1.x выбирает случайный индекс и допускает повтор раньше
полного прохода. Гарантия одного посещения каждого ID за проход существовала
в 2.x с Media3; новый порядок ID сохраняет её. Она не выдаётся за подтверждённое
свойство 1.x. Репозиторий 1.x не изменялся.

## Проверки

Первый прогон `LocalPlaybackTest` и `WaveQueueModeTest` прошёл: 18 сценариев,
без ошибок и пропусков ([XML](qa/m11-9/local-modes-android15.xml)). Отдельный
сценарий проходит 62 файла через настоящую MediaBrowser-сессию: каждый ID ровно
один раз, возврат к началу, Previous/Next и не более трёх элементов Media3.

После этого расширена проверка с намеренно запрещённым `library.tracks()`:
добавлены естественный переход с последнего трека на первый при ALL,
shuffle, Next и восстановление нового движка с режимами. Первый общий прогон
обнаружил старое синхронное ожидание позиции сразу после смены профиля.
Тест теперь ждёт завершения асинхронного восстановления, как остальные проверки.
Кроме этого общий прогон обнаружил ошибку адресного восстановления: при пустом
движке и сохранённом текущем ID цикл сравнивал отсутствующий элемент Media3
с сохранённым ID и повторял запрос бесконечно. Исправлено сравнение фактического
ID движка до и после запроса; запрещающий полный снимок тест проверяет и пустой
движок. В первом общем прогоне было 9 ошибок из 44; этот результат не считается
успешной проверкой. После исправления все 44 сценария `LocalPlaybackTest`,
`StorageRecoveryTest`, `CollectionsPlaybackTest`, `SystemBrowserTest`,
`WaveQueueModeTest` и `MyWavePlaybackTest` прошли на Android 15 без ошибок
и пропусков: [итоговый XML](qa/m11-9/regressions-android15.xml).
`core:test` и `app:lintDebug` также прошли.

## Оставшийся объём

Это не окончание M11. `SafLibrary.state.tracks` ещё держит полный снимок;
преобразование автоматического порядка в ручной и ручные списки в плеере ещё
используют метаданные всего выбранного списка. Нужно завершить хранение ручного
порядка как ссылок, убрать полный снимок библиотеки, объединить каталог с
Яндексом и проверить большой объём. Сохранённые плейлисты уже являются JSON
с упорядоченными ссылками; страницы предназначены экрану каталога, а не формату
плейлиста. Физические устройства этим прогоном не проверяются.

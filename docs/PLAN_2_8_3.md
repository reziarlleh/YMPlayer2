# 2.8.3 — аудит и исправления

Цикл и baseVersion=2.8.3 зафиксированы17 ноября2026 до изменения продукта.
Владелец поручил проверку оставшихся наблюдений, затем расширил её до тщательного
аудита и определил это целью нового билда. База — опубликованный2.8.2-build148.
Пока цели не завершены, повышается только сквозной Build внутри2.8.3.
Публикация нового релиза этим поручением не задана.

## Границы

- D-001…D-005 исключены из активной очереди решением владельца. Не расследовать
  чужие старые единичные сообщения; возвращаться только при независимом
  обнаружении в процессе будущей разработки. Архивные свидетельства сохраняются,
  статус не называется «исправлено».
- Пять будущих функциональных задач из ROADMAP не входят в аудит автоматически.
- Сохранить функциональные модули и направление зависимостей. Не объединять их,
  не добавлять заранее новые модули и не переписывать рабочие подсистемы ради чистки.
- Android6+, applicationId, подпись, данные, профили, доступ к пользовательским
  папкам и восемь языков остаются контрактами совместимости.

## Цели и критерии

1. Проверить D-006: выдачу волны, повторяющиеся кандидаты, feedback и сохранение
   контекста сессии/очереди. Сопоставить реальный протокол с исходниками;
   исправить подтверждённые ошибки. Ограничения живой проверки аккаунта указать.
2. Повторить D-007: пустой офлайн-кэш без аккаунта через современные и legacy
   медиаклиенты. Отделить устаревшие предпосылки теста от дефекта текущего UX;
   выбранный источник не должен случайно запускать прежнюю очередь.
3. Повторить D-009: сохранённый Play/Pause после разрушения аудиослужбы при
   живом процессе/Activity. Исправить подтверждённый путь без безусловного Play
   в Авто/Выкл и без потери ручных команд/позиции/очереди.
4. Аудит состояния, профилей, кэша/экспорта/SAF, отмены фоновых задач, сетевых
   ошибок, UI/фокуса, системных медиакоманд и обновлятора. Новые доказанные
   дефекты исправить в рамках цикла либо явно описать остаток и причину.
5. Проверить кандидатов RepoWise на устаревший/неиспользуемый код по настоящим
   вызовам, Android/runtime-границам и тестам. Удалять только доказанное;
   возможные оптимизации отличать от выполненных и измеренных.
6. Сверить документацию с кодом, актуализировать планы, карты, багрепорт,
   журнал и ошибки решений. Не подменять проверку функции проверкой ссылок.
7. JVM, подходящие native23/35, полный debug lint, release/R8/подпись/minSDK,
   обновление поверх148 с сохранением данных. Подготовить новый подписанный APK,
   отдельный отчёт с исходной отрицательной пробой и итоговой матрицей.

## Состав и критерии

- Уточнение после143: любая кнопка Моей волны сохраняет её текущий трек,
  позицию и полную очередь. Играющая продолжает играть, пауза возобновляется;
  после выбора аккаунта действует то же правило. Сброс — только явным Stop
  и применением изменённых настроек. [B-050](LOCAL_PROFILE_WAVE_RETURN_2_8_0.md).

- Исправление после проверки141,14 ноября: контекстный выбор аккаунта сразу
  продолжает вызванную функцию (клипы/радио/волна/Яндекс-каталог/поиск/офлайн),
  после готовности выбранного аккаунта и при необходимости завершения входа.
  Обычный самостоятельный выбор профиля остаётся на паузе. Отмена отменяет
  ожидавшее действие; поворот/смена оформления не должны его терять или повторять.
- Переименование Яндекс-профилей убирается: только имя из аккаунта. Новый профиль
  появляется в списке после успешного входа и получения имени; до этого только
  экран подключения. Отмена убирает незавершённое подключение. Старые ручные
  подписи заменяются именами аккаунтов, прежние ID/данные сохраняются.
- Уточнение владельца14 ноября: чистая установка содержит только встроенный
  неудаляемый профиль **Локальный**, для файлов устройства/USB без входа в Яндекс.
  Добавление — кнопкой **Добавить профиль Яндекс**; имя после входа берётся из
  аккаунта (displayName, затем login).
  Существующие ID/входы/очереди/настройки сохраняются; новый встроенный профиль
  добавляется отдельно. Имена всегда берутся из аккаунта; ручных подписей нет.
- Дополнительное уточнение14 ноября: функции с аккаунтом из Локального сначала
  предлагают выбор профиля Яндекса; если списка нет — предложение подключить
  с подтверждением/отменой. Не создавать профиль и не переходить к подключению
  автоматически. Отмена сохраняет прежний раздел и локальный сеанс.
- Добавление Яндекс-профилей, имена из аккаунта, удаление с
  подтверждением и быстрое переключение через существующую кнопку профилей.
- Профили Яндекса могут использовать и локальную музыку. Встроенный Локальный
  не авторизуется; прежний guest после миграции остаётся обычным отдельным профилем.
- Отдельные аккаунты, избранное/плейлисты, история, радио/волна и checkpoints.
  Обновление имени из аккаунта сохраняет ID и не требует повторной авторизации.
- Миграция прежних данных с сохранением ID owner/road/guest и их аккаунтов;
  свежая установка начинает только с Локального. Локальный не удаляется и не
  переименовывается даже при наличии других профилей.
- Общие папки устройства/USB, выданные Android-разрешения и физическое размещение
  кэша остаются общими. Нельзя удалять исходные музыкальные файлы при удалении профиля.
- Владелец уточнил: язык, скин/тема и масштаб свои у каждого пользователя.
  При выборе другого профиля всегда открывать плеер на паузе, сохранив его
  очередь/позицию; прежний Play не должен запускаться сам при переключении.
- Все новые подписи/ошибки — во всех8 языках. Проверки миграции/CRUD/изолированной
  авторизации, запоздалых ответов и воспроизведения; UI сенсор/DPAD, Android6+.
- Обе инструкции, README, карта функций/переноса, план и журнал описывают
  проверенное состояние. Полное описание2.8.0 накапливает все изменения цикла.

## Границы

После139 владелец поручил расширить диагностику для D-004/Fox_7:
зафиксировать тип/контекст команд медиасессии и уход/возврат Activity.
Это выполнено в140 того же2.8.0; политика Play/Pause/Stop сохраняется.
Критерии: реальные modern/legacy MediaController-команды видны в экспорте,
неудача записи не блокирует управление, ручная Pause не отменяется при возврате.
Контекст System UI может отображаться как media notification controller;
такую запись нельзя выдавать за достоверное имя виджета/человеческого действия.

D-004 при начале цикла отложен владельцем; после139 возобновлён
[отдельный разбор свежего137](FORUM_FOX7_FRESH_137_2026_11_13.md), без изменения кода.
Тайм-аут1003 не исправляется попутно и не выдаётся за причину нового файла.
Другие будущие функции, Google Play, приборка и1.x не запускаются.
Пароли/PIN/семейные ограничения/облачная синхронизация профилей не поручены.
До приёмки и разрешения публикации Stable/Latest/update feeds сохранялись на 137;
после разрешения 14 ноября обновлены до 144.

# M11.6 — последовательный локальный режим без второй полной очереди

Дата: 2026-09-29. Исходники после опубликованного build49; новый APK для этого
изменения ещё не выпущен.

`AndroidPlayback` при обычном последовательном воспроизведении больше не
сохраняет полный `List<Track>` в `logicalQueue`. Плеер удерживает ближайшие
элементы Media3 и соответствие их ID абсолютным позициям; `PlaybackState`
по-прежнему содержит окно до 29 треков. При переходе, выборе далёкого трека
и редактировании порядок пока разрешается из `SafLibrary.state`. Включение
shuffle или повтора всей очереди всё ещё передаёт полный список Media3;
ручная очередь и «Моя волна» используют отдельные прежние пути.

На Android 15 прошли все 13 `LocalPlaybackTest` (0 ошибок), включая дальний
выбор, изменение очереди и переключение режимов. Дополнительно выполнены
`StorageRecoveryTest`, `BootCheckpointTest`, `CollectionsPlaybackTest`,
`SystemBrowserTest`, `WaveQueueModeTest`: 18 сценариев, 0 ошибок, 1 пропуск
([XML](qa/m11-6/regressions-android15.xml)). Пропущен
`BootCheckpointTest.checkpointAcrossEmulatorBoot`, которому нужен отдельный
режим запуска; его прежняя проверка описана в [M8.4](M8_4_VERIFICATION.md).
`app:lintDebug` и `core:test` завершились без ошибок.

Это **не завершает M11**: `SafLibrary.state.tracks` хранит полный каталог,
временная выборка для смены трека ещё проходит по нему, а shuffle/repeat ALL
оставляют полную очередь Media3. Следующий перенос должен получать текущий
трек и соседей адресно из SQLite, затем убрать постоянный снимок библиотеки
без потери USB-ссылок, восстановления и редактируемых списков.

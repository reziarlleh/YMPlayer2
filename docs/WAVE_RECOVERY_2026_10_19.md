# Восстановление волны после2–3 треков —19 октября2026

Стабильный выпуск — **2.6.3-build119**.19 октября владелец прямо разрешил
публикацию. Опубликован тот же подписанный APK119 без пересборки, с прежними
package/ключом/API28+. Предыдущий stable2.6.2-build117 и pre-publication QA ниже
сохраняются как исторические свидетельства, не как текущий канал обновления.

## Исходные сообщения

- Волна играет2–3 песни, затем остаётся на поиске. На фотографии диагностик видны
  WAVE_DRAIN returned=5 accepted=0, session=false и исчерпание попыток NO_PROGRESS.
- Другой пользователь117 видит «Яндекс не прислал новых треков для волны»;
  следующий трек иногда появляется только послеEOF/перемотки к концу.
- Исследуется общая логика, без привязки к моделиГУ. Доступность других сайтов
  сама по себе не доказывает доступность каждого API Яндекса.

Фото не заменяют полный журнал. NO_PROGRESS формирует приложение после
ограниченных попыток; сам код не доказывает ни отсутствие сети, ни неисправностьГУ.
Совпадение точных персональных ответов Яндекса с fixture пока не доказано.

## Подтверждённая причина и исправление

1. Первоначальная временная ошибка modern session переводила волну на legacy
   station. Исправное legacy-продолжение работало, но при повторении небольшого
   набора recovery вновь вызывал только legacy. Возврата к modern не было.
   Теперь застрявший sessionless/legacy повторно создаёт modern session, сохраняя
   seeds/станцию/cursor. Если modern временно недоступен, остаётся ограниченный
   fallback на ту же станцию. Settings и SIGN_IN/ACCESS не обходятся.
2. WaveLoader передавал в recover исходный previous, хотя drain уже продвинул
   server cursor. Теперь отдельно сохраняется последний пригодный batch;
   пустой ответ его не стирает, исключения также не отматывают продолжение.
3. cursorAdvanced мог сравниваться сnull после перехода в recovery и ложно
   показывать продвижение. Теперь сравнивается фактический запрос и непустой
   новый cursor. Добавлены числовые unavailable/seen/blocked для причин фильтрации.

История правильно отбрасывала уже услышанное; очищать её было бы маскировкой
ошибки. Сохранены4000 элементов истории по профилю/аккаунту, дизлайки треков/
артистов, настройки, короткая очередь, current+next предзагрузка и ограниченные
попытки. Fatal/cancellation, pause/stop и защита от позднего ответа сохранены.
Fallback после пустого modern вынесен за catch: сбой station не удваивает запрос.

УEOF уже был собственный ограниченный бюджет повторов — это совместимо с
наблюдением «иногда появляется в конце», но не доказывает сетевой сценарий
конкретного пользователя. Основное исправление восстанавливает фоновую подгрузку
во время текущей песни, не требует ожидатьEOF.

Reference1.x, только чтение: YandexMusicClient.getMoreMyWave при отсутствии session
повторяет getMyWave, YmpRepository.loadMoreWave начинает recovery через
getMyWaveFastStart. В2.x обратный переход перенесён неполно. Исходники1.x не менялись.

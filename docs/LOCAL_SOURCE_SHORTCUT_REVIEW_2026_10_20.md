# Быстрый возврат к локальной музыке — анализ 20 октября 2026

Статус на22 октября: быстрый переход к последнему локальному списку включён
в [планы будущих версий](ROADMAP.md#будущие-версии) по прямому указанию владельца.
Ниже сохранён разбор20–21 октября, без реализации и нового релиза; поведение
возобновления и номер версии ещё не назначены. Stable остаётся **2.6.3-build119**.
Это не новый подтверждённый баг воспроизведения.

Прочитана [четвёртая страница темы4PDA](https://4pda.to/forum/index.php?showtopic=1127108&st=60).

плейлисты для быстрого доступа. Эти варианты следует различать.

## Подтверждённое состояние кода

- [PlayerScreen](../feature/shell/src/main/kotlin/dev/petrov/ymplayer2/shell/PlayerScreen.kt#L77):
  верхнее меню запускает волну, офлайн или локальное избранное. В дополнительных
  действиях уже есть фильтры LOCAL/USB.
- [AndroidPlayback.chooseSource](../playback/android/src/main/kotlin/dev/petrov/ymplayer2/playback/AndroidPlayback.kt#L549):
  смена фильтра выбирает доступный локальный трек с позицией0; это не возврат
  к прежней локальной сессии. Индексируемая ветка вызывается с resume=false.
- [restore](../playback/android/src/main/kotlin/dev/petrov/ymplayer2/playback/AndroidPlayback.kt#L1165)
  и [checkpoint](../playback/android/src/main/kotlin/dev/petrov/ymplayer2/playback/AndroidPlayback.kt#L1430)
  используют один queue:$profile. Отдельного last-local snapshot нет. Переход
  к волне заменяет музыкальное состояние; source:$profile хранит только фильтр.
  Оставшийся references:$profile без согласованной локальной позиции/источника
  не является сохранённой последней локальной сессией.
- [ShellApp](../feature/shell/src/main/kotlin/dev/petrov/ymplayer2/shell/ShellApp.kt#L189)
  сохраняет состояние просмотра по профилю/маршруту. Открытие локальной медиатеки
  и возобновление аудио — разные действия. Маршрут folders управляет разрешёнными
  папками; простой переход туда не равнозначен открытию прежнего списка музыки.
- Текущая группа каталога не обязательно равна воспроизводимой очереди. В UI
  нужно различать каталог, явно запущенный список и автоматически следующий
  библиотеке источник, а не обещать возврат в «папку» без уточнения.

Это адресная проверка актуальных исходников и независимый review, без сборок,
эмуляторов, физических устройств и runtime-экспериментов. RepoWise имеет ранее
зафиксированный stale index; выводы проверены в исходниках, а не приняты из индекса.

## Технические границы

Android предоставляет [getStorageVolumes](https://developer.android.com/reference/android/os/storage/StorageManager#getStorageVolumes())
для перечисления видимых пользователю общих/внешних томов, включая SD/USB.
Обнаруженный том сам по себе не даёт дополнительных прав на его файлы.
[SAF](https://developer.android.com/training/data-storage/shared/documents-files)
предоставляет доступ к выбранной пользователем папке; существуют ограничения
выбора корней и утрата доступа при удалении/перемещении документов.

Таким образом, автоматический список всех физических устройств и их файлов
не следует обещать без условий. При этом для возврата к уже известной очереди
можно использовать сохранённые ссылки каталога и ранее выданные разрешения,
не угадывая носитель по имени/пути. Число подключённых носителей этому не мешает.
Отключённая флешка, удалённый файл и отозванное разрешение остаются реальными
ограничениями воспроизведения; их нужно показывать явно.

## Сопоставление вариантов, не утверждённый план

1. **Открыть локальную медиатеку.** Короткая навигация с onlineSource=false;
   сама по себе не должна останавливать текущую музыку. Упрощает выбор, но
   не полностью решает запрос на продолжение прежнего локального воспроизведения.
2. **Продолжить локальную музыку.** Отдельный сохраняемый checkpoint на профиль:
   тип очереди, порядок/область каталога, текущийID, позиция и режимы. Нужны
   правила проверки доступности и обработки отсутствующего текущего трека.
   Не выбирать другую флешку/первый трек молча и не терять текущую сессию при отказе.
3. **Закреплённые папки/плейлисты.** Управляемый пользователем быстрый доступ,
   дополнение к возврату последней сессии. Локальное избранное остаётся выборкой
   любимых треков; принудительно складывать туда всё ради навигации не требуется.

Пункт в существующем всплывающем меню не требует прокрутки самого главного
экрана. Неограниченное дерево папок на главном экране, неявное объединение всех
носителей и неочевидные кнопки с разными действиями могут ухудшить UX; это
основание определить понятную семантику, а не запретить быстрый возврат вообще.
Автоматическое переключение при пропаже интернета не входит в рассмотренный
запрос ручного возврата и не запускается этим обсуждением.

## Уточнение21 октября: явное сохранение локального списка

Предложение владельца: у текущей очереди добавить команду «сохранить как последний
локальный список», доступную только для действительно локальной очереди.
Так пользователь явно выбирает назначение быстрого возврата; приложение не
выводит его из истории волн, радио, поиска и клипов.

Предлагаемое поведение, пока без реализации:

- Непустая очередь целиком состоит из LOCAL/USB. Проверять полный логический
  список: окно PlaybackState.queue и источник одного текущего трека недостаточны.
  Скачанный трек Яндекса остаётся YANDEX и не проходит это условие.
- Один сохраняемый список на профиль; следующая явная команда заменяет прежний.
  Обычные переключения источников сохранённый выбор не меняют. Возврат доступен
  из существующего верхнего меню выбора источника.
- Сохраняются ссылки на файлы и порядок всей очереди, без копирования аудио.
  При отсутствии носителя/прав показывается проблема, текущая музыка не теряется
  из-за неудавшейся проверки доступности.
- Состав/порядок и продолжение с конкретного трека/времени — разные обещания.
  Не считать возобновление позиции уже решённым обычным сохранением плейлиста.

Повторная адресная проверка21 октября: editableReferences в AndroidPlayback
возвращает полный порядок явной очереди либо индексированного каталога.
[Collections](../core/src/main/kotlin/dev/petrov/ymplayer2/core/Collections.kt#L11)
хранит SavedTrack и порядок; CreateMany создаёт новый UUID и запрещает повтор
названия. [LocalCollections](../library/local/src/main/kotlin/dev/petrov/ymplayer2/library/LocalCollections.kt#L38)
атомарно записывает данные профиля. Это основа для повторного использования,
но готового перезаписываемого слота и позиции воспроизведения в ней нет.
RepoWise context не завершился и был прерван; выводы основаны на актуальных
исходниках и независимом review. Сборки/устройства для обсуждения не запускались.

Приложение, настройки, переводы, README и инструкции пользователя не менялись.
На20–21 октября реализация, включение в план и публикация ответа на4PDA не
выполнялись. 22 октября в план добавлен быстрый переход к локальному списку;
это не меняет статус реализации и выводы проверки выше.

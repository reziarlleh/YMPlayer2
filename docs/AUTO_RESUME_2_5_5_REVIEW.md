# Проверка автовосстановления — 2.5.5-build104

12 октября2026. Проверка по вопросу владельца: восстанавливается ли только
раздел/очередь/позиция или само воспроизведение тоже. Сверены текущие исходники
main, RepoWise context и сохранённые свидетельства; новые runtime-тесты не запускались.

## Результат

Автопродолжение уже реализовано при открытии приложения. LaunchStateStore
хранит последний источник и признак playing отдельно для профиля.
PlayerApplication.restoreLaunch вызывается из MainActivity; восстановление
самого процесса AudioService не равносильно команде включить звук.

| Источник | Сохранено playing=true | Сохранено playing=false |
| --- | --- | --- |
| Музыка | resumeOnLaunch, сохранённый трек/очередь/позиция; для Яндекса после восстановления аккаунта | Очередь/позиция восстанавливаются на паузе |
| Радио | restoreOnLaunch повторно включает выбранную станцию, с актуального прямого эфира | Станция выбирается, эфир остаётся остановленным |
| Клипы | Если последним разделом были Клипы, открывается ClipActivity, checkpoint запускается с сохранённой позиции | Автоматическое восстановление остаётся на паузе |

Явное закрытие клипа кнопкой Назад сохраняет паузу и прежний раздел возврата.
Уход клипа в фон временно ставит видео на паузу, сохраняя прежнее намерение Play.
Медиапозиция записывается периодически и при уходе с экрана. При резком
обесточивании до записи на накопитель последняя запись не гарантируется.
Для продолжения необходимы доступный файл/USB либо рабочая сеть и авторизация.

Самостоятельного запуска YMPlayer2 по BOOT_COMPLETED нет: приложение не содержит
такого receiver/разрешения. Если автомобильный лаунчер сам открывает YMPlayer2,
срабатывает обычное восстановление при запуске. Стандартные медиакоманды
остаются отдельным способом управления плеером.

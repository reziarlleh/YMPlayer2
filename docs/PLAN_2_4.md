# 2.4 — настройки и источники волны, бесконечный рандом

Утверждено владельцем 2026-10-05. База — main / stable 2.3.4-build79,
после [оценки совместимости](API_28_FEASIBILITY.md). Одна последовательная
линия разработки, без параллельных исправлений 2.3.
2026-10-06 владелец расширил состав 2.4: основное добавление — управление
волнами и поведением списков. API28 расширяет поддерживаемые устройства.

## Текущие этапы по указанию владельца

1. Получать доступные занятия, характер, настроение и язык из API Яндекса
   в контексте текущего аккаунта. Не выводить региональные языки из фотографии
   как общий фиксированный список. Меню настроек — символ «…» внутри кнопки
   «Моя волна», справа, отдельная доступная с пульта команда.
2. Отдельная задача после уточнений: запуск волны по треку, исполнителю и плейлисту. Сохранять выбранный
   источник при продолжении, восстановлении и feedback; не подменять его общей волной.
3. Отдельная задача после уточнений: для конечных Яндекс-списков четвёртый режим кнопки повторения:
   после списка продолжить волну по источнику списка. Сохранить OFF/ALL/ONE.
   Для альбома/подборки использовать соответствующий источник, не случайный трек.
4. Отдельная задача после уточнений: рандом любых конечных local/USB/Яндекс-списков играет бесконечно в пределах
   списка; повторение при рандоме недоступно. В самой волне эти кнопки скрыты.
5. Для завершённого первого этапа проверить выбор/сессии/восстановление,
   обновить инструкции/карты и выпустить следующий
   сквозной Build как ручной prerelease. Stable feeds/latest сохраняют79.

Этап1 реализован 2026-10-06: 98 JVM и 42 native-проверки пройдены,
ручная beta81 опубликована, signed80→81 и HTTP сверены. [Подробности](WAVE_SETTINGS_2_4_VERIFICATION.md).
Последующее уточнение владельца: выполняется только «Настроить волну»;
пункты2–4 не запускаются автоматически, каждый обсуждается отдельной задачей.
Старый build80 остаётся опубликованным свидетельством адаптации API28,
а не завершением расширенного плана2.4. Приёмка прежних устройств не получена.

## Завершённая подготовка API28 (build80)

1. Снизить minSdk 11 Android-модулей до 28, сохранив target36/compile37.
2. Адаптировать foreground офлайн-синхронизации, экспорт диагностики и
   освобождение MediaMetadataRetriever; сохранить пути API29+.
3. Проверить lint всех модулей и целевые runtime-сценарии на API28, TV29 и API35.
   Замечания B-009 устранить точечно, если они мешают полной проверке.
4. Выделить следующий сквозной Build, собрать APK прежним ключом, проверить
   пакет/минимум/подпись и signed установку поверх79 на прежних эмуляторах.
5. Опубликовать GitHub **prerelease**, ручную ссылку и отчёт. GitHub latest,
   `update/manifest.json` и `update/stable.json` сохраняют stable79/min29.

## Ограничение распространения

2.4.0beta не публикуется в манифестах автоматического обновления до явного
подтверждения стабильной работы на прежних устройствах владельцем/пользователями.
Проектные тесты и эмуляторы не заменяют это подтверждение. Beta сохраняет
applicationId и сертификат2.x; установка поверх2.3 сохраняет данные.
Клиент beta продолжает слушать **stable** feed, чтобы после отдельного решения
получить стабильный выпуск с более высоким Build. Отдельного beta feed нет.
Возврат на79 после установки beta с более высоким versionCode обычным
installer невозможен; удаление приложения удаляет его приватные данные.

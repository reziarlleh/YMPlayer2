# M11 — порядок ID локальной очереди (работа после build47)

Дата: 2026-09-28. Это промежуточная проверка исходников, **не выпуск APK**.

`IndexedLocalLibrary.orderedTrackIds(source)` читает из SQLite только ID в
устойчивом порядке `title_key,id`, включая строки временно недоступного USB.
Для фильтра источника добавлен индекс `(source,title_key,id)`; база переходит
с версии 1 на 2 созданием индекса без замены строк. Одновременные запросы
`SafLibrary.refresh()` после старта не повторяют уже завершившийся обход.

`PlaybackController.queuePage()` задаёт порционный контракт экрану очереди.
`QueueScreen` загружает видимые строки по 80 и удерживает до пяти ближайших
страниц; дальний переход не требует последовательного раскрытия списка.
`AndroidPlayback` при автоматической локальной очереди берёт порядок ID из
SQLite, затем запрашивает метаданные нужной страницы по этим ID. Ручная
очередь и волна сохраняют прежний порядок через реализацию по умолчанию.
Так ограничен кэш UI, но ещё не память логической очереди плеера.

На Android 15 прошли три теста `LocalIndexMigrationTest`: импорт старого JSON,
группы и порядок ID с фильтрами, обновление существующей базы 1→2 с сохранением
недоступной USB-ссылки. Отдельно прошли 12 сценариев `LocalPlaybackTest` до
изменения UI и два адресных сценария после него: редактирование/режимы и
прямой переход к треку №96 в очереди из 102 элементов. После подключения
SQLite-страницы оба сценария повторены; тест сравнил ID страницы 81–102
с действительным порядком очереди.

Плеер пока продолжает брать полный `List<Track>` из `SafLibrary.state` для
автоматического воспроизведения и хранить его в `PlaybackState.queue`. Следующее
изменение должно оставить метаданные только в окне вокруг текущего трека,
сохраняя shuffle/repeat, редактирование и восстановление.
M11 не завершён; build47 остаётся последним опубликованным APK.

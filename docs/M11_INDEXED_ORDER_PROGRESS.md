# M11 — индексные страницы локальной очереди (работа после build47)

Исходники проверены 2026-09-28; экранные изменения выпущены в
`2.0.0beta-build48`. Переход аудиодвижка на курсор остаётся будущей работой.

Промежуточный `orderedTrackIds` читал из SQLite все ID в устойчивом порядке
`title_key,id`; после уточнения владельца он удалён как ненужная полная очередь.
Страницы сохраняют тот же порядок, включая временно недоступные USB-ссылки.
Для фильтра источника добавлен индекс `(source,title_key,id)`; база переходит
с версии 1 на 2 созданием индекса без замены строк. Одновременные запросы
`SafLibrary.refresh()` после старта не повторяют уже завершившийся обход.

`PlaybackController.queuePage()` задаёт порционный контракт экрану очереди.
`QueueScreen` загружает видимые строки по 80 и удерживает до пяти ближайших
страниц; дальний переход не требует последовательного раскрытия списка.
Первый вариант `AndroidPlayback` собирал весь порядок ID из SQLite, затем
запрашивал метаданные страницы. По замечанию владельца от 2026-09-28 это
лишняя промежуточная очередь: теперь страница автоматического каталога
читается сразу индексным запросом. Ручная очередь и волна сохраняют прежний
порядок через реализацию по умолчанию. Так ограничен кэш UI, но ещё не память
логической очереди плеера.

Индекс получил запрос одного соседнего доступного трека по `(title_key,id)`
с фильтром источника и переходом через край для повтора. Он не материализует
все `Track`. Это подготовка к [решению ADR-031](DECISIONS/ADR-031-catalog-cursor-not-queue.md),
аудиодвижок пока этим запросом не пользуется.

На Android 15 прошли три теста `LocalIndexMigrationTest`: импорт старого JSON,
группы и порядок ID с фильтрами, обновление существующей базы 1→2 с сохранением
недоступной USB-ссылки. Отдельно прошли 12 сценариев `LocalPlaybackTest` до
изменения UI и два адресных сценария после него: редактирование/режимы и
прямой переход к треку №96 в очереди из 102 элементов. После подключения
SQLite-страницы оба сценария повторены; тест сравнил ID страницы 81–102
с действительным порядком очереди.
После упрощения прямого запроса страниц и добавления соседнего трека
повторены все `LocalPlaybackTest` (13) и `LocalIndexMigrationTest` (3) на
Android 15: 16/16, без ошибок. Подписанный APK build48 и реальный переход
build47→48 проверены отдельно в [M12.4](M12_4_VERIFICATION.md).

В build49 `PlaybackState.queue` для автоматического локального режима
содержит только окно до 29 `Track`, отдельные абсолютную позицию и общее число.
Экран очереди читает любую далёкую страницу из SQLite; перевод этой очереди в
ручную при перестановке сохраняет порядок и текущий трек. На Android 15
повторены все 13 `LocalPlaybackTest` (13/13), включая переход к №96 из 102
и переключение ограниченного/полного режима Media3. Изменение вошло в
[подписанный build49](https://github.com/reziarlleh/YMPlayer2/releases/tag/v2.0.0beta-build49).
После исправления повторного запроса страницы при обновлении индекса адресный
сценарий прямого перехода прошёл ещё раз (1/1); `:core:test` и `:app:lintDebug`
также завершились без ошибок.

Плеер всё ещё берёт полный `List<Track>` из `SafLibrary.state` и держит его в
`AndroidPlayback.logicalQueue`. Следующий шаг — заменить эту автоматическую
очередь курсором по текущему ID/источнику, оставить явный порядок ID только
для редактируемых списков. Shuffle/repeat, возврат USB, восстановление и волна
требуют регрессии. M11 не завершён; build49 — последний опубликованный APK.

# M9.2 — первый видеоплеер клипов

Дата: 2026-09-25. Реализован отдельный `feature:clips`, а не ещё один режим
аудиоочереди. Пункт «Клипы» открывает неэкспортируемый полноэкранный экран
с собственным ExoPlayer; текущая музыка ставится на паузу до открытия видео
и не возобновляется сама после выхода. Системная «Назад» закрывает экран.
У видео есть переключение, история назад, скрываемые во время воспроизведения
элементы управления, обработка ошибок и предварительный запрос следующего
клипа и URL потока. Это **не предзагрузка видеобайтов**: прогрев Media3
следующего элемента остаётся до завершения M9. HLS и DASH подключены как
отдельные Media3-модули.

Подписан `2.0.0beta-build29` (`versionCode=29`, SHA-256
`14a54a8057394a86525cc3f46fc0024236f9df1a2e334d3f3ab38beddc6a490f`).
APK установлен поверх build28 на Android 15 phone и поверх build27 на TV API 29;
`firstInstallTime` в обоих случаях сохранился. На обоих эмуляторах итоговый
неотладочный APK открыл экран из вкладки, без входа показал подсказку, а
системная «Назад» вернула к основному плееру. Экран визуально проверен на
телефоне и TV; TV-пульт в живом видео ещё не проверен. Адресный
`ClipHandoffTest` проверил паузу аудио при входе и отсутствие самопроизвольного
возобновления после закрытия. Три теста протокола и handoff прошли на обоих
эмуляторах (`OK (4 tests)` на каждом). `assembleDebug`, `assembleDebugAndroidTest`,
`assembleMinifiedDebug`, `lintDebug`, release build и `:core:test` прошли.
Первый запуск теста handoff на телефоне опередил обновление каталога в
аудиослужбе и не смог начать аудиофикстуру; тест теперь ожидает/повторяет
запуск до готовности каталога, после чего проходит. Это изменение только
теста, не доказательство исправления функции в продукте.

Кандидат build25 остался зарезервирован после ошибки компиляции release:
зависимость ExoPlayer была только в debug. Подписанные build26–28 не публиковались:
при проверке Android 15 release обнаружилось, что Compose-кнопки клипов
закрывает чёрный видеослой. Для воспроизведения дефекта добавлен отдельный
`minifiedDebug`-вариант без выдачи номера Build; в итоговом экране поверх
`TextureView` используются нативные элементы управления. Их видимость
проверена в минифицированном варианте и в подписанном build29 на Android 15/TV.
Промежуточные номера повторно не используются.

**Открыто:** живые сессии Clip Wave и реальное HLS/DASH-видео личного аккаунта,
длительная очередь, предзагрузка видеобайтов, аппаратные кнопки/TV-фокус во
время видео и поведение при смене аккаунта. Пока этого нет,
M9 нельзя объявить полностью принятым. Тесты протокола M9.1 используют
контрактные ответы, а не реальный ответ Яндекса.

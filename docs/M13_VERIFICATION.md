# M13 — пользовательские скины 2.1.0

Дата: 2026-10-01. Кандидат `2.1.0beta-build63` создан и проверен локально;
стабильный [2.1.0-build64](https://github.com/reziarlleh/YMPlayer2/releases/tag/v2.1.0-build64) опубликован. Build63 не публиковался и
не менял канал обновлений stable62. Сквозная нумерация сохранена.

## Реализация

В существующем designsystem находятся [парсер](../designsystem/src/main/kotlin/dev/petrov/ymplayer2/designsystem/skin/SkinPackageReader.kt)
и [SkinRepository](../designsystem/src/main/kotlin/dev/petrov/ymplayer2/designsystem/skin/SkinRepository.kt).
Пакет ZIP/JSON содержит только [визуальные данные](SKIN_FORMAT.md).
Проверяются версия, ID, поля, роли/цвета, пути, повторения, размеры и векторы.
Ничего не распаковывается по указанным в пакете путям и не загружается из сети.
Пользовательские копии и активный ID сохраняются отдельно от музыкальных данных.

SAF в MainActivity передаёт файл на проверку. Preview имеет два режима и
отдельное «Применить». Ошибка нового импорта очищает его preview и сохраняет
активный скин. При повреждении активной копии после перезапуска включается
«Оксид». Удаление доступно только для неактивных пользовательских пакетов.
Готовы «Гавань», «Олива», «Серебро», шаблон «Оксида»,
[упаковщик](../tools/Pack-Skin.py) и [руководство автора](SKIN_AUTHOR_GUIDE.md).

Compose получает выбранный AppSkin. Native ClipControlsView меняет цвета
существующих Views; фокус, команды, сессия и медиапозиция не меняются.
Белая панель K4811 и официальные launcher/TV banner сохраняют свои контракты.
Структура экранов, размеры кнопок и шрифты не входят в внешний контракт v1.

## Найденные неверные пути

Первоначальная проверка native recolor требовала точного равенства миллисекунд
играющего видео, хотя время продолжает идти. Исправлена проверка непрерывного
прогресса без сброса. LazyColumn-тест обращался к ещё не созданной строке;
теперь список сначала прокручивается до её semantics. D-pad focus проверяется
на TV, а телефон проверяет touch: принудительный focus в touch mode был ошибкой
теста, не импортёра. Эти неудачные результаты не выдаются за успешную приёмку.

Отдельно найден реальный прежний дефект поворота TV29: при переходе в портрет
изменялся `screenLayout` (configuration diff `0x20000580`), не включённый в
configChanges ClipActivity. Добавлен `screenLayout`; изолированный тест и
общий прогон сохранили ту же Activity и контроллер. Логи до/после сохранены.

## Границы доказательств

Использовались только `emulator-5554` (Android 15) и `emulator-5556` (TV29).
WAV/HLS/DASH — реальные собственные медиаданные, не новая личная сессия Яндекса.
Аппаратные K4811/CWG/USB и личная сеть владельца не переобъявляются принятыми.
Они не блокируют отдельный программный этап M13. Репозиторий 1.x не изменялся.
Подпись и `runtimeAcceptance=pending` сохраняют эту границу в build.json.

## Публикация

Stable64: 4 870 013 байт, SHA-256
`dc4cd82e280074e580f89635b9026e11abf3b28f0b5777ad3fb1ade724b5f889`.
GitHub release публичный, без draft/prerelease; восемь assets — APK, SHA-256,
подпись, build.json и четыре пакета тем/шаблона. APK присутствует в теге
`v2.1.0-build64`, что обеспечивает резервный version-pinned jsDelivr URL.
Оба манифеста отправлены для build64. [HTTP-сверка](qa/m13-skins/publication.json):
GitHub, jsDelivr и Gcore отдали идентичный APK64 по размеру/SHA-256.
GitHub raw и jsDelivr отдают manifest.json/stable.json64. Gcore @main ещё
кеширует stable62/общий61; его version-pinned APK64 доступен и совпадает.
Клиент сравнивает все валидные манифесты и выбирает максимальный Build, поэтому
запаздывание третьего источника не понижает предложение64 от первых двух.
Изначальная HTTP-проверка не прошла для одного из трёх APK-адресов; повторная
проверка прошла без изменения APK. Состояние сети не объявляется дефектом приложения.
Первый вызов GitHub API отклонил короткий target SHA; повтор с полным commit ID
успешен. Это ошибка команды публикации, не дополнительная сборка приложения.

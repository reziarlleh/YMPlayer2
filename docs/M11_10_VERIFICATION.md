# M11.10 — каталог на диске, ручные ссылки читаются по ID

Дата: 2026-09-30. Актуальный план —
[PROJECT_STATUS](PROJECT_STATUS.md). Проверки и подписанный build53 указаны ниже.

`SafLibrary.state` больше не содержит полный список `Track`: только папки,
число записей каждой папки, готовность, сканирование и ошибки. Метаданные
запрашиваются по ID или порциями из SQLite. Старый синхронный `tracks()`
для SAF намеренно запрещён, чтобы скрытая зависимость от полного снимка
не возвращалась. Папки в UI показывают счётчики, полученные при индексации.

Ручной запуск читает только переданные ID. Добавление читает выбранный ID;
восстановление и обновление недоступных ссылок читают ID сохранённого списка.
Когда пользователь редактирует автоматический порядок всей медиатеки,
плеер сначала получает порядок ID с учётом источника, включая недоступные
ссылки. Полный снимок библиотеки для этого не используется. Разрешённые
метаданные этого ручного списка пока остаются в `logicalQueue`; их сокращение
до соседних записей — следующий шаг, а не выполненная часть этого отчёта.

Команды во время чтения метаданных сохраняют порядок. При выходе из аккаунта
во время такого чтения изменение аккаунта обрабатывается после чтения:
онлайн-треки удаляются, локальные ссылки сохраняются. То же правило повторной
обработки применяется к изменению каталога во время чтения.

## Индексация папок

Каждая папка полностью обходится перед заменой её записей одной транзакцией.
Предыдущие метаданные файла читаются адресно для проверки размера, даты и
обложки. Во время обхода временно существует результат одной папки; постоянного
снимка всех папок нет. Повторный ID в ответе SAF учитывается один раз.

При ошибке обхода прежние строки папки остаются в SQLite как недоступные.
Даже новая папка с неуспешным первым обходом сохраняется для следующего
обновления. Удаление папки из медиатеки удаляет только её строки и разрешение
приложения; остальные папки и исходные аудиофайлы не затрагиваются.
Структура SQLite v2 и идентификаторы файлов не меняются; старый JSON импортируется
при первом создании индекса. Изменение не затрагивает пакет и данные 1.x.

## Соответствие reference

`LocalPlaylistStore.LocalPlaylist.toJson/fromJson` 1.x сохраняет порядок треков
в JSON. В 2.x сохранены порядок явного списка и ссылки на исходные файлы,
но загрузка сведений отделена в адресные запросы. SQLite-каталог и изоляция
профилей — архитектура 2.x; этот отчёт не приписывает их 1.x.

## Проверки и найденные ошибки

- Первый общий прогон остановлен после обнаружения зависимости тестового
  `OnlineHarness` от удалённого снимка: 42 исполненных сценария, 13 ошибок
  ([XML](qa/m11-10/interrupted-first-android15.xml)). Это не успешная проверка.
  Debug-провайдер теперь читает две WAV-записи адресной страницей. Ожидания
  редактирования в тестах учитывают асинхронное чтение диска.
- Следующий прогон: 65 сценариев, одна ошибка
  ([XML](qa/m11-10/before-account-fix-android15.xml)). Выход из Яндекса во время
  локального чтения терял уведомление; добавлена отложенная обработка изменения.
- После исправления прошли 8 целевых сценариев, включая онлайн-аудио,
  выход из аккаунта, ручной порядок и независимые папки
  ([XML](qa/m11-10/scale-account-roots-android15.xml)).
- В этом же прогоне выполнен реальный SAF-обход **5 002 документов**;
  первый обход занял **81 899 мс** на Android 15
  ([время](qa/m11-10/first-scale-scan-time.txt)). Проверены дальняя выборка
  с позиции 4500, страница очереди на 80 строк, компактный checkpoint,
  shuffle/repeat и восстановление на паузе. Документы используют два созданных
  WAV-файла; это проверка объёма каталога и адресного доступа, а не сравнение
  производительности реального USB с разными форматами аудио.

Расширенный прогон: 83 сценария, из них 81 прошёл, один условно пропущен
(`BootCheckpointTest` требует отдельного запуска с перезагрузкой), один завершился
ошибкой теста ([XML](qa/m11-10/expanded-before-harness-fix-android15.xml)).
`LargeCatalogTest` оставлял MediaBrowser подключённым перед остановкой службы,
поэтому служба корректно продолжала существовать. После освобождения подключения
этот сценарий прошёл отдельно без ошибок и пропусков
([XML](qa/m11-10/scale-final-android15.xml)). Проверены размер списка Media3,
дальний выбор, поиск и восстановление после остановки службы на каталоге из
5 002 записей. Остальные 81 сценарий охватывают локальное/онлайн/офлайн-аудио,
волну, системный браузер, качество, клипы, облачные плейлисты и интерфейс.
`core:test` и `app:lintDebug` прошли в расширенном прогоне. Ошибка тестового
подключения не потребовала изменения приложения.

Отдельно выполнены seed и verify с полной перезагрузкой эмулятора Android 15:
[до перезагрузки](qa/m11-10/boot-recovery/seed.txt),
[после](qa/m11-10/boot-recovery/verify.txt). Профиль, текущая ссылка и позиция
не менее 9 секунд сохранились; воспроизведение восстановилось на паузе.

M11 остаётся открытым: ручные списки ещё держат все разрешённые метаданные
выбранного порядка; требуется объединение каталога с Яндексом. Физические
K4811/HyperOS и аппаратная скорость USB этим отчётом не подтверждаются.

4 738 314 байт, SHA-256 —
`ef9e2d749b7a3f52ae7e88c9e422f363d84f729c3052f3f55989210393362423`.

На Android 15 выполнена установка поверх build52 через `adb install -r`:
[до](qa/m11-10/before-build53-package.txt),
[после](qa/m11-10/after-build53-package.txt). SAF-каталог и текущий второй
тестовый WAV с позицией 3 секунды на паузе сохранились. Подписанный APK прошёл
реальное фоновое WAV-аудио, системные Pause/Play/Next и холодное восстановление
на паузе: [результат](qa/m11-10/release-playback/release-playback.json),
[AudioFlinger](qa/m11-10/release-playback/audioflinger.txt). Это проверка
обновления пакета; пользовательский интерфейс updater здесь повторно не проверялся.
M11 и стабильный 2.0.0 этим выпуском не закрываются.

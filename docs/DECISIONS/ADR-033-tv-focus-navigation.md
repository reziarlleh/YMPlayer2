# ADR-033 — вертикальная навигация и строки выбора на TV

2026-10-04: реализация геометрии через `View.getFocusedRect` оказалась
реентерабельной. Она заменена чтением координат из событий фокуса;
см. [ADR-039](../ADR_039_CHOICE_ROW_FOCUS.md). Поведение пульта сохраняется.
Ниже — историческое решение build66, а не описание текущего вызова API.

2026-10-01. Принято для patch 2.1.2 по двум дефектам, найденным владельцем.

## Контекст

Material3 Slider использует все четыре стрелки для изменения значения. Для
плеера это ловушка: из прогрессбара нельзя выйти ↑/↓. Стандартный дробный шаг
в 1% также округляется до нуля при переводе в целые секунды короткого трека.

Широкая горизонтальная строка имеет собственную область поиска фокуса.
Расстояние до её центра по горизонтали может перевесить близость строки по
вертикали. Поиск тогда выбирает следующую кнопку, пропуская всю строку.
Воспроизведено на TV29 и подтверждено диагностикой focusSearch; выбранные
FilterChip не отключены и принимают прямой фокус.

## Решение

- `horizontalSliderNavigation` перехватывает четыре стрелки перед Slider.
  ↑/↓ вызывают вертикальное перемещение фокуса; ←/→ выполняют один шаг seek.
  Обрабатывается KeyDown, KeyUp поглощается без повторного действия. Даже при
  отсутствии соседнего элемента вертикальная стрелка не меняет позицию.
- Шаг перемотки сохраняет масштаб 1% длительности, минимум одна секунда,
  с ограничением диапазона. Сенсорное перемещение Slider не меняется.
- `ChoiceRow` в designsystem задаёт вход вертикального фокуса через выбранный
  пункт. Для строки область поиска проецируется на колонку входящего фокуса;
  это устраняет смещение к далёкому центру всей строки. Используются публичные
  `View.getFocusedRect`, `FocusProperties.focusRect`, `FocusRequester` и
  `LayoutCoordinates`, без внутренних API Compose и глобального перехвата.
- Стрелки не активируют пункты. Выбор меняется только нажатием. ←/→ внутри
  строки работают стандартно. Для ряда независимых фильтров приоритет имеет
  включённый фильтр, при отсутствии выбранного — первый.
- Общий компонент используется для источников, категорий/фильтров каталога,
  коллекций/поиска Яндекса и разделов карточки исполнителя.

## Проверки и отвергнутые подходы

Одного focusGroup оказалось недостаточно: центр группы остаётся далёким.
Принудительный canFocus и замена FilterChip на обычную clickable Surface
не исправили геометрию; эти попытки удалены. Глобальный перехват ↑/↓ на всех
prismFocus тоже не помог и не оставлен, в том числе чтобы не вмешиваться
в редактирование текста. Временная диагностика внутренних API удалена из тестов.

В native-проверках сначала используется реальное событие D-pad для выхода
Android из touch mode. Отдельно проверяются оба направления входа, пункты
в начале/конце широкой строки, горизонтальный переход, неизменность выбранного
раздела/фильтра и паузы. [Результаты](../PATCH_2_1_2_VERIFICATION.md).

Локализация 2.2 остаётся отдельной приостановленной задачей. Core, provider,
воспроизведение/предзагрузка и репозиторий 1.x этим решением не меняются.

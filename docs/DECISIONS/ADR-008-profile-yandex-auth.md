# ADR-008 — вход в Яндекс внутри профиля

2026-09-10. M4. Владелец уточнил: вход должен работать как в 1.x, при полностью
самостоятельном получении и хранении токенов 2.x. Отдельная регистрация OAuth
для этого этапа не требуется.

## Протокол и границы

Перенесён сценарий `YandexMusicClient.requestDeviceCode`, `pollDeviceToken` и
`getAccountStatus`, проверенный через RepoWise и актуальный исходник 1.x.
Это вход по коду через OAuth-клиент «Яндекс.Музыка». Публичные сведения клиента
проверены в Яндекс OAuth; среди его прав есть `music:read`, `music:write`,
`music:content`. Эта регистрация не является аккаунтом пользователя YMPlayer.

Клиентская конфигурация хранится локально в `.provider/yandex.properties` и
включается в выдаваемый APK при сборке. Она не содержит пользовательского токена,
не читается из приложения 1.x и не требует его установки. Никакого общего
файла авторизации или обращения к данным 1.x нет. Конфигурация исключена из Git.
Значения, включённые в APK, нельзя считать секретами, защищёнными от извлечения.

`:provider:yandex` содержит HTTPS-транспорт, DTO-разбор и Android Keystore store;
`:core` — контракт и машину состояния; shell — экран аккаунта и действия пользователя.
Вызовы выполняются только после явного «Получить код входа». Гость не авторизуется.
Ни вход, ни выход не запускают музыку и не изменяют локальные плейлисты/очередь.

## Идентичность и сохранение

OAuth-токен выдаётся клиенту для аккаунта пользователя. Пара `device_id`/`device_name`
дополнительно обозначает устройство. В 2.x новый UUID создаётся отдельно для
каждого локального профиля и сохраняется между входами. UUID и токены 1.x не используются.

Каждый профиль имеет отдельный шифрованный файл и ключ AES-GCM в Android Keystore;
profile ID включён в authenticated data. Файлы находятся в `noBackupFilesDir`,
backup приложения отключён. При недоступном ключе нет перехода к открытому хранению.
Токены не попадают в UI state, Bundle, сообщения ошибок и диагностические строки.

Смена профиля и отмена прекращают ожидание; поколение операции отбрасывает поздние
ответы. Если отмена произошла во время атомарной записи, новое состояние откатывается.
Выход завершает удаление именно выбранного профиля даже при переключении в процессе.
Выход удаляет локальную сессию; отзыв разрешения у Яндекса — отдельная операция,
в этой части не выполняется и не объявляется выполненной.

## Интерфейс и ошибки

Код показывается до открытия браузера вместе с предложением записать его:
на странице Яндекса вставка из буфера доступна не всегда. Переход выполняется
только отдельной кнопкой «Открыть Яндекс».

Профили → Яндекс выбранного профиля. «Назад» с экрана аккаунта отменяет незаконченный
вход и возвращает к профилям. Открытие браузера и пересоздание Activity сохраняют
ожидание: пользователь должен успеть подтвердить код. После завершения процесса
незавершённый код не восстанавливается; сохранённая сессия читается отдельно.

Учитываются серверные interval/expires_in, pending, slow_down, отказ, ошибка сети,
невалидная конфигурация и отказ хранения. В build7 аккаунт Музыки ошибочно проверялся
перед сохранением токена; [ADR-009](ADR-009-auth-legacy-parity.md) исправляет порядок
по 1.x: сначала сохранить OAuth, затем отдельно получить сведения Музыки.
Адрес страницы кода допускает только известные HTTPS-страницы
Яндекс OAuth; HTTP-перенаправления отключены, TLS-проверки стандартные.
Живой ответ `/device/code` 2026-09-11 вернул `https://ya.ru/device`:
этот точный адрес добавлен к двум адресам `oauth.yandex.ru`/`oauth.yandex.com`.
Произвольные поддомены и другие пути не допускаются.

Клиент без настройки OAuth сообщает о недоступности входа в этой сборке и сохраняет
локальный режим. Срок сохранённого токена учитывается; автоматическое обновление
токенов и обработка ответов музыкального каталога будут связаны с M5.

## Основания

- [Код устройства и обмен на токен](https://www.yandex.ru/dev/id/doc/ru/codes/screen-code-oauth).
- [Регистрация OAuth-клиента](https://yandex.ru/dev/id/doc/ru/register-client).
- [Android Keystore](https://developer.android.com/privacy-and-security/keystore).

Реальный успешный вход требует подтверждения владельцем аккаунта; тестовый
сервер/адаптер не является доказательством получения живого токена.

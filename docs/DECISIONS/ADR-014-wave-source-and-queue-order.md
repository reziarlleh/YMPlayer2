# ADR-014: источник «Волна» сохраняется после Stop

Дата: 2026-09-14. Уточнение владельца: повтор и рандом нужны для обычных
списков, но не для волны. Компоновка build14 принята, перестраивать её не требуется.

## Ошибка и reference

В build14 `AndroidPlayback.stop()` вызывал `cancelWave()`: отменял работу,
стирал session/cursor/batches и `wave`, оставляя треки последней порции.
Интерфейс затем отображал ручные режимы для этой конечной очереди.
`sessionPlayer` также передавал repeat/shuffle непосредственно в ExoPlayer,
обходя запрет команд `AndroidPlayback`.

Reference: `D:/_codex/YaPlay`, commit `7d118b4e3ec817b706748ae8d129fdc00f3a0146`,
`YmpPlaybackService.stopPlayback()` не сбрасывает `waveMode`/источник;
`toggleShuffle()` при `waveMode` сохраняет порядок и выключает shuffle.
Режим источника не равен признаку «сейчас звучит».

## Правило отображения и действия

| Текущая очередь | Рандом / повтор |
| --- | --- |
| Волна играет, приостановлена, остановлена, ждёт сеть либо восстановлена | Скрыты, команды не применяются |
| Обычный плейлист, альбом, избранное, выбранные треки local/USB/Яндекс | Доступны |
| Конечный рекомендованный плейлист | Доступны: это список, а не радио-сессия |
| Пустая очередь или ещё не подключённый playback | Скрыты |

Наличие кнопки запуска «Моя волна» и происхождение отдельного трека из Яндекса
не определяют режим. Явный выбор обычного списка/источника либо ручное изменение
очереди завершает волну; Stop/Pause и перезапуск сервиса её не превращают в список.

`PlaybackState.supportsQueueOrdering` задаёт доступность ручных режимов для UI
и системного player facade. Сами системные setters направляются в тот же
контроллер, где действует запрет для волны, даже если внешний клиент сохранил
старый набор доступных команд.

## Stop и продолжение

Остановка отменяет сетевые задачи, инвалидирует их поколения, сбрасывает
намерение Play и очищает временное аудио. Источник, session/cursor/batch ID и
метаданные текущего/следующего трека сохраняются. В движке остаются только
допустимые для повторной подготовки элементы; следующий полный файл снова
готовится после явного Play. Поздний ответ не возобновляет музыку.

Stop до первого ответа также сохраняет волну. Play доступен и в этом состоянии;
восстановление пустой ещё не начавшейся сессии использует start, а не next.
Checkpoint не содержит токенов или временных stream URL.

Проверки и выпуск: [M6.4](../M6_4_VERIFICATION.md).

# ADR-010: онлайн-каталог и отложенное получение ссылки на аудио

2026-09-11 · M5. Продолжение разрешено владельцем после успешного входа build8.

## Решение

`OnlineMusic` в core управляет поиском, страницами, деталями и безопасным состоянием
экрана. `YandexMusicApi` в provider:yandex переносит чтение каталога и получение
аудиоссылки из рабочего `YandexMusicClient` 1.x, reference commit `7d118b4`:
`search`, `getAlbumTracks`, `getArtistTracks`, `getPlaylists`, `getPlaylistTracks`,
`getLikedTrackKeys`, `getTracks`, `getDirectUrl`, `buildDirectLink`.

Поиск расширен с первой страницы `type=all` на отдельные типы `track`, `album`,
`artist`, `playlist` и явную загрузку следующих страниц. Коллекция M5 — чтение
«Мне нравится» и плейлистов аккаунта. Для альбомов и исполнителей доступны поиск
и детали. Создание/редактирование облачных списков, лайки, волна и офлайн-синхронизация
не входят в этот инкремент; F10 перенесён частично, F11/F25 не объявляются готовыми.

## Изоляция аккаунтов

- UI получает модели без credentials. `AccountAuth.withSession` читает сессию под
  тем же mutex, что вход/выход, и проверяет профиль и поколение до и после запроса.
- Новый запрос отменяет прежний; номер операции отбрасывает поздний ответ даже
  от транспорта, который не выполнил отмену. Смена профиля/выход очищают экран
  и временный онлайн-каталог. Отдельное обновление имени аккаунта не сбрасывает поиск.
- Восстановление очереди выполняется до реакции на новый профиль. `Main.immediate`
  может вызвать подписчика прямо внутри записи StateFlow: промежуточное состояние
  нельзя сохранять под именем нового профиля.
- При выходе удаляются онлайн-ссылки из очереди активного профиля; локальные треки
  сохраняются. Смена профиля сохраняет его отдельный checkpoint и оставляет новый на паузе.

## Аудио и хранение

Очередь содержит метаданные и постоянный ID `yandex:<track>:<album>`. В Media3
передаётся внутренняя ссылка с профилем и ID. `ResolvingDataSource` получает временный
HTTPS URL непосредственно на потоке загрузки Media3. Восстановление и новая попытка
чтения запрашивают ссылку снова. OAuth отправляется только на `api.music.yandex.net`;
XML сервера хранения и само аудио запрашиваются без OAuth.

Перенесены заголовки 1.x, connect/read timeout 15/20 секунд, download-info, выбор
полного MP3 с максимальным доступным bitrate и подпись ссылки из XML. Превью
не выдаётся за полный трек. Не добавлены отдельная загрузка всей очереди,
постоянный аудиокэш или токен в URI/SharedPreferences очереди.

Дополнительный кэш метаданных ограничен 4000 треками в памяти. Видимые результаты
и открытая очередь сохраняют собственные метаданные, поэтому их первые строки
не теряют возможность запуска после вытеснения из кэша. Список ID
избранного/плейлиста может приходить целиком по API 1.x, но дополнительные метаданные
запрашиваются только для текущих 50 ссылок. Порядок смешанных встроенных треков и
ссылок восстанавливается по исходным строкам; ответ `/tracks` не задаёт порядок.
Изменение коллекции на сервере между страницами может изменить её состав;
синхронизация ревизий относится к следующему этапу коллекций.

Обложки загружаются без credentials и постоянного дискового кэша, с пределом 2 MiB
на ответ и уменьшением изображения. Общий кэш bitmap остаётся 4 MiB. При недоступной
обложке используется иллюстрация скина. XML с DTD/entities и посторонние URL отклоняются;
проверка TLS сохраняется. Ошибки HTTP классифицируются до разбора JSON/HTML.

## UI и проверка

В поиске и медиатеке есть переключатель «Устройство / USB» / «Яндекс Музыка».
Детали возвращаются к родительским результатам через «Назад». Поиск, страницы
и навигация не меняют аудио; запуск показанных треков и добавление в очередь —
явные действия. После ошибки повтор Play должен заново подготовить источник,
даже если Media3 сохранил `playWhenReady=true`.

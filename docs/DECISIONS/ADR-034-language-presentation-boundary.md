# ADR-034 — язык как отдельный слой представления

Принято 2026-10-02 для первой beta 2.2.0. База — stable 2.1.5-build69,
HEAD `00e624e`. Прежняя `codex/2.2.0-localization-wip` не сливается в проект.
Её каталог английских формулировок используется только как справочник;
подключение текстов выполнено заново на актуальных исходниках.

## Решение

Android-модуль localization содержит полный English в `values`, Russian
в `values-ru`, каталог ключей и список готовых языков. Это стандартное разделение
кода и ресурсов [Android](https://developer.android.com/guide/topics/resources/localization).
Неподдерживаемая системная локаль получает English. Auto первый и по умолчанию;
готовые языки упорядочены по английскому названию, подписаны также на своём языке.

AppLanguages сохраняет выбор в отдельных общих для устройства preferences.
UiStrings переключает Resources через Configuration в своём контексте.
Наблюдаемое состояние обновляет Compose-текст; native-клипы, синхронизация
и сайдбар наблюдают изменение языка отдельно. Activity, очередь, профиль,
проигрыватель и открытый раздел не пересоздаются по команде выбора языка.
Auto обновляется при системном изменении конфигурации.

Новые вызовы UI используют ключ Msg и отдельные параметры. Параметры непрозрачны:
названия треков, исполнителей, альбомов, плейлистов и скинов не переводятся.
Приложение не переписывает метаданные или файлы при переключении языка.
Встроенные имена профилей локализуются только при совпадении ID и исходной
подписи; произвольное имя профиля сохраняется.

Core остаётся JVM-модулем без Android/Compose. Его существующие строковые
сообщения и enum labels переводятся на границе отображения. Адаптер принимает
только app-owned статусы/ошибки, никогда не произвольный заголовок музыки.
Известные обёртки ошибок волны, повтора и неподтверждённого редактирования
обрабатываются отдельно. Английские алиасы помогают перерисовать ранее
показанный статус при возврате к Russian; неоднозначный короткий алиас не угадывается.
Фикстуры старых русскоязычных тестов используют отдельный language preference.

## Проверка и последствия

Список пакетов и генератор проверяют наличие каждой строки, уникальные ключи,
сохранение параметров и множественные формы счётчика треков. Ресурсы и ключи
закоммичены; Python нужен для изменения каталогов, но не для обычной Gradle-сборки.
Для нового языка нужны полный пакет и запись в languages.json, затем native-проверки.
Пользовательские языковые пакеты и перезапись переводов на устройстве не вводятся.

API, авторизация, протоколы, кэш, алгоритмы аудио/видео, ключи пользовательских
данных и сборки 1.x не меняются. В shell сохраняются общий заголовок,
«О приложении», раздельные offline/offline_settings и правила пульта build66.
Приёмка формулировок владельцем следует за публикацией первой beta.

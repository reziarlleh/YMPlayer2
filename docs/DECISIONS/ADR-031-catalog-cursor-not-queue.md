# ADR-031 — каталог не является очередью воспроизведения

Дата: 2026-09-28. Область: M11/F04–F06/F16. Уточнение владельца после
[ADR-030](ADR-030-local-engine-window.md): для запуска музыки не нужен полный список
метаданных всех треков.

## Решение

- SQLite-индекс служит поиску, группам, фильтрам и экранным страницам. Его
  наличие не означает, что весь каталог надо копировать в очередь плеера.
- Сохранённый локальный плейлист — упорядоченный список ID. Для воспроизведения
  разрешаются текущий ID и ближайшие элементы; оригиналы файлов не копируются.
- При запуске из всей локальной медиатеки состояние воспроизведения хранит
  текущий ID, фильтр источника и режим. Следующий/предыдущий доступный трек
  определяется индексным запросом. Для shuffle нужен ограниченный журнал
  пройденных ID и выбор ещё не сыгранных; не список полных `Track`.
- «Моя волна» остаётся отдельной сессией рекомендаций Яндекса. Следующий трек
  определяется ответом сервиса, а аудио для него готовится параллельно
  воспроизведению текущего. Её нельзя смешивать с локальным курсором.
- Ручная очередь и пользовательский плейлист сохраняют явный порядок ID и
  операции редактирования. Это небольшой список ссылок, а не копия каталога.

## Состояние реализации

Экран автоматической локальной очереди теперь получает страницу напрямую из
SQLite без промежуточной полной копии ID. Индекс умеет запросить один соседний
доступный трек. Но `SafLibrary.state.tracks`, `AndroidPlayback.logicalQueue` и
`PlaybackState.queue` пока держат полные метаданные автоматической очереди;
плеер ещё не использует новый курсор. ADR-030 описывает поведение выпущенного
build47; его полная логическая очередь должна быть заменена при переносе на
этот контракт. До этого M11 нельзя считать законченным.

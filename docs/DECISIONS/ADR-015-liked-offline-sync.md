# ADR-015: офлайн-коллекция только из треков «Мне нравится»

Дата: 2026-09-19. По разрешению владельца продолжается M7 после build15.
Первая законченная часть M7.1 — постоянные аудио/обложки, ручная синхронизация
и офлайн-воспроизведение. Отдельные настройки качества (F09) и изменения облачных
плейлистов (остаток F10) остаются следующими частями M7.

## Источник поведения

Reference: `D:/_codex/YaPlay`, commit `7d118b4e3ec817b706748ae8d129fdc00f3a0146`.
Прочитаны README, PROJECT_AUDIT, CHANGELOG beta.12 и актуальные методы/тесты.

| Вход / действие | Работающий метод 1.x | Перенос в 2.x / выход и ошибки |
| --- | --- | --- |
| Полный список liked tracks | `YmpRepository.syncFavoriteCache`, `getLikedTracks` | `YandexLikedMusicApi`: один полный снимок ID и метаданные порциями; пропавшие метаданные не означают снятый лайк |
| Синхронизация одного трека | `YandexTrackCache.cacheLiked` | `LikedFileStore.sync`: независимые аудио и обложка; исправная часть сохраняется при сбое другой |
| Проверка существующих файлов | `CacheFileIntegrity.check/remember` | SHA-256 отдельно от метаданных; без checksum — разбор аудио/изображения, затем запись checksum |
| Проверка аудио | `CachedMediaValidator.audio` | Настоящие пакеты MediaExtractor, порядок времени, длительность с допуском 2–5 с; заголовок сам по себе не доказывает целый трек |
| Проверка обложки | `syncLikedArtwork`, `CachedMediaValidator.artwork` | Настоящее изображение, отказ от частично декодированного; отсутствие у источника отдельно от ошибки; логотип никогда не записывается в кэш |
| Публикация файла | `CacheFileIntegrity.replace` | Временный файл в том же каталоге, проверка длины/содержимого, атомарное переименование |
| Снятие лайка | `removeLike/dislike`, `removeLikedTrack` | Подтверждённая коллекция удаляет аудио, обложку, метаданные и checksum |
| Фоновая ручная синхронизация | `CacheSyncService` | Отдельный dataSync foreground service; прогресс/остановка, Wi-Fi по умолчанию; перезапуск процесса не возобновляет загрузку автоматически |

В 1.x проход синхронизации использует исходный список. Повторная итоговая сверка
с сервером, запрет поздней публикации после unlike и изоляция пары профиль/аккаунт —
дополнительные гарантии 2.x. Они не выдаются за уже существовавшие методы 1.x.

## Модули и ограничения

- `core/OfflineMusic` владеет состоянием, поколениями операций, отменой,
  подтверждённым списком лайков и сверкой результата. UI видит только эти контракты.
- `provider:yandex/YandexLikedMusicApi` получает только likes/tracks. Любимые
  исполнители и альбомы не раскрываются в треки для синхронизации.
- Новый `library:offline/LikedFileStore` владеет только своими файлами в filesDir.
  Каталог определяется хэшем **profileId + accountId**, имя трека — хэшем его ID.
  Токены и временные подписанные URL туда не записываются. Никакого импорта из 1.x.
- `playback:android` сначала открывает проверенный офлайн-файл активного аккаунта,
  затем обычный поток. Без сети работает сохранённый вход; после явного выхода
  файлы аккаунта недоступны, повторный вход в тот же аккаунт может использовать их.
- Очистка офлайн-файлов не снимает лайки на сервере. Готовые файлы сохраняются
  при отмене, ошибке сети и завершении процесса; повторный запуск ремонтирует недостающее.
- Одновременно загружается один файл; предел 128 МиБ на аудио и 8 МиБ на обложку,
  проверяется свободное место. Качество пока соответствует рабочему AUTO из M5.1.
- Сервис следует текущим требованиям Android к
  [типу dataSync](https://developer.android.com/develop/background-work/services/fgs/service-types#data-sync)
  и [тайм-аутам](https://developer.android.com/develop/background-work/services/fgs/timeout).
  Истечение системного времени останавливает работу и сохраняет готовое; загрузка
  не запускается из boot receiver. При запрете уведомлений управление остаётся в приложении.

Реальное персональное API и физический HyperOS проверяются отдельно от fixture-тестов.
Новый код не меняет протокол получения аудиоссылки 1.x/M5.1 или правила очереди волны M6.4.

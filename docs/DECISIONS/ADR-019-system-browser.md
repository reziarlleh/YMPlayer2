# ADR-019: системный браузер двух источников

Дата: 2026-09-24. Первый законченный шаг M8 (F20).

## Проверенный образец 1.x

`YmpPlaybackService` в `D:/_codex/YaPlay` (`7d118b4`) реализует platform
`MediaBrowserService`: корень `ymp_root`, два запускаемых элемента
`ymp_my_wave` и `ymp_liked_cache`. `onPlayFromMediaId` запускает соответственно
загрузку волны или очередь уже скачанных лайков. Просмотр дерева не запускает
воспроизведение. Дерево всех треков 1.x не публикует.

## Реализация 2.x

`AudioService` остаётся единственным владельцем ExoPlayer и foreground-уведомления,
но теперь предоставляет Media3 `MediaLibrarySession`. Манифест объявляет
MediaLibraryService и platform MediaBrowserService; прежний action
MediaSessionService сохранён для контроллеров, использовавших его раньше.
ID источников совпадают с 1.x, при этом оба приложения имеют отдельные package,
service, session и данные.

Корень и два элемента доступны для просмотра без чтения персональной коллекции.
Передаваемые браузером URI и метаданные игнорируются. Только два известных ID
превращаются во внутренний выбор источника; внешний клиент не может добавить
произвольный файл или сетевой адрес в очередь. Выбор сам по себе не запускает
музыку: Play вызывает уже существующий `AndroidPlayback.playMyWave()` либо
собирает очередь из готовых треков текущего профиля в `OfflineMusic`. Пустой
офлайн-кэш не возобновляет предыдущую локальную очередь. Остальные системные
Play/Pause/Stop/Next продолжают управлять той же сессией, что и интерфейс.

Media3 автоматически предоставляет совместимость с platform MediaBrowser;
это соответствует [официальному руководству Android](https://developer.android.com/media/media3/session/serve-content)
и [руководству по миграции](https://developer.android.com/media/media3/exoplayer/migration-guide).
Реальный CWG, физические кнопки и жизненный цикл автомобильного устройства
требуют отдельной аппаратной приёмки. Полное дерево медиатеки также не входит
в этот шаг.

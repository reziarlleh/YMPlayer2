# ADR-017: облачные операции плейлистов

Дата: 2026-09-20. M7.3 / F10 после build17.

## Рабочее поведение 1.x

Reference: `D:/_codex/YaPlay`, commit `7d118b4e3ec817b706748ae8d129fdc00f3a0146`.
Прочитаны `YandexMusicClient.createPlaylist`, `addTrackToPlaylist`,
`insertTrackDiff`, `deletePlaylist`, `getPlaylist`, `parsePlaylistSummary`,
`YmpRepository.createPlaylistAndAddTrack` и подтверждение удаления в MainActivity.
CHANGELOG 0.3.0/0.3.2/0.3.6 описывает создание, добавление текущего/найденного
трека и удаление списка. Переименование облачного списка, перестановка и
удаление отдельных облачных треков не входят в подтверждённый перенос этого этапа.

| Операция | Протокол 1.x | Перенос |
| --- | --- | --- |
| Создать | POST `/users/{uid}/playlists/create`, title, visibility=private | Приватный список; отдельное создание или создание с добавлением трека |
| Добавить | GET свежего списка; revision >= 1, at = trackCount; POST kind/revision/diff в change | Append одной пары id/albumId; change-relative как запасной путь |
| Удалить | POST `{kind}/delete`, запасной playlists/delete, form kind | Подтверждение в UI с названием и указанием удаления из аккаунта на всех устройствах |
| После успеха | Обновление медиатеки | Обновление полки/открытого списка; очередь и аудио сохраняются |

Старый fallback срабатывал при любом IOException. В 2.x он ограничен HTTP
404/405, когда основной путь отсутствует. Таймаут, 5xx, отказ доступа и конфликт
ревизии не повторяют запись через второй endpoint: сервер мог выполнить первый
запрос. Добавлен необязательный HTTP-код в MusicException, без сохранения
токена или сырого тела ответа. Удаление, как в 1.x, принимает пустой успешный
HTTP-ответ; явный JSON error не принимается за успех.

## Границы и жизненный цикл

`core/CloudPlaylists` управляет командами и диалогом, `CloudPlaylistApi` —
контракт, `provider:yandex/YandexPlaylistApi` — протокол. `app` связывает их
с AccountAuth и OnlineMusic. Новый Gradle-модуль не нужен; контроллер не знает
плеер, локальные коллекции и офлайн-хранилище.

Владелец операции — профиль и UID аккаунта. Перед каждым сетевым шагом
проверяется собственная сессия 2.x; после чтения и перед POST доступ проверяется
повторно. Смена профиля/выход отменяет команду и отбрасывает поздние результаты.
Отправленную на сервер запись отмена не может гарантированно отозвать.
UI блокирует повторное нажатие во время команды. Автоматического повтора записей нет.

Если создание прошло, а добавление не подтвердилось, сохраняются имя и ID
созданного списка. Повтор не создаёт его заново автоматически: пользователь
получает сообщение и обновляет списки перед следующим действием. При неизвестном
результате сетевой записи интерфейс предлагает проверить плейлисты в Яндексе.
Списки чужих владельцев и локальные файлы не допускаются к записи.

## Интерфейс

Создание — «Моя музыка в Яндексе → Мои плейлисты». Добавление найденного или
текущего трека — существующее меню «…». Удаление — карточка собственного списка.
Диалог прокручивается и использует PRISM/видимый D-pad фокус. Главная композиция
плеера, лайки и семантика волны не меняются. Закрытие во время запроса отключено,
чтобы Back не создавал ложного ожидания отмены уже отправленной записи.

Протокол проверяется по рабочим методам 1.x и тестовому транспорту. Изменения
личных облачных плейлистов не выполняются автоматически в ходе тестов.
Персональная серверная приёмка фиксируется отдельно от эмуляторов и фикстур.

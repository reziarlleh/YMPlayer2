# ADR-011: «Моя волна» и отдельные отметки трека, исполнителя и альбома

Дата: 2026-09-12. Принято по прямому уточнению владельца.

## Семантика

| Объект | Лайк | Удаление лайка | Дизлайк | Отмена дизлайка |
| --- | --- | --- | --- | --- |
| Трек | Добавить в «Мне нравится» | Удалить из этого списка | Никогда не предлагать этот трек | Снова разрешить рекомендации трека |
| Исполнитель | Добавить в «Любимые исполнители» | Удалить из этого списка | Никогда не предлагать этого исполнителя | Снова разрешить его рекомендации |
| Альбом | Добавить в «Любимые альбомы» | Удалить из этого списка | Не предусмотрен в этом этапе | Не предусмотрена |

Снятие лайка не является дизлайком; снятие запрета не ставит лайк.
В каждом запросе есть тип объекта и его ID. Исполнители совместного трека
представлены отдельными `ArtistRef`, без разбиения отображаемой строки имён.
Отметка трека не изменяет отметки его исполнителей или альбома.

**Будущий постоянный офлайн-кэш синхронизирует только треки из «Мне нравится».**
Лайк исполнителю/альбому не разворачивает дискографию/альбом в список загрузки.
Офлайн-кэш ещё не подключён. Потоковая очередь и предварительный запрос
следующей рекомендации не являются постоянной синхронизацией коллекции.

## Модули и перенос

- `core/MusicTaste`: три независимых списка, четыре явно названных действия,
  состояние загрузки/ошибки, сериализация изменений, изоляция профилей.
  После записи перечитывается действительное состояние сервера, также при
  частичном сбое составной операции. Непроверенная отметка не показывается как успешная.
- `provider/yandex/YandexTasteApi`: endpoint/form mapping. Треки перенесены из
  `YandexMusicClient.likeTrack/removeLikedTrack/dislikeTrack/removeDislikedTrack`
  1.x; совместимый fallback снятия отметки относится к тому же треку.
- `core/MyWave`: контракт batch/session/cursor/feedback, ограниченное восстановление
  сессии и проход мимо повторных, недоступных или запрещённых рекомендаций.
- `provider/yandex/YandexWaveApi`: JSON `rotor/session/new` из
  `getMyWaveFastStart/getMyWaveSessionFirstBatch`, `session/.../tracks` из
  `getMoreMyWave`, fallback `station/user:onyourwave/tracks`. Сохраняются
  `includeTracksInResponse`, `includeWaveModel`, `interactive`, первый новый
  ID как cursor и batch ID каждого трека. Ответы с вложенным `track` и
  псевдонимами `id/trackId/track_id/realId` сверены с разбором 1.x.
- `playback/android`: быстрый первый трек, следующая рекомендация в фоне,
  продолжение в Media3, запрет повторного запуска после паузы/смены профиля/
  ручной очереди, сохранение session/cursor/batches и метаданных без OAuth/URL.
  Восстановление остаётся на паузе. История активной очереди ограничена;
  история дедупликации — до 4000 ID в памяти.
- `feature/shell`: подписанные действия трека; отдельный диалог каждого
  исполнителя и альбома; отметки на страницах исполнителя/альбома; отдельные
  полки библиотеки. Векторы WAVE/BLOCK задаёт `designsystem`, без логики API.

В активной волне запрет трека удаляет его из предложенной очереди; запрет
исполнителя исключает все треки с его ID, включая совместные. Если запрещён
текущий трек, выбирается следующая допустимая рекомендация с сохранением намерения
Play/Pause. Явно выбранный пользователем поиск/обычный список остаётся доступным.
Содержимое рекомендованных плейлистов в интерфейсе также фильтруется по запретам.
Обычный Skip отправляет радио-feedback, но не создаёт постоянного дизлайка.

Радио-feedback `radioStarted/trackStarted/dislike` перенесён из
`YmpRepository.sendWave*`; `trackFinished/skip` добавлены с длительностью
прослушивания. Ошибка feedback не останавливает музыку. Серверные запреты
пишутся отдельно в dislikes — одного события радио для этого недостаточно.

## Источники расширений

Продолжение и предзагрузка M6 уточнены после реальной остановки после второго
трека: [ADR-012](ADR-012-wave-continuation.md) фиксирует найденные расхождения
и карту переноса методов 1.x; [M6.2](../M6_2_VERIFICATION.md) содержит проверку.

Рабочий reference 1.x: `D:/_codex/YaPlay`, commit `7d118b4e3ec8`;
исходники reference не изменяются. В 1.x нет отдельной реализации всех новых
полок и отметок альбома/исполнителя, поэтому эти части проверяются отдельно.

- [Первичный код клиента: likes/dislikes](https://github.com/MarshalX/yandex-music-api/blob/main/yandex_music/_client/likes.py):
  разные object types и form keys; треки возвращают revision, артисты/альбомы — ok.
- [Landing/feed](https://github.com/MarshalX/yandex-music-api/blob/main/yandex_music/_client/landing.py),
  [BlockEntity](https://github.com/MarshalX/yandex-music-api/blob/main/yandex_music/landing/block_entity.py),
  [GeneratedPlaylist](https://github.com/MarshalX/yandex-music-api/blob/main/yandex_music/feed/generated_playlist.py):
  персональные плейлисты извлекаются из вложенного `data.data`, обычные — `data`;
  резервный feed — `generatedPlaylists[].data`. Чужой константный user ID из
  стороннего клиента не используется: запрос идёт с текущей OAuth-сессией.
- [Радио-feedback](https://github.com/MarshalX/yandex-music-api/blob/main/yandex_music/_client/radio.py).

Размещение отметок в интерфейсе уточнено владельцем 2026-09-13:
у трека остаются его реакции, исполнители/альбом находятся в «…».
[ADR-013](ADR-013-fixed-player-and-artist-cards.md) заменяет компоновку M6.1,
сохраняя семантику и отдельные идентификаторы целей.

Это первичный код неофициального API-клиента, а не гарантия неизменности сервера
Яндекса. Проверки фикстур подтверждают совместимость с этими форматами;
персональная выдача и изменение реального аккаунта требуют отдельной приёмки.

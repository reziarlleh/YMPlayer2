# ADR-006 — локальные плейлисты и избранное по профилям

2026-09-10. M3.2 — развитие локального каталога 2.x, без обращения к Яндексу.

Reference 1.x проверен через RepoWise и исходный `LocalPlaylistStore.java`:
`rename`, `removeTrack`, `delete` изменяют только метаданные списка; локальное
избранное отделено от Яндекса. В 2.x сохраняем это поведение и добавляем разделение
по профилям, отдельный каталог и явную очередь вместо копирования legacy storage.

Плейлист — именованный упорядоченный набор уникальных ссылок на треки, избранное —
отдельный набор ссылок. У каждого локального профиля свои списки; каталог файлов
остаётся общим. Удаление плейлиста не снимает отметки избранного и не меняет очередь.

В `:core` находятся модели, контракт `UserCollections` и чистые переходы состояния.
В `:library:local` добавлен `LocalCollections`: один приватный `user-collections.json`
с версией схемы 1. Mutex последовательно применяет операции; AtomicFile сохраняет
новое состояние перед публикацией в StateFlow. Ошибка записи оставляет старые данные.
Неизвестная/повреждённая схема блокирует запись и предлагает повторное чтение.
UI передаёт идентификатор профиля, выбранного в момент действия, в каждую операцию.

Взаимное исключение обеспечивается самим хранилищем, поскольку AtomicFile не
предоставляет блокировку: [контракт Android AtomicFile](https://developer.android.com/reference/android/util/AtomicFile).

Хранятся ID и последние известные название, исполнитель, источник, длительность,
декоративный индекс. Аудио, обложки и URI для воспроизведения в этот файл не копируются.
При показе используются актуальные записи каталога; отсутствующая запись отображается
недоступной со старым названием. Отключение или исключение папки из индекса не очищает
плейлисты/избранное. Возврат того же SAF ID восстанавливает доступность. Переименование
самого файла или смена идентификатора документа не сопоставляются автоматически.

Изменения коллекций не вызывают команд плеера. Явное «Воспроизвести список» или выбор
его трека отправляет `playQueue(ids, startId)`; адаптер проверяет текущий каталог,
исключает недоступные/неизвестные ID и заменяет очередь одной операцией. Если доступных
треков нет, текущая очередь не меняется. Режимы repeat/shuffle профиля сохраняются.
Изменение исходного плейлиста после запуска не меняет уже начатую очередь.

Названия: после обрезки пробелов от 1 до 80 символов, без управляющих символов,
уникальные в пределах профиля без учёта регистра. ID плейлиста не зависит от названия.
Новые иконки используют существующий контракт оформления с запасными ресурсами PRISM.

Плейлисты доступны из разделов медиатеки, избранное — соседним пунктом. Меню трека
позволяет изменить избранное и добавить в существующий/новый плейлист. Экран плейлиста
поддерживает выбор треков, порядок, удаление элементов и явный запуск. Удаление всего
плейлиста требует подтверждения в интерфейсе; это не удаление музыкальных файлов.

Экспорт/импорт M3U, синхронизация Яндекса и локальное избранное как источник облачного
кэша в M3.2 не входят. Обложки и восстановление активной очереди после исчезновения
USB относятся к M3.3, полноценная облачная синхронизация — к этапам Яндекса.

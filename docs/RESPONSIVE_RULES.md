# Адаптивность и ввод

Статус: проектные правила для Android-прототипа, 2026-09-09.

Реализация M1 уточняет правила: rail с 600 dp, плеер + очередь с 960 dp при
высоте окна ≥500 dp. Детали каталога пока последовательные. Если высота области
контента <520 dp, окно короткое или fontScale >1.3, Play и транспорт размещаются
перед компактной обложкой. Фактически выполненная матрица — [M1_VERIFICATION.md](M1_VERIFICATION.md);
остальные значения ниже остаются расширенной целью, а не заявлением о проверке.

Размер определяется доступным окном после системных insets в dp; текст — в sp.
Физическое разрешение и название устройства не заменяют размеры окна.
Базовые границы согласованы с
[Android window size classes](https://developer.android.com/develop/ui/compose/layouts/adaptive/use-window-size-classes).

| Доступная ширина | Shell | Контент и плеер |
| --- | --- | --- |
| <600 dp, compact | Нижняя навигация | Одна колонка; очередь/детали отдельным маршрутом; мини-плеер над навигацией |
| 600–839 dp, medium | Компактный rail | Основной контент; две панели только если хватает ширины и высоты |
| 840–1199 dp, expanded | Rail | На главной плеер и очередь; в каталоге список и детали при достаточном месте |
| ≥1200 dp, large+ | Rail/расширенная навигация | Ограничить ширину контента; дополнительная панель вместо растяжения текста |

Отдельное правило короткого окна: при высоте <480 dp приоритет у названия,
транспорта и доступного списка. Уменьшить/убрать крупную обложку, свернуть очередь,
сократить вертикальные отступы. В landscape mini-player может стать компактной
боковой/нижней полосой. Третью панель не добавлять по одному признаку ширины.

## Поведение

- Portrait: вертикальная композиция; крупные панели открываются последовательно.
- Landscape: artwork и controls могут располагаться рядом; transport остаётся
  цельной группой. При дефиците места прятать второстепенные действия в меню.
- Начальные min-width: основной плеер 320 dp, очередь 280 dp; gap 16–24 dp.
  Окончательные значения уточнить измерением прототипа, а не фиксировать пиксельную сетку.
- Главные touch targets ≥48 dp, в автомобильной композиции транспорт 56–64 dp.
  При нехватке места менять компоновку, не сжимать targets.
- Длинное название: до двух строк на главной; в строках каталога ellipsis и
  доступный полный текст. Большой font scale увеличивает строки, а не обрезает controls.
- Статус/ошибка не изменяют ширину группы транспорта. Журнал прокручивается;
  при его открытии сохранить доступ к воспроизведению.
- Учитывать IME, cutout, системные панели и Back; insets не накапливаются после поворота.
- Состояние и scroll position сохраняются по route + profile; resize не создаёт
  новый источник/очередь и не запускает сетевой запрос без необходимости.

## TV и клавиатура

TV — отдельная политика ввода и дистанционного чтения, а не просто широкий
экран. Предусмотреть TV-компоненты, явный начальный фокус и восстановление фокуса
по ключу элемента. В библиотеках ленивых списков элемент не должен терять фокус
при загрузке следующей страницы. Упорядоченные группы транспорта не переносятся.
Основы выбора:
[Compose for TV](https://developer.android.com/training/tv/playback/compose?hl=en).

DPAD_UP/DOWN/LEFT/RIGHT и OK работают без тач-жестов. Back закрывает верхнюю
панель/клавиатуру, затем возвращает маршрут. Главный экран получает фокус на Play;
при возврате в каталог — на прежнюю строку. Не использовать scale-анимацию фокуса.

## Матрица приёмки прототипа

| Группа | Проверки |
| --- | --- |
| Размеры | 360×800, 412×915, 640×360, 800×480, 960×540 dp; широкое ≥1200 dp |
| Границы | 599/600, 839/840 dp по ширине; 479/480 dp по высоте |
| Текст | fontScale 1.0/1.3/2.0; длинный русский и латинский текст |
| Темы/плотность | Light/Dark; разные DPI при одинаковом доступном dp |
| Состояния | loading, data, empty, error, offline, USB unavailable, expired login |
| Ввод | Первый тап, мышь, клавиатура, настоящий TV DPAD/OK/Back |
| Жизненный цикл | Поворот, resize, фон/возврат, IME и cutout |

Числа здесь — тестовые размеры, не заявленные параметры K4811. Веб-макет
проверяет только свою компоновку. Android-прототип, TV-эмулятор и физический
K4811 дают отдельные уровни доказательств; установка на устройство требует
отдельного разрешения пользователя.

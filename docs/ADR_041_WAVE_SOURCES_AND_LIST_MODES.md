# ADR-041 — источники волн и режимы конечного списка

Принято 2026-10-06 по прямому уточнению владельца. Дополняет
[настройки волны](ADR_040_WAVE_SETTINGS.md); все изменения выпускаются одной ручной
beta2.4 поверх81. Stable/latest и auto feeds79 сохраняются.

## Источник

`PlaybackOrigin` содержит вид источника, заголовок и необязательный `WaveRequest`.
Это описание текущего списка, не дополнительная очередь. Его хранит checkpoint
профиля; при переключении списка/профиля не переиспользуется чужой источник.
Для ручного редактирования очереди описание исходного списка сбрасывается:
изменённая очередь может содержать музыку из нескольких источников.

- Трек: `track:<id>`; исполнитель: `artist:<id>`; альбом: `album:<id>`.
- Яндекс-плейлист: `playlist:<ownerUid>_<kind>`. Чужой плейлист использует его
  владельца, не UID текущего слушателя. «Мне нравится» — kind3 своего аккаунта.
- Источники без валидного идентификатора не заменяются общей волной.
  Локальные плейлисты/избранное и офлайн-кэш не имеют Яндекс-источника волны.
- Сессия, запрос следующего трека, feedback, retry и восстановление используют
  тот же seed. У них остаётся существующий короткий буфер previous/current/next.

Новые источники не реализованы готовым алгоритмом1.x: это расширение
контракта уже перенесённого rotor/session и preload. Формат track/artist/album
сверен с [первичным клиентом](https://github.com/MarshalX/yandex-music-api/blob/main/docs/source/radio.md).
Для playlist публичный HTTP `/rotor/station/playlist:103372440_2131/info`
6 октября вернул тот же type/tag; UUID того же публичного плейлиста дал400.
Проверка метаданных не выдаётся за персональную приёмку воспроизведения.

## Режимы

Повтор OFF/ALL/ONE остаётся отдельной кнопкой. Новая кнопка с иконкой волны
включает продолжение после конечного Яндекс-списка. Рандом, повтор списка/трека
и продолжение взаимно исключаются в общем контракте плеера, включая MediaSession.
Выключение одного режима не включает другой автоматически. В самой волне все
три скрыты и не могут включаться внешними командами.

Рандом бесконечно проходит элементы только выбранного списка; обёртывание
в начало работает без логического Repeat.ALL. В Media3 маленького дискового
окна переход на границе делает существующий индекс/порядок ссылок. Полная
метадата тысяч файлов не загружается. Для обычной Media3-очереди внутренний
REPEAT_ALL обеспечивает бесконечный shuffle, но UI/MediaSession сохраняют
логический repeat OFF. Это разные уровни управления, не два выбранных режима.

Продолжение запускается на естественном STATE_ENDED с playWhenReady, а не по
номеру элемента небольшого окна. Пауза/Stop не запускают радио. Источник и режим
сохраняются, восстановление остаётся на паузе. Ошибка радио допускает retry того
же источника. Неидентифицируемый результат поиска не объявляется плейлистом.
В конечном списке UI по-прежнему играет уже показанные/загруженные треки;
эта задача не меняет пагинацию каталога на скрытую загрузку всего удалённого списка.

## Интерфейс

У каждого Яндекс-объекта есть команда в дополнительном меню. В меню трека
команды трека, каждого исполнителя и альбома подписаны отдельно.
На главном экране общая кнопка показывает источник/название списка и открывает
выбор «Моя волна», «Оффлайн», «Локальное избранное». Плейлисты выбираются
в медиатеке. «…» справа сохраняет отдельный переход к настройкам волны.
«Любой/любое/любая» выводится первым, без изменения серверных seeds/подписей.

Проверки, границы и результат публикации — в
[отчёте этапа](WAVE_SOURCES_2_4_VERIFICATION.md).

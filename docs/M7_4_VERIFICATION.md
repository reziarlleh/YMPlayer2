# M7.4 — редактор облачных плейлистов

Дата: 2026-09-23. F11 по запросу владельца перед переходом к M8.

В карточке своего плейлиста добавлен редактор: переименование, удаление
конкретного вхождения и перемещение на выбранную позицию. Добавление через
«…», создание и удаление всего списка из M7.3 сохраняются.

Повторы трека не объединяются. Перед записью проверяются свежая revision
и порядок; после записи перечитывается результат. Ошибка требует обновления
списка, автоматического повтора изменений нет. Текущая очередь, лайки и
постоянный кэш сохраняются.

[Источники протокола, обработка ошибок и границы модулей](DECISIONS/ADR-018-cloud-playlist-editor.md).

Анонимное чтение [публичного плейлиста Яндекса](qa/m7-4/public-playlist-shape.json)
подтвердило 100 исходных позиций, вложенные сведения о треке и альбоме,
совпадение `trackCount` с длиной списка и допустимую `revision=0`. Этот ответ
не проверяет запись в собственный плейлист.

## Персональная приёмка

Транспортные тесты и native UI используют изолированные фикстуры без личных
токенов. Реальная серверная запись в аккаунт Яндекса и физический HyperOS
проверяются владельцем на итоговом APK.

Сценарий общей проверки: создать плейлист → добавить несколько треков через
«…» → переименовать → переместить первый трек в конец и обратно → добавить
повтор трека и удалить только одно его вхождение → проверить результат в Яндексе
после повторного открытия приложения → удалить тестовый плейлист.

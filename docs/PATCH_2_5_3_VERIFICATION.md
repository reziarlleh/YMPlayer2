# Патч стабильной линии 2.5.3 — темы, USB и история волны

Задача владельца 9 октября2026. Опубликован подписанный stable **2.5.3-build101**.
GitHub latest и оба stable feeds переведены на101.
Ручной APK beta99 и отдельный эксперимент не изменяются.

## Причины и изменения

- B-021 подтверждён исходниками: ShellApp начинал с dark, выбор темы жил
  только в rememberSaveable. Теперь ThemePreferences сохраняет режим сразу
  при выборе; system остаётся режимом, а цвета следуют конфигурации Android.
- B-022: существовал только OpenDocumentTree и обязательный persistable grant.
  Наличие DocumentsUI или разрешение другого файлового менеджера не даёт
  YMPlayer доступа к USB. Добавлен выбор смонтированной папки на API28/29,
  отдельное разрешение чтения и opt-out scoped storage на Android10.
  API30+ сохраняет SAF. Нет WRITE_EXTERNAL_STORAGE/MANAGE_EXTERNAL_STORAGE,
  обращения к приватным API или копирования музыки. Обход ограничен выбранной
  папкой, отменяемый; ссылки наружу исключены. Неполный обход сохраняет старый
  индекс недоступным вместо его стирания. Физическая прошивка пользователя
  недоступна: её причина и успешность обходного пути не объявляются доказанными.
- B-023: восстановление волны сохраняло лишь текущую короткую очередь, теряя
  дедупликацию старых треков. Теперь сохраняются до4000 ключей треков в текущем
  сеансе/профиле. Это история фильтра, а не огромная очередь и не кэш аудио.
  При ответе только со старыми/запрещёнными треками сначала продолжается обход
  сессии, сброс происходит при зацикливании курсора. Fallback-курсор ответа —
  последний полученный трек; выбранный новый трек остаётся рабочим курсором.
  В диагностике виден успех/ошибка feedback без токенов и данных аккаунта.
  Авторов подбирает сервер: однообразие2–3 исполнителей у конкретного аккаунта
  не воспроизведено и не выдаётся за устранённую настройку сервера.

Сопоставлены getMoreMyWave/getMyWaveFastStart/YmpRepository1.x:
первый трек сразу, следующий отдельно; queue/cursor, ограниченное восстановление,
station feedback. 1.x не изменялся. Настройки Любимое/Незнакомое/Популярное
не подменяются принудительной рандомизацией клиента.

## Исходные отказы проверок

Общая файловая фикстура сначала пыталась mkdir/write от имени read-only
приложения. На API28/29 это закономерно отказало: подготовку отделили от
проверки чтения и не добавляли WRITE в продукт. Следующая версия coroutine
теста вывела не-Unit return type; JUnit отказал в создании класса. Исправлена
сигнатура runBlocking<Unit>, окончательные7/7 на каждом API прошли.
Эти отказы сохранены в patch100-extra-* / patch100-final-*; успешный результат
отдельно в patch100-verified-*. Это не новые дефекты исполнения плеера.
Полные native-логи/API35 и XML/PNG подписанной проверки находятся в .local-build;
проверки профилей/позиций от прежних выпусков не приписаны101.

## Причины и исправление

1. PublicArtwork отправлял content:// в HTTPS-loader. Сохранённый PNG после
   переноса кэша читался через ContentResolver, но не отображался на экране.
   Теперь локальные file/content/android.resource читаются через ContentResolver.
2. Каждый обычный sync заново считал полный SHA аудио/обложек и записывал JSON
   всех треков. Быстрый catalog124 ускорял открытие, но не эту операцию.
   planSync теперь сверяет свежий bulk inventory, индекс и маркеры завершения.
   Готовые записи публикуются одним пакетом; новые аудиофайлы скачиваются раньше
   обновления метаданных/обложек старых записей. Автоматический лайк использует
   тот же incremental-путь.
3. URI недостаточно для повторного чтения восстановленной картинки: её размер,
   mtime и даже прежняя SHA могут совпасть. При каждой успешной записи обложки
   сохраняется новая ревизия; она входит в ключ UI-кэша. Декодирование локальных
   картинок ограничено по размеру, как и онлайн-картинок.

**Проверить и восстановить кэш** — отдельное явное действие с полным чтением
аудио/обложек, прогрессом и отменой через существующий OfflineSyncService.
Нужны аккаунт и сеть по прежней политике Wi-Fi: сначала запрашиваются свежие лайки.
Старые store.sync/load остаются строгими, выбранное аудио проходит прежний контроль.
Известное повреждение отмечается .invalid с сохранением ожидаемой SHA; успешное
восстановление снимает маркер. Отмена проверки не останавливает отдельный плеер.

Добавлены три сообщения во всех8 языках (739 сообщений, полные пакеты), обе
инструкции и карты функций. Инструкции явно отмечают отсутствие новой кнопки
в опубликованной124. Новых модулей/веток кода заранее не создавалось.

## Что может выглядеть как пропавшая обложка

| Случай | Поведение и действие |
| --- | --- |
| Валидный SAF-PNG после переноса папки | Подтверждённый B-045, исправлено чтение content:// |
| Ремонт файла по прежнему URI/size/mtime | Новая постоянная ревизия обновляет UI без перезапуска аудио |
| Файл картинки не был скачан/потерян | Обычная синхронизация докачивает его, сохраняя готовое аудио |
| Картинка повреждена, в том числе с прежним размером | Полная проверка обнаруживает и восстанавливает её |
| Яндекс не передал исходную картинку | Настоящее состояние «без обложки»; логотип не записывается вместо неё |
| USB отключён или отозван доступ к папке | Сначала восстановить доступ; при необходимости заново открыть экран |
| Очень большая локальная картинка | Ограничены входной объём и размер декодирования; native проверил также обычную file-обложку |

Возврат доступа к тому же URI без перезаписи файла отдельно не эмулировался.
Состояние ошибки загрузки живёт до смены ключа/повторного создания компонента;
это граница проверки, а не обещание автоматического восстановления любой USB-сессии.

## Границы и следующий шаг

Быстрая докачка — проверка наличия/завершённости, не новый аудит каждого байта.
Legacy-записи без ожидаемого размера используют маркеры завершения. Скрытое
изменение того же размера выявляют полный audit и проверка выбранного аудио,
с прежним ограниченным повторным использованием playback proof.
Первое перечисление носителя/legacy JSON без пригодного индекса остаётся O(N).
Часовой физический сценарий пользователя и скорость реальной сети/USB не измерены.
Приёмка владельца/физического устройства не заявляется. Клипы/радио,1.x и форум
не менялись. RepoWise context/doctor/update не завершились в ограниченном ожидании;
[receipt](qa/offline-sync265/repowise.json), свежесть индекса не заявляется,
актуальные исходники проверены напрямую.

## Архитектура APK и метод

Владелец предоставил ARM64 и x86 APK. У них **побайтно одинаковый classes.dex**:
SHA-256 `75e90937faaebf44f231225bf65700bf5e57fc8d94e321e91c92a2ba0f74baaf`.
Подписи обоих APK проверены; сертификат FMPLAY совпадает. Варианты различаются
нативным libffmpegJNI.so. Анализируемый код Android-метаданных идентичен:
x86 для этого сравнения не означает, что пользователь должен иметь x86-ГУ.

Исходный ARM64 APK не установился в AOSP x86_64 (NO_MATCHING_ABIS). Полученный
x86 установлен без перепаковки/изменения подписи. Подготовленный Google APIs35
образ после получения x86 для этой проверки не понадобился.

FMPLAY проигрывал публичные Серебряный Дождь и Lo-Fi Radio. YMPlayer проигрывал
синтетический Cover fixture с тегами и обложкой через обычный SAF picker.
SHA установленного YMPlayer совпал с релизным APK98. Яндекс-токен не использовался.
MediaSessionManager / MediaController читались внешним app_process-инструментом.
На API28 shell UID2000 не имеет нужного права чтения активных сессий; использован
**root UID0 только эмулятора**. Это привилегированный потребитель, не доказательство
доступа обычного приложения без разрешения.

## Подтверждённые различия

| Поле/поведение | FMPLAY | YMPlayer98 |
| --- | --- | --- |
| TITLE / ARTIST | песня / исполнитель, до ответа сервера — станция | название / исполнитель трека |
| ALBUM | название станции | альбом трека |
| DISPLAY_TITLE | дублирует TITLE | null |
| DISPLAY_SUBTITLE | дублирует ARTIST, если он известен | null |
| DISPLAY_DESCRIPTION | дублирует ALBUM, если он известен | null |
| ART bitmap | 600×600 | null |
| ALBUM_ART bitmap | null | 320×320 |
| DISPLAY_ICON bitmap | 336×336 | 320×320 |
| Artwork URI | не заполнены | три URI присутствуют |
| Framework getDescription | текст и bitmap есть | текст и bitmap есть |
| PLAYING | state3, speed1, actions52786 | state3, speed1, actions7340027 |
| PAUSED | state2, speed0, actions52788 | state2, speed0, actions7340029 |
| Session flags | 3 | 7, дополнительно queue-команды |
| Уведомление | MediaStyle, PUBLIC, transport, title/text/subText | MediaStyle, PUBLIC, transport, title/text; subText null |
| Длительность | -1 для эфира | 29999 мс для тестового трека |

Обычные TITLE/ARTIST и framework getDescription корректны у обоих приложений.
Различие duration/seek/queue для радио и конечного трека ожидаемо и не объявлено
дефектом. Это не сравнение обоих приложений на идентичном аудиопотоке.

Системные KEYCODE_MEDIA_PAUSE/PLAY работают у обоих. В YMPlayer дополнительно
проверен NEXT: Cover fixture → one. STOP FMPLAY оставляет станцию в состоянии
PAUSED и очищает сведения о песне; это его поведение, не универсальный контракт.
После HOME FMPLAY остаётся PLAYING с текстом/обложкой. Смена станции сначала
публикует Lo-Fi Radio, затем название песни/исполнителя; в двух снимках этого
прогона обновление наблюдалось через114 мс. Опрос100 мс не измеряет точное
время callback и не доказывает синхронную доставку первого bitmap.

В декомпилированной цепочке PlaybackService → i12/er.buildMetadata →
MediaSessionCompat → framework MediaSession.setMetadata используются стандартные
механизмы Android. В этом пути не найден API определённой марки машины или MCU.
В просмотренном коде не найдены metachanged/playstatechanged broadcasts.
RemoteControlClient присутствует в библиотеке, но выбран только при API<21;
на API28 применяется platform MediaSession. Не принимать наличие старого класса
в DEX за выполняемый на современном устройстве механизм.

JADX1.5.6 завершил общий разбор с36 ошибками отдельных методов. Поэтому вывод
о полях подкреплён runtime, а не только восстановленным Java. Чужой APK,
декомпилированный код и полный системный дамп в Git не добавлены.

## Что это означает для исправления

Если внешний получатель читает непосредственно DISPLAY_* и ART без стандартного
fallback, он получит данные от FMPLAY и пустые поля от YMPlayer. Это конкретный
проверенный кандидат для совместимости. Он пока **не доказывает**, какие именно
поля читает приборка и почему исчезает вся карточка.

Минимальный путь прототипа:

1. Для музыкальных треков явно заполнить displayTitle, subtitle и description
   существующего Media3 MediaMetadata. Проверить их появление в platform-сессии.
2. Отдельно обеспечить ART в той же системной сессии. В текущем
   [LegacyConversions1.11.0](https://github.com/androidx/media/blob/1.11.0/libraries/session/src/main/java/androidx/media3/session/LegacyConversions.java)
   bitmap экспортируется только в ALBUM_ART/DISPLAY_ICON. Одних новых display-полей
   или artworkUri для ART недостаточно. Не подменять это второй MediaSession
   или рефлексией в production; оценить ограниченную адаптацию конвертера.
3. Для Радио отдельно согласовать семантику: сейчас YMPlayer публикует станцию
   в TITLE, песню/исполнителя вместе в ARTIST. FMPLAY публикует песню в TITLE,
   исполнителя в ARTIST, станцию в ALBUM/display description. Изменение этого
   поведения требует проверки сохранения нужной информации для CWG.
4. Проверить полный/пустой набор тегов, начальную загрузку обложки, смену
   трека/станции, Pause/Play/Stop и фон. Конечное отображение на приборке
   подтвердить отдельно; Android-эмулятор его не заменяет.

Прототип и новый релиз в этом сравнении не создавались. Добавлять новые права
плееру, OEM-broadcasts или интеграцию Android Auto по данным проверки оснований нет.
Обычный непривилегированный внешний клиент и APK Я.Музыки ещё не сравнивались.

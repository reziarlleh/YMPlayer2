# Локальный и Яндекс-профили — уточнение2.8.0

14 ноября2026 владелец уточнил [состав2.8.0](PLAN_2_8_0.md).
Выполнение продолжается в том же цикле; Stable/Latest/feeds —2.7.0-build137.

## Поведение

- Чистая установка содержит только **Локальный** (`local`): музыка устройства,
  USB, свои локальные списки, история, очередь и настройки. Он не удаляется,
  не переименовывается и не получает вход Яндекса. Запрет действует в core,
  а не только через скрытие меню.
- При обращении из Локального к волне, Яндекс-каталогу/поиску, радио, клипам,
  аккаунту или привязанному офлайн-кэшу сначала показывается выбор профиля Яндекса.
  Если таких профилей нет, появляется предложение подключить аккаунт с отменой.
  Открытие/отмена предложения не создаёт профиль, не запускает OAuth и не меняет
  текущий раздел или локальную очередь. Подключение начинается только после
  явного подтверждения; выбор существующего профиля открывает его плеер на паузе.
- **Добавить профиль Яндекс** создаёт отдельную запись и открывает страницу
  авторизации без предварительного запроса имени. Пока сведений нет, подпись —
  **Яндекс**. Обычная авторизация по коду не меняется.
- Используется уже существующий ответ `account/status`: `displayName`, затем
  `login`; при отсутствии обоих — прежний технический fallback Яндекс ID.
  Новый OAuth scope или другой токен не нужны. Токен сохраняется до необязательной
  загрузки имени; сетевой отказ имени не отменяет вход.
- Имя автоматически сохраняется в списке, в том числе для неактивных профилей.
  Для прежних аккаунтов используются уже сохранённые сведения Keystore без сети.
  Явные пользовательские переименования сохраняются. Имена аккаунта не переводятся.
- Каждый профиль имеет свои язык, тему/скин, масштаб, аккаунт, списки и позицию.
  Выбор другого профиля восстанавливает его плеер **на паузе**. Профиль Яндекса
  также может слушать локальные файлы. Физические папки/разрешения остаются общими.

## Миграция и границы

`user-profiles.json` переходит со schema1 на schema2: явно хранится `userNamed`,
чтобы автоматически полученное имя после перезапуска не стало ручным псевдонимом.
Встроенный `local` добавляется первым. Прежние owner/road/guest/UUID сохраняют
ID, зашифрованные сессии, очереди, избранное и персональные настройки. Выбранный
существующий профиль не заменяется новым Локальным. Повторная загрузка не
перезаписывает уже актуальный список. Повреждённый файл остаётся нетронутым,
изменения блокируются. Удаление других профилей не удаляет исходную музыку.

Прежний [отчёт138/139](USER_PROFILES_2_8_0_VERIFICATION.md) — историческая база;
его формулировки о чистом User1 и равноправном входе заменены этим уточнением.
Диагностика140 и отложенный D-004 сохранены; политика воспроизведения не меняется.

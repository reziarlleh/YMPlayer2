# Проверка существующего Music OAuth в эфирном Яндекс Радио

6 октября 2026 года, база **2.4.1-build84**. Владелец разрешил проверочный
прототип для персональной коллекции FM-станций. Производственное приложение,
APK, сквозной Build и update feeds не изменены. Это продолжение
[оценки сервиса](YANDEX_RADIO_FEASIBILITY.md), не завершённая интеграция.

## Что проверено

В отдельном чистом headless-контексте без пользовательских cookies открыты
страница «Европы Плюс» и `/collection`. Аудио заглушено; лайки/реакции не
отправлялись. Из реального сетевого обмена получены адреса ресурса:

| Запрос GET к `https://radio.api.music.yandex.ru` | Назначение | Без входа |
| --- | --- | --- |
| `/account/about` | Сведения об аккаунте/доступности | 200, без UID |
| `/radio/v1/collection/stations/slugs` | Избранные станции | 401 |
| `/radio/v1/collection/tracks/ids` | Избранные треки | 401 |
| `/radio/v1/collection/shows/ids` | Избранные передачи | 401 |

Frontend отправляет `X-Yandex-Music-Client: YandexMusicWebRadio/1.0.0`.
[Срез адресов/статусов](qa/radio-research-2026-10-06/browser-endpoints.json).
Затем отдельный HTTP-прототип без cookie-jar повторил account/stations/tracks
без Authorization и с заведомо неверным OAuth. Коллекции в обоих случаях401;
`/account/about` с неверным токеном также401. Сервер различает эти запросы.
[Контрольные ответы](qa/radio-research-2026-10-06/auth-controls.json).

Ответ200 от `/account/about` без входа **не доказывает авторизацию**. Его JSON
содержит регион/подписку/доступность, а не подтверждённую личную коллекцию.
Эти результаты не доказывают, что действующий Music OAuth будет принят:
он пока не передавался серверу в этом исследовании.

## Прототип и критерий успеха

[tools/Probe-YandexRadio.py](../tools/Probe-YandexRadio.py) использует только
GET, стандартный Python и фиксированные Music/FM origins. Токен читается из
частного файла в памяти, не из аргумента со значением токена. Cookies не
используются; редиректы запрещены. Новый токен/Device Flow не запрашиваются.
В отчёт попадают статусы, формы JSON, число элементов и признаки совпадения
UID; токен, UID, названия станций, содержимое коллекции и сообщения ошибок
сервера не сохраняются.

Запуск после указания владельцем существующего локального файла токена:

```powershell
python tools/Probe-YandexRadio.py --token-file <частный-файл> --output .local-build/radio-research/auth-probe.json
```

Не создавать файл токена в отслеживаемой части репозитория и не присылать
его содержимое в чат. Отчёт по умолчанию находится в игнорируемой `.local-build`.

Прототип проверяет тем же токеном Music `/account/status`, FM `/account/about`
и FM-избранное. Доступ к станции считается подтверждённым, только если
анонимный/неверный токен отвергнут, действующий токен принят с распознаваемым
списком и Music возвращает UID. Пустое избранное допускается. Полное
подтверждение аккаунта требует дополнительно совпадения явно возвращённых UID.
Если FM не вернёт UID, отчёт отделит подтверждённый доступ к коллекции от
непроверенного совпадения личности; код выхода2 означает незавершённую проверку.

Шесть [проверок прототипа](../tools/tests/test_yandex_radio_probe.py) прошли:
совпадение/расхождение UID, отсутствие FM UID, публичная коллекция не доказывает
вход, редирект запрещён, приватные значения не попадают в отчёт.
[Лог](qa/radio-research-2026-10-06/probe-checks.txt). Вымышленные ответы проверяют
только эти защитные условия, не совместимость реального Music OAuth с FM.

## Что мешает основному прогону и точка продолжения

В `.provider/yandex.properties` есть clientId/clientSecret; это реквизиты
OAuth-клиента, **не пользовательский access token**. Переменная окружения или
локальный файл действующего пользовательского токена не обнаружены. В debug
аккаунтах работающих QA-эмуляторов5556/5560 хранилища пусты; release на API28
также не содержит `no_backup/yandex-accounts`. Release-хранилище TV/API29
недоступно через run-as/root, поэтому отсутствие токена там не заявляется.
Чужие профили браузера и физические устройства не использованы.

Владельцу задан вопрос о месте действующего токена. До ответа задача открыта:
нет доказательств ни успешного входа нашим Music-токеном, ни необходимости
другой авторизации. После ответа:

1. Если доступен частный локальный файл — выполнить основной прогон и сохранить
   обезличенный результат, сверить UID и защищённое избранное.
2. Если токен есть только в приложении на смартфоне — добавить ограниченную
   проверку внутри приложения, где доступен существующий Keystore текущего
   профиля. Отдельный APK с другим applicationId этого доступа не имеет.
   Передавать токен наружу или получать другой вместо него не требуется.
3. По фактическому результату решить, нужна ли отдельная авторизация и какие
   личные операции можно переносить. Запись/изменение избранного пока не проверены.

Адреса получены из внутреннего web-протокола, официального публичного контракта
FM API не найдено. Ни playback/Media3, ни интеграция FM в меню не относятся к
результату этого прототипа. Воспроизведение плеера не подвергалось регрессии:
его код не менялся. Следующая независимая задача после проверки — B-006.

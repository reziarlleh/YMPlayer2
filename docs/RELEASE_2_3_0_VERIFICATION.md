# Проверка 2.3.0 — история прослушивания

Дата: 2026-10-03. База — main `3a759a5`, stable 2.2.2-build74.
[План цикла](PLAN_2_3.md); никаких параллельных patch/веток 2.2.

## Изменения

- Медиатека → История прослушивания: последние 500 разных треков профиля,
  повтор поднимает запись, страницы по 80, дата/время и подтверждаемая очистка.
- Только фактический Media3.isPlaying: выбор, ожидание, предзагрузка волны и
  восстановление на паузе не считаются прослушиванием. Служба пишет и в фоне.
- Отдельное хранилище SQLite с транзакцией; в записи нет URI аудио/SAF,
  токенов и подписанных потоков. Старые базы/настройки не мигрируют и не сбрасываются.
- Повторный запуск использует каталог/аккаунт/кэш текущего профиля. Из истории
  запускается обычный список из одного выбранного трека; недоступный носитель
  сохраняет подпись, но не становится доступным по одной исторической записи.
- Новые тексты добавлены сразу на все восемь языков. [English guide](USER_GUIDE_EN.md)
  содержит инструкции и существующие иллюстрации с обозначением их происхождения.
- Два старых недетерминированных шага теста очереди исправлены: потокобезопасный
  журнал I/O и ожидание shuffle до detach. Код очереди не переписан.

## Приёмка

Core JVM: 90/90. Debug/AndroidTest собраны; release lint: 0 errors / 31 прежних
warnings. Generated catalog: 585 сообщений, восемь полных пакетов, --check прошёл.

На Android15/TV29 проверены 12 разных native сценариев каждого устройства:
SQLite лимит/порядок/профили/перезапуск, история local и управление входом с пульта,
ручная очередь, шесть онлайн-сценариев, волна, офлайн и вертикальный фокус.
В итоговой группе прошли 11/12, а проверка lookup ещё содержала неверное
предусловие: вход в онлайн-медиатеку успевал загрузить каталог.
Смена профилей теперь выполняется на уже открытой истории; lookup действительно
пуст перед нажатием play. Исправленный двенадцатый сценарий прошёл отдельно
на обоих устройствах. [Групповые и целевые логи](qa/2-3-0).

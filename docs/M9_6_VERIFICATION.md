# M9.6 — сегментированное видео и длительное продолжение клипов

Дата: 2026-09-30. Проверки рабочих исходников после build55.
Актуальный план: [PROJECT_STATUS](PROJECT_STATUS.md).

Поведение соответствует [ADR-022](DECISIONS/ADR-022-clip-preload-and-session-ownership.md):
один следующий медиаресурс готовится заранее, пустое продолжение начинает новую
rotor-сессию, feedback текущего клипа относится к породившей его сессии.
Архитектура и production-код клипов не изменены.

`ClipTransportPlaybackTest` использует собственное 16-секундное H.264/AAC-видео,
HLS с восемью TS-сегментами и DASH с отдельными init/media-фрагментами.
Production `ClipMediaPreloader` загружает сэмплы до перехода, передаёт именно
подготовленный MediaSource, затем ExoPlayer проходит отметку 0:05 без ошибки.
Проверены videoFormat 160×90 и переход через две двухсекундные границы.
Оба сценария прошли на Android 15 в общем выборочном прогоне восьми сценариев
([XML](qa/m12-7/final-targeted.xml)).

`ClipLongSessionTest` прошёл 60 естественных `STATE_ENDED` Media3 с ускорением
seek к концу собственного MP4: переход инициирует listener, а не `next()`.
Вымышленный API выдаёт пять новых клипов на сессию и пустой `/next`; создано
13 сессий, для всех 60 FINISHED-events подтверждена исходная session ID.
После 61-го клипа возврат ограничен сохранёнными 40 клипами: назад до c22,
дальше предыдущий ничего не меняет и новые серверные сессии не создаются
([XML](qa/m9-6/long-android15.xml)). Это функциональная последовательность,
не часовой нагрузочный прогон.

[Происхождение и генератор фикстур](qa/m9-6/FIXTURES.md). Файлы находятся только
в androidTest APK. Сегменты читаются локально; ответы API явно вымышленные.
Эти проверки подтверждают контейнеры, Media3 и логику сессий; не подтверждают
новые реальные видеоответы Яндекса, сеть владельца или изображение HyperOS.
Длительная сетевая сессия и физическая приёмка остаются независимыми.

На настоящем Android TV API 29 также прошли все три сценария вместе с двумя
проверками профиля ([прогон](qa/m12-7/tv-profile-and-video.txt), пять без ошибок).
Общий выпускной прогон выполняется в M12.7.
